# RE-569 — Select locked-portrait NOISE shadow and the fighter costume check

Status: IMPLEMENTED (decomp source, host tests, PPSSPP goldens; the NOISE cost is unmeasured on a physical PSP)
Topics: rendering, select, noise, costume, matanim, toolchain, goldens
Relevant files: `crates/ssb-engine/src/rdp_noise.rs`, `psp-runtime/src/meshdraw.rs` (`draw_sprite_noise`), `psp-game/src/players_screen.rs`, `tools/romtool/src/matcolors.rs`

## Question

How does the PSP draw the locked-portrait shadows (`mnplayersvs.c:362`, RE-411, RE-448), and are fighter costume matanim scripts read the way the decomp reads them?

## NOISE shadow (PSP deviation)

- The portrait combiner takes NOISE as its C input; the PSP GE has none.
- Model: CPU, per texel, the angrylion RDP noise. Levels `[32,96,160,224,288,352,-96,-32]` (9-bit sign-extended); combiner `((a-b)*c+(d<<8)+0x80)>>8`, clamped; one level per pixel shared by R, G, B; xorshift32 with a LUT per share (`SHADOW_NOISE_SHARE = 0x30`).
- `draw_sprite_noise` copies the RGBA8888 sprite into `list_memory` (64 KiB per frame), combines texels with alpha > 0, and binds the copy. Other formats and mip levels draw plain.
- Deviations:
  - Per texel of the 45x43 sprite (64x64 storage), not per screen pixel; the GE bilinear filter blends neighbours.
  - Alpha-0 texels are left unchanged (the RDP output is invisible there; alpha comes from TEXEL0).
  - The xorshift seed is fixed each frame, so output is deterministic (`--twice`: 0 px). The RDP's noise free-runs.
- Evidence is decomp-only: Rice cannot show NOISE (the shadow crop is identical across N64 frames 017-020).
- Cost, PPSSPP profile build, `vsplayers@400`: `noise` span ~1.0 ms average, ~3.0 ms peak; 4 shadows x 4096 texels (~1763 combined each). Physical PSP unmeasured (`PLAN.md`, MS8).

## Costume check

- `romtool costumes <rom> [--pack <pak>]` compares two readings of every fighter costume script at every selectable costume: the matcolors decomp reference (no code shared with `ssb-rom`) and the packer's `matanim::colors_at`.
- Result, real ROM and pack v132: 428 scripts, 2068 readings, 0 colour or palette differences (prim, env, blend, light1, light2, PaletteID); 0 costume-override keys past a fighter's count (36 fighter objects, 987 nodes). Costume counts agree with `ftparam.c:56`.
- Inert writes excluded by rule: texture id 0, ids on MObjSubs without ALPHA/SPLIT or with FRAC, PaletteID 0 vs unset.
- One real gap (exit 1): Luigi's eyes. Costume scripts 0x29A4 and 0x4F74 in file 323 set `TextureIDCurrent = 1` on the eye MObj (flags 0x3005 ALPHA, sprite list `sub_0x414`). The N64 shows `sprites[1]` from creation and after each part rebuild; only `ftParamResetTexturePartAll` (base 0) gives sprite 0. The PSP shows sprite 0 (`modelpart.rs:260`). Fix needs a per-fighter costume-set initial texture id and an N64 capture (`PLAN.md`).
