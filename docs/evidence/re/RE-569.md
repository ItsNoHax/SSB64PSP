# RE-569 — Select locked-portrait NOISE shadow and the fighter costume check

Status: IMPLEMENTED (decomp source, host tests, PPSSPP goldens; NOISE cost measured on a PSP-2000)
Topics: rendering, select, noise, costume, matanim, toolchain, goldens
Relevant files: `crates/ssb-engine/src/rdp_noise.rs`, `psp-runtime/src/meshdraw.rs` (`draw_sprite_noise`), `psp-game/src/players_screen.rs`, `tools/romtool/src/matcolors.rs`

## Question

How does the PSP draw the locked-portrait shadows (`mnplayersvs.c:362`, RE-411, RE-448), and are fighter costume matanim scripts read the way the decomp reads them?

## NOISE shadow (PSP deviation)

- The portrait combiner takes NOISE as its C input; the PSP GE has none.
- Model: CPU, per texel, the angrylion RDP noise. Levels `[32,96,160,224,288,352,-96,-32]` (9-bit sign-extended); combiner `((a-b)*c+(d<<8)+0x80)>>8`, clamped; one level per pixel shared by R, G, B; xorshift32 with a LUT per share (`SHADOW_NOISE_SHARE = 0x30`).
- `draw_sprite_noise` copies the RGBA8888 sprite into `list_memory` (64 KiB per frame), combines texels with alpha > 0, and binds the copy. Other formats and mip levels draw plain.
- Deviations:
  - Per texel of the 45x43 sprite (64x64 storage), not per screen pixel; the GE bilinear filter blends neighbours.
  - Alpha-0 texels are left unchanged (the RDP output is invisible there; alpha comes from TEXEL0).
  - The xorshift seed is fixed each frame, so output is deterministic (`--twice`: 0 px). The RDP's noise free-runs.
- Evidence is decomp-only: Rice cannot show NOISE (the shadow crop is identical across N64 frames 017-020).
- Cost, PPSSPP profile build, `vsplayers@400`: `noise` span ~1.0 ms average, ~3.0 ms peak; 4 shadows x 4096 texels (~1763 combined each).

## NOISE cost on a PSP-2000 (batch 189)

- Build: `profile,capture_scene_file`, `vsplayers@400`, pack v149 on ms0, PSPLink; mean of report windows 1-2 (120 frames each), every variant interleaved with the baseline.
- Baseline: `noise` 1.60 ms average, 2.1-2.5 ms peak; CPU busy 6.40 ms; 57.5 fps.
- Shadows drawn plain (bound): CPU busy 4.74 ms, still 57.5 fps, vblank wait 5.4 to 7.0 ms. NOISE does not limit the select frame rate.
- Compiled loop: ~30 instructions per opaque texel, one uncached `sw` per texel.

| Variant | `noise` ms | vs baseline |
|---|---|---|
| Copy only, no combine (bound) | 0.65 | -0.95 |
| Combine, stores to a cached hot static (bound, not drawable) | 0.92 | -0.68 |
| Combine, alpha-0 stores skipped (bound) | 1.54 | -0.07 |
| Cached list memory + line writeback | 1.77 | +0.17 |
| Cached VRAM alias (`ge_vertices`) + writeback | 1.75 | +0.15 |
| Uncached VRAM alias | 2.06 | +0.46 |
| Allegrex `cache 0x18` (Create Dirty Exclusive) per line, fill, `cache 0x1b` | 1.66 | +0.06 |
| Stores batched per 16 / 64 texels via a stack array | 1.97 / 1.87 | +0.37 / +0.27 |
| Run memo (8 outputs per repeated texel) | 1.94 | +0.34 |

- `cache 0x18` on the Allegrex: a self-checking build (read back from memory after `cache 0x1b`, compared with the plain path) ran 40 s, 0 mismatches. It creates a dirty line without a fetch, as on the R4000.
- Kept: the plain uncached loop. Every cheaper bound drops the combine or the stores that drawing needs.

## Costume check

- `romtool costumes <rom> [--pack <pak>]` compares two readings of every fighter costume script at every selectable costume: the matcolors decomp reference (no code shared with `ssb-rom`) and the packer's `matanim::colors_at`.
- Result, real ROM and pack v132: 428 scripts, 2068 readings, 0 colour or palette differences (prim, env, blend, light1, light2, PaletteID); 0 costume-override keys past a fighter's count (36 fighter objects, 987 nodes). Costume counts agree with `ftparam.c:56`.
- Inert writes excluded by rule: texture id 0, ids on MObjSubs without ALPHA/SPLIT or with FRAC, PaletteID 0 vs unset.
- Luigi's eyes (resolved): costume scripts 0x29A4 and 0x4F74 in file 323 set `TextureIDCurrent = 1` on the eye MObj (flags 0x3005 ALPHA, sprite list `sub_0x414`). The N64 shows `sprites[1]` from creation and after each part rebuild; only `ftParamResetTexturePartAll` (base 0) gives sprite 0. Port: tablegen `TEXTURE_PART_MADE`, read by `modelpart::texture_part_made` (pack v133).
- N64 RDRAM trace: after a forced detail restore, the rebuilt MObj has `texture_id_curr = 1`; control run stays 0. Luigi's sprites 0 and 1 have identical texels: no golden moved.
- After the fix: `romtool costumes` exit 0; 526 scripts, 0 differences, 0 unread; texture parts 168 readings, 0 disagree.
