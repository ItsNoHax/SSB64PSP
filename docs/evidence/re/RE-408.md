# RE-408 — The results and select demo clips in the pack

Status: IMPLEMENTED (decomp source, ROM decode, pack test, PPSSPPHeadless goldens unchanged, workspace tests, both PSP builds; no physical PSP)
Topics: animation, pack, fighter, asset-pipeline
Relevant files: `crates/ssb-rom/src/{anim,anim_table,pack}.rs`, `tools/gen-anim-table.py`, `crates/ssb-rom/tests/demo_clips.rs`

## Question

The VS results screen and the character selects pose the fighters with
the demo statuses `nFTDemoStatusWin1` to `nFTDemoStatusLose`. Where are
their clips, what kind of clip are they, and what does packing them take?

## Source

- **Who plays what.**
  - `mnVSResultsSetFighterStatus` gives the winner a random pick from
    `mnVSResultsGetStatusWin`: Win1 to Win3, or Win1 and Win2 for Kirby.
    Everyone else gets `nFTDemoStatusLose`, and so does everyone after a
    no contest.
  - The VS select's `mnPlayersVSGetStatusSelected` uses Win1 to Win4 by
    fighter.
  - Both call `scSubsysFighterSetStatus`, which is
    `ftMainSetStatus(gobj, status, 0, 1.0, 0.0)`.
- **The mapping.** A status from 0x10000 up to 0x1000E goes through the
  shared demo table `D_ovl1_80390BE8` (`scsubsysdata.c`). Entry `n` has
  motion `0x10000 + n` and no `proc_update` for Win1 to Lose.
  `ftMainSetStatus` takes away 0x10000 and indexes `fp->data->submotion`,
  which is the fighter's `dFT<Name>SubMotionDescs` (`scsubsys`). Win1 to
  Win4 and Lose are rows 1 to 5.
- **Files per fighter** (Win1, Win2, Win3, Win4, Lose):

  | Fighter | Files |
  |---|---|
  | Mario | 357, 358, 359, 360, 361 |
  | Fox | 370, 371, 372, 372, 373 |
  | Donkey Kong | 381, 382, 383, 384, 385 |
  | Samus | 393, 394, 395, 395, 396 |
  | Luigi | 462, 463, 464, 464, 361 |
  | Link | 404, 405, 406, 406, 407 |

  - Most fighters repeat one row for Win3 and Win4.
  - Luigi's Lose is Mario's claps (`llFTMarioAnimClapsFileID`).
  - Jigglypuff's Win1 is named `llFTLuigiAnimUnknownFileID` (file 469).
    It sits in Jigglypuff's block and fits her 22 joints, so only the name
    is wrong.
  - Master Hand's five rows all use his default clip, 2098. Metal Mario,
    the Poly fighters and Giant Donkey Kong have no clip here: their rows
    are null, or their table has just one row.
- **What they are.** Figatrees. No demo row sets `FTANIM_FLAG_ANIMJOINT`.
  The files decode as 16-bit figatree scripts, and their ROM lengths match
  their C sources.
- **Lead joint.** Some rows' `anim_desc` sets 0x80000000: Kirby's Win1
  and Win2, Pikachu's Win1 and Ness's Win2. Checked against the ROM:
  - Each of those four tables is one entry longer than the fighter's
    joints. With the first entry dropped, the unanimated-joint pattern
    matches the fighter's unflagged demo clips (for example Kirby 416
    against 418). So one runtime joint leads, as it does for the battle
    figatrees.
  - Every unflagged table is exactly the fighter's joint count, except
    Samus's claps (396). That table is 24 entries for 23 joints. Its
    first 23 entries match her Win2's pattern, and the extra entry is a
    trailing null. 73 of her battle figatrees also have one trailing
    entry.
- **Lengths and looping.**
  - Every Win clip ends: 120 frames, except Mario's Win4 (65), Samus's
    Win2 (75), Yoshi's Win3 and Win4 (124) and Kirby's Win1 and Win2
    (161).
  - Every Lose clip (the claps) loops, except Jigglypuff's (file 472,
    120 frames).
  - No demo status has a `proc_update`, so nothing ends an ending Win
    clip: the fighter keeps its last pose.

## Implementation

- **Slots.** `tools/gen-anim-table.py` adds the five slots after the
  entry slots (`anim::SLOT_WIN1` to `SLOT_LOSE`, 614 to 618; `SLOT_COUNT`
  is 619).
  - It reads the demo enum, `D_ovl1_80390BE8` and every
    `dFT<Name>SubMotionDescs`.
  - It fails if a row sets `FTANIM_FLAG_ANIMJOINT`.
  - It takes each row's lead-joint flag from `anim_desc` and each length
    from the clip's C source.
- **Figatree path.** `anim::is_anim_joint_slot` now covers only the seven
  entry slots, so `decode_fighter`, romtool and `skeleton.rs` handle the
  demo slots as figatrees. The lead-joint handling (RE-331) needed no
  change.
- **Pack v64.** It is 28,510,000 bytes, SHA-256
  `33fd70558a870a81d9e6ff283127739f5d49bccdb98c1ae3073f2836056e0e13`.
  - 27 of 27 fighters are packed, with 3,030 animations, 670 of them with
    a runtime joint.
  - Nothing new failed to pack. Only the four Poly entry clips (RE-401)
    are still skipped.

## Deviations

- **Translate scales.** Luigi's own demo rows set
  `FTANIM_FLAG_TRANSLATE_SCALES`, and his borrowed Mario claps does not.
  The pack does not record that flag for any slot. The batch that plays
  these clips has to handle it.
- **Motion scripts.** The rows' motion scripts (`D_ovl1_*`: voice clips
  and other events) are not ported.
- **Not played yet.** Nothing plays the clips. The next batch draws the
  results screen's fighters.

## Verification

- **Pack test.** `tests/demo_clips.rs` checks all five slots for every
  playable fighter:
  - the slot is present and not an `AnimJoint` slot;
  - the length (0 for a looping clip);
  - the flagged rows' unbound first entry;
  - the model joints bound in order;
  - Samus's unbound trailing entry;
  - Luigi's Lose is Mario's file 361.

  With Kirby's Win1 flag removed from the test, it fails.
- **Lengths.** `romtool anims --verify` agrees with the decompilation on
  all 49 new finite lengths: 2,514 lengths checked, against 2,465
  before. It still reports the 58 entry-slot differences it reported
  before this batch, because the generated table gives `AnimJoint`
  entry slots no C length.
- **Census.** The missing-slot test counts 70 more empty slots: the
  fourteen rows without demo clips.
- **Goldens.** All 109 goldens are unchanged, captured twice.
- **Gates.** Workspace tests, pinned Clippy, rustfmt and both PSP builds
  pass.
