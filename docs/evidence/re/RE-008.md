# RE-008 — C-button mapping *(OPEN)*

Status: OPEN
Topics: camera
Relevant files: ft/ftkey.c, sys/controller.c, crates/ssb-engine/src/input.rs, ftkey.c

**Question.** Which C-button functions matter in Smash 64, and what should
they map to on a PSP with no C-stick?

**Evidence so far.** Unlike Melee, Smash 64's C-buttons are not attack inputs.
They appear to be used for taunt and for camera control in some single-player
modes. **Not yet confirmed against the decomp's input handling** (`ft/ftkey.c`,
`sys/controller.c`).

**One function is now confirmed (RE-295).**
`ft/ftcommon/ftcommonkneebend.c`'s `ftCommonKneeBendCheckButtonTap` treats
*any* C-button tap (`R_CBUTTONS|L_CBUTTONS|D_CBUTTONS|U_CBUTTONS`) as a real
jump-by-button input in the fighter status machine — independent of the
taunt/camera roles above. `psp-game`'s Training mode now reads this directly
(`JUMP_BUTTON_MASK` in `psp-game/src/main.rs`), using the already-existing
`DEFAULT_MAPPING` (Triangle → C-Up, Square → C-Down) with no new button
assignment. Taunt and single-player-camera C-button uses remain unconfirmed.

**Current implementation.** C-Up → Triangle, C-Down → Square, per
`DEFAULT_MAPPING` in `crates/ssb-engine/src/input.rs`. C-Left and C-Right are
currently **unmapped**. Both C-Up and C-Down are sufficient for the jump
function (RE-295): the decomp's check accepts any one C-button, not a
specific one.

**Confidence: low, unchanged for taunt/camera.** The jump-button function is
now decomp-confirmed and real, not a placeholder. Camera and taunt uses still
need `ftkey.c`/menu-input reading before M4. If C-Left/C-Right turn out to
matter for those, the PSP has no free buttons and a modifier scheme will be
needed.
