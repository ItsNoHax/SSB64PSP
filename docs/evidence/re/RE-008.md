# RE-008 — C-button mapping

Status: COMPLETE (decomp source, host tests)
Topics: input, camera, fighter
Relevant files: `ft/ftmain.c`, `ft/ftcommon/ftcommonkneebend.c`, `ft/ftcommon/ftcommonjumpaerial.c`, `ft/ftcommon/ftcommonappeal.c`, `ft/ftdata.c`, `ft/ftkey.c`, `crates/ssb-engine/src/input.rs`, `crates/ssb-game/src/fighter.rs`

**Question.** Which C-button functions matter in Smash 64, and what should
they map to on a PSP with no C-stick?

**Source.** In the fighter code, the C-buttons appear only as one
interchangeable jump button, always as the full
`R_CBUTTONS | L_CBUTTONS | D_CBUTTONS | U_CBUTTONS` mask:

* `ftCommonKneeBendCheckButtonTap` — a tap starts a jump (RE-295).
* `ftCommonKneeBendProcUpdate`, `ftCommonHammerKneeBendProcUpdate` and
  `ftDonkeyThrowFKneeBendProcUpdate` — a release during the short-hop window
  makes a short hop.
* `ftCommonJumpAerialMultiCheckJumpButtonHold` — holding one continues Kirby's
  and Jigglypuff's multi-jump.

Taunt is not a C-button. `ftCommonAppealCheckInterruptCommon` tests
`button_tap & button_mask_l`, and `dFTManagerDefaultFighterDesc` sets the
masks to A `0x8000`, B `0x4000`, Z `0x2000` and L `0x0020` (`L_TRIG`).
`ftkey.c` only replays scripted `FTKEY_EVENT_BUTTON` inputs for demo and
CPU players; it reads no controller. No camera code reads a C-button. The
other C-button readers are menus (as alternatives to the D-pad) and the
debug battle menu (`dbbattle.c`, C-Up/C-Down step the dummy's status).

The same input pass (`ftMainProcUpdateInterrupt` for `nFTPlayerKindMan`) turns a
held R into A + Z before it derives taps and releases:
`if (button_hold & R_TRIG) button_hold |= (A_BUTTON | Z_TRIG)`. R is shield
and grab through that expansion, not through its own reads.

**Implementation.** `SSB64_GAME_MAPPING` already passes all four C-buttons
through as raw N64 bits (D-pad), so jump works from any of them. The
asset-viewer mapping's doc comment claimed taunt/camera roles; it now cites
this record. `Fighter::set_input` applies the R → A + Z expansion to the
current and previous input, so taps and releases see it as the source's do.

**Verification.** `fighter::tests::r_trigger_holds_a_and_z`. The workspace
tests pass. Taunt (`Appeal`) itself is not ported; when it is, it reads L.
