## Integration and boundaries

`spgame::Frontend` owns the select, intro, continue and stage-clear
controllers and creates/advances the existing campaign `Session`. It
emits Battle, BonusStage and other unported overlays as explicit host
requests. A host request does not simulate a VS battle or skip a stage.
The host resets the scheduler on Intro entry, runs actual battles, consumes
their results through Session and calls `Frontend::sync` at scene returns.

The select and scene controllers expose presentation state. Authored
sprites, cameras, fighter demo assets, option-arrow display threads and
PSP draws are not implemented by this batch. The existing PSP menu and
live gameplay do not call the new frontend yet. Live bonus-stat callbacks,
bonus-stage controllers, Master Hand, ending/challenger/message overlays
and persistent saves/unlock writes remain in `TODO.md`.

The continue decomp uses an uninitialized local `stick_range` in the wait
calculation when a directional button tap short-circuits the stick query.
The port uses the supplied stick-x value for that calculation. Button taps
still bypass the repeat gate and neutral input resets it. The original's
undefined button-path repeat value is not reproduced; no N64 runtime trace
establishes it. The controller input represents the host's controller view;
four-controller aggregation remains host work.
