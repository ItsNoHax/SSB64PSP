# RE-501 — Scene read-ahead: first-frame load times on a PSP-2000

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `capture_scene_file,profile,memory_ballast` builds, ballast 47,891,712, pack v109 read over USB `host0:` through a symlink beside the PRX, 3 alternating runs each; PPSSPP `capture_scene_file,profile,headless_capture`)
Topics: performance, hardware, loading, deviation
Relevant files: `psp-game/src/scene_load.rs`, `psp-game/src/main.rs`, `crates/ssb-rom/src/scene_roots.rs`, `crates/ssb-rom/tests/scene_roots.rs`

## Question

How much of a scene's first-frame load can background reads started earlier
(menu to child menus, select to stage previews, stage select to the roster's
fighter files, VS end or reset to results) take off, against HEAD c8a0e36?

## Findings

Scene-start frame CPU on the PSP-2000, mean of 3 (USB hostfs speeds; an `ms0:`
pack will differ):

| transition | HEAD | read-ahead |
|---|---|---|
| players-training entry (tick 8) | 145.1 ms, 10 reads | 163.3 ms, 33 reads |
| to maps (tick 102) | 23.7 ms, load 13.9 | 18.4 ms, load 0 |
| to battle (tick 115) | 179.3 ms, load 115.4 | 77.3 ms, wait 28.0 |
| VS to results (tick 642) | 130.4 ms, load 98.4 | 27.4 ms, wait 0 |
| vs-mode to players-vs (tick 20) | 141.3 ms, load 136.6 | 84.4 ms, wait 79.3 |

- The capture routes leave maps after 13 ticks and vs-mode after 12, before
  the background reads finish, hence the waits; a person dwells longer.
- The results trigger frame (GAME SET hold, tick 547) costs 12.8 ms, under
  16.7 ms, no dropped frame.
- players-training entry costs 18 ms more: the twelve kinds' select clips are
  23 extra small scattered reads. Only routes that enter it straight from
  the title pay this: the 1P mode menu reads the four 1P selects ahead,
  clips included (`read_ahead_menus`).
- PPSSPP CPU: battle 36.8 to 4.4 ms, results 30.1 to 1.6 ms, players-vs 42 to
  5.2 ms.
- VS end sets `Battle.end` 95 ticks before results in `vsresults`; a
  no-contest reset only 3 ticks, so it gains nothing (cpu 37 ms to wait 36.7).
- Frame hashes over 12 routes (up to 1102 frames) and all 201 goldens are
  unchanged: read-ahead alters no tick or pixel.

## Deviation

The N64 `mnMaps` loads one stage preview per cursor hover. The port holds all
nine VS previews (layer-object file plus wallpaper, about 5 MB; `low_free` on
f1-vs-players 37.5 to 32.0 MB), read ahead from the character select. VS Back
from the stage select reloads players-vs. See
[D-046](../../decisions/D-046.md).

## Enter waits (batch 193)

- `Plan::enter_begin` drained every background read in flight; the battle
  above waited 28 ms for maps-preview reads it then dropped.
- Now: reads not yet started for another scene are dropped; `enter` waits
  only for a read in flight that holds a file it wants. A read holding none
  finishes in the background; its files leave at the first `safe_point`
  after it ends (`leave_after`), never while held.
- Host proof: `an_enter_waits_only_for_reads_it_wants` (both model and
  differential `Old` model changed); breaking either half fails it.
- No current capture route reproduces the wait on the PSP: `stageselect`
  enters battle at tick 30 and `training` at tick 8, both `wait_us=0` before
  and after.


## 1P and Bonus Practice read-ahead (batch 198)

- Intro → battle: `spgame::read_ahead::battle_files` predicts the battle's `gkind` and kinds from the scene data after `Manager::prepare_stage` (allies, fixed opponents); no RNG draw. Polygons drawn at the battle start are not predicted; the Fighting Polygon Team's twelve are `campaign_extras` anyway.
- Host proof: `predicts_each_stage_roster` (every common 1P stage, 8 seeds: roster ⊆ prediction except drawn Polygons; seed unchanged). Fails when the allies are dropped.
- Stage clear → next intro; Bonus Practice select → bonus battle after `STAGE_DWELL_TICS` on one fighter.
- PSP-2000, profile builds, files on host0, two rounds each (A/B: same commit, hooks disabled), scene load `cpu_us`:

| Load | without | with |
|---|---|---|
| Link battle (`onepintro`) | 40.1-40.2 ms | 1.2 ms |
| Mario Bros. battle (`onepmario`) | 44.5-44.6 ms | 1.4 ms |
| Kirby Team battle (`onepkirby`) | 52.2-52.6 ms | 1.3 ms |
| Polygon Team battle (`onepzako`) | 73.0-74.6 ms | 2.5 ms |
| Break the Targets battle (`bonusselect`) | 26.1-27.0 ms | 0.9 ms |
| Next intro after a clear (`oneptargetclear`, one round) | 31.1 ms | 0.7 ms |

- Worst frame (5 reports): intro scenes 81-123 to 41-55 ms; the rest is the intro's own first load.
- `oneptargetclear` presses A through the next intro after 60 ticks: its Mario Bros. battle still reads 22 files (66.4 to 27.7 ms).
- Prefetch CPU per call 0.5-4.8 ms (Polygon Team: 270 roots).
- Not done: battle end → stage clear (stage clear load 6-9 ms); Characters scene (one 2 KB demand read); 1P intro tic 81 vs 60 and tally 11-12 VIs are N64 load latency, not PSP cost (RE-458).
