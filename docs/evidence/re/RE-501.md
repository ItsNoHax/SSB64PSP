# RE-501 — Scene read-ahead: first-frame load times on a PSP-2000

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `capture_scene_file,profile,memory_ballast` builds, ballast 47,891,712, pack v109 read over USB `host0:` through a symlink beside the PRX, 3 alternating runs each; PPSSPP `capture_scene_file,profile,headless_capture`)
Topics: performance, hardware, loading, deviation
Relevant files: `psp-game/src/scene_load.rs`, `psp-game/src/main.rs`, `crates/ssb-rom/src/scene_roots.rs`, `crates/ssb-rom/tests/scene_roots.rs`

## Question

How much of a scene's first-frame load can background reads started earlier
(menu to child menus, select to stage previews, stage select to the roster's
fighter files, VS end or reset to results) take off, against HEAD c8a0e36?

## Findings

Scene-start frame CPU on the PSP-2000, mean of 3 (USB hostfs speeds; an `ms0:`
pack will differ):

| transition | HEAD | read-ahead |
|---|---|---|
| players-training entry (tick 8) | 145.1 ms, 10 reads | 163.3 ms, 33 reads |
| to maps (tick 102) | 23.7 ms, load 13.9 | 18.4 ms, load 0 |
| to battle (tick 115) | 179.3 ms, load 115.4 | 77.3 ms, wait 28.0 |
| VS to results (tick 642) | 130.4 ms, load 98.4 | 27.4 ms, wait 0 |
| vs-mode to players-vs (tick 20) | 141.3 ms, load 136.6 | 84.4 ms, wait 79.3 |

- The capture routes leave maps after 13 ticks and vs-mode after 12, before
  the background reads finish, hence the waits; a person dwells longer.
- The results trigger frame (GAME SET hold, tick 547) costs 12.8 ms, under
  16.7 ms, no dropped frame.
- players-training entry costs 18 ms more: the twelve kinds' select clips are
  23 extra small scattered reads.
- PPSSPP CPU: battle 36.8 to 4.4 ms, results 30.1 to 1.6 ms, players-vs 42 to
  5.2 ms.
- VS end sets `Battle.end` 95 ticks before results in `vsresults`; a
  no-contest reset only 3 ticks, so it gains nothing (cpu 37 ms to wait 36.7).
- Frame hashes over 12 routes (up to 1102 frames) and all 201 goldens are
  unchanged: read-ahead alters no tick or pixel.

## Deviation

The N64 `mnMaps` loads one stage preview per cursor hover. The port holds all
nine VS previews (layer-object file plus wallpaper, about 5 MB; `low_free` on
f1-vs-players 37.5 to 32.0 MB), read ahead from the character select. VS Back
from the stage select reloads players-vs. See
[D-046](../../decisions/D-046.md).
