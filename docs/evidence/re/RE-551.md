## Question

How do the captured star (spit) and lost star (copy loss) behave in the original?

## Evidence

- **Capture star** (efmanager.c:5837, proc :5858-5873): odd `effect_timer` draws 2 `syUtilsRandIntRange` plus `efManagerStarRodSparkMakeEffect`. Release: flag2==1 stop, escape, splash; flag2==2 stop, splash (ftcommoncapturekirby.c:333, :355).
- **Lost star** (efmanager.c:5879, :5919/:5957): x +20 per frame, y arc, ejected out of bounds with no splash. Scale from `EFFECT_SCALE` (1.5 to 2.0).
- **N64 spit** (`9:8:x=127;49:40:b;129:3:a`): star t135 scale 1.6, rotate.z +10 deg per frame, first spark t137, gone at release t165, Fall t169. Rust matches.
- **N64 lose** (`...;300:3:l`): star t300 at (498, 1398.15), y deltas 80, 77, 74, last t350, ejected t351. Matches.
- **Same object.** ROM test `the_lost_star_shares_the_captured_stars_object` proves both stars use one object key.
- **Golden consequences.** `f1-vs-four-magnifier` 90674 native px (tick 2801: captured-star sparks and splash advance `syUtilsRand`). New rows `f1-training-kirby-spit`, `f1-training-kirby-lose`.

## Deviations

- Star draw: `kirby_star_mesh` from object (86, 0x5458), added to `EFFECT_SCALE_X_GRAPHS` (CLD seed, head 1); CLD and XLU are pixel-identical on the current scenes. Hiding the star moves kirby-spit 16976 px and kirby-lose 7644 px, so it draws.
- `Effects.map_bounds` is None in host tests unless set.
- Lost star position is taken when queued.
- Pre-existing: `lose_copy` plays FGM LoseCopy last; flag2==1 release lacks `ftKirbySpecialNInitPassiveVars` (PLAN row).
- Unported: N64 spit throw shows a yellow-green streak around Kirby (PLAN row).
