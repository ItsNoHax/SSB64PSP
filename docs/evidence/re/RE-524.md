# RE-524 — Board the Platforms: per-tick N64 traces expose platform, jump, landing and ledge divergences

Status: COMPLETE on host and PPSSPP for all 12 courses; physical PSP not re-run
Topics: bonus stage 2, yakumono animation, fighter ground/air transitions, jump, ledge teeter, bumpers, wallpaper
Relevant files: `crates/ssb-rom/src/skeleton.rs`, `crates/ssb-rom/src/ground_obj.rs`, `crates/ssb-rom/src/stage.rs`, `crates/ssb-game/src/status.rs`, `crates/ssb-game/src/fighter.rs`, `crates/ssb-game/src/map.rs`, `crates/ssb-game/src/combat.rs`, `crates/ssb-game/src/kirby.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `tools/romtool/src/main.rs`

## Question

On a PSP, Board the Platforms did not match the N64 and some platforms could not be boarded. Static data (collision lines, spawns, yakumono animation, platform kinds, camera) already matched the ROM and decomp, so where did the dynamics diverge?

## Method

N64 warp-boot traces (`nGRKindBonus2Start + fkind`, decomp build, one line per frame: status, situation, facing, position, velocities, animation frame) of every course. Two scripted pad courses per fighter (walk, run, short and full jumps, aerial jumps, drop-through, turn) were replayed with the same inputs on a host harness and on PPSSPP, then compared frame by frame. The N64 harness releases input at Go, about frame 60; the port's scripts were aligned to that frame.

## Findings

- **Creation pose.** `grDisplayMakeGeometryLayer` calls `gcPlayAnimAll` when it makes a layer, so the yakumono animation has parsed frame 0 before the first tick. `mpCollisionPlayYakumonoAnim` measures the first speed from that pose. Starting from the file's rest pose put every carried frame one platform step off. Fix: `StageAnimator::creation_pose`.
- **No entry.** Bonus stages set `FTCreateDesc::is_skip_entry`, and `ftManagerInitFighter` places the fighter with `mpCommonSetFighterWaitOrFall`; there is no `nFTCommonStatusEntry`.
- **Path bumpers.** A `TraI` track writes the whole translation from its path, so the orbiting Bumpers move on both axes (`ground_obj.rs`, `item_play`).
- **Bumper angle 362.** `ftMainGetBumperDamageAngle` replaces it with the truncated angle from the attacker to the fighter's collision centre and faces the fighter away from the attacker (`combat.rs`, `bumper_damage_angle`).
- **Jump force is whole.** `ftCommonJumpGetJumpForceButton` returns its X and Y through `s32 *`, so both are truncated toward zero before `jump_height_mul` scales them. A button short hop at stick -30 gets 44, not 44.34, and Mario's N64 JumpB leaves the ground at 54.40, not 54.64. The difference compounds over the arc.
- **SetFighterAir spends the ground jump.** `mpCommonSetFighterAir` sets `jumps_used = 1`. Pass, fall-off-edge, the hammer fall and DK's cargo pass all go through it. Without it, Fox kept his aerial jumps after dropping through a platform.
- **`ignore_line_id` resets on every status change.** `ftMainSetStatus` writes `coll_data.ignore_line_id = -1`; `ftCommonPassSetStatusParam` sets it again after the change. The port never cleared it, so a fighter that jumped out of Pass fell through the same platform again.
- **Ottotto (ledge teeter).** Wait, the three walks, RunBrake, LandingLight/Heavy, LandingFallSpecial, Appeal, and Dash once `dash_to_run <= anim_frame` run `mpCommonProcFighterOnCliffEdge`. Past an end of the floor, `mpCommonCheckSetFighterCliffEdge` puts the fighter 40 units inside that end when it faces the drop and |stick_x| < 60 toward it, unless a LWall/RWall query hits. It then raises `MAP_FLAG_FLOOREDGE`, which leads to `ftCommonOttottoSetStatus`. Ottotto has no physics proc. Its interrupts are the landing chain, squat, turn, and walk at forward stick >= 60. Its map proc returns to Wait more than 60 units from the facing end. Without it, slow walks went over edges that the N64 stops at.
- **Wait or landing.** JumpF/B, JumpAerialF/B, Fall, FallAerial, Pass, GuardPass and StopCeil land through `mpCommonProcFighterCliffFloorCeil` → `mpCommonSetFighterWaitOrLanding`: Wait if `vel_air.y > -20`, else Landing. Kirby's JumpAerialF1–F5 use `mpCommonProcFighterCliffWaitOrLanding`. The port always played LandingLight.
- **Stop at the edge.** `mpCommonSetFighterFallOnEdgeBreak` runs `MAP_PROC_TYPE_STOPEDGE` (`mpCommonCheckFighterOnEdge`), which holds the fighter on the floor's end. It is the `proc_map` of 92 status-table entries: the ground attacks and jabs, item swings and throws, rolls, getups, getup attacks, pipe entry and exit, and several grounded specials. Together with the `proc_map`s that call `mpCommonProcFighterOnEdge` or `mpCommonCheckFighterOnEdge`, these statuses stop at the edge. The port listed only 14 of them, so Kirby's getup roll (DownForwardU) on his course carried him off a platform that the N64 holds him on (`map::stops_at_edge`). Captain's Falcon Kick stops only once `flag3` is set and keeps its own pass.
- **Backdrop.** Every bonus stage (GRKind 17–40) draws `grWallpaperMakeStatic`'s single sprite: file 119 at 0x26C88, 300x220. The geometry layers had been suspected; they are not the backdrop.

## Verification

- Host harness (no fighter animation, no blast zones): both scripted courses match the N64 exactly for 1500 frames for most fighters. The remaining host divergences are root-motion statuses (TransN: Yoshi/Ness JumpAerial, TurnRun) and deaths, which the harness does not model.
- PPSSPP (real game, with animation, bumpers and blast zones): idle on all 12 courses matches the N64, with 0 mismatches over 700 frames. Both scripted courses for all 12 fighters match every compared frame: 1500, or to the end of the stage after a KO. Kirby's first course matched only after the stop-at-edge fix.
