# RE-336 — Filter-compensated material textures in the texel check

Status: COMPLETE (bisect, decomp and ROM check, texel check with a broken-pack control, host tests, PSP builds, 69-scene golden matrix; no physical-PSP capture)
Topics: material, texture, pack, asset-pipeline, effects, visual-regression
Relevant files: `crates/ssb-rom/src/pack.rs`, `tools/romtool/src/main.rs`, `tools/romtool/src/matcolors.rs`, `tools/romtool/src/matsample.rs`

**Question.** `romtool matcolors --pack` failed. Textures 160 and 161 (32x32, `Psm8888`, tile IA16) differed from `sprites[0]` in 307 of 1,024 texels. RE-327 had recorded 145/145 exact matches. Is the packer or the check wrong?

## Bisect

- A pack built at `141be33` (RE-327, SHA-256 `010291620b7e…`, byte-identical to RE-327's record) passes the current checker. A pack built at `fe01213` fails it. `b87b732` only reformats tests. So `fe01213` ("restore camera XLU state") introduced the difference.
- `fe01213` seeds task head 1 with `G_RM_AA_ZB_XLU_SURF`. Before it, primitives on head 1 that set no render mode were packed as opaque.

## Source and ROM evidence

- File 83 is `EFCommonEffects1`. The entry is `DamageFlyMDust` (`MObjSub` `0xC998`, `MatAnimJoint` `0xCB44`). Its `sprites[]` table at `0xC97C` lists seven IA16 32x32 `CommonSpark` frames, with `sprites[0]` at `0xC178` (`src/relocData/83_EFCommonEffects1.c`).
- `dEFManagerDamageFlyMDustEffectDesc` draws with `gcDrawDObjTreeDLLinksForGObj` (`src/ef/efmanager.c:321-347`). Its `DObjDLLink` is `{ 1, DamageFlyMDust_DisplayList }`, so it draws on task head 1 (`gcDrawDObjDLLinks`, `src/sys/objdisplay.c:1527`).
- The display list at `0xCA58` (14 commands, decoded from the ROM) sets the combiner, tiles and geometry. It contains no `G_SETOTHERMODE_L`. It therefore inherits the head-1 render mode that `func_80016338` sets: `G_RM_AA_ZB_XLU_SURF` (`src/sys/objdisplay.c:2606-2610`).
- The effect therefore blends by texel alpha on the N64. The packer's `Translucent` alpha policy is correct for it.

## Cause

- At `141be33` the texture was converted under the `Opaque` policy. The 3-point solve forced alpha to 255, measured mean error 217, and was rejected, so the raw texels shipped.
- Under `Translucent` (RE-306) the solve was accepted. Level 0 is the filter compensation. RGB stays 255 because the source RGB is constant white. Alpha moves on 307 texels by -19 to +23, most by +1. The earlier "alpha bit" description was not correct.
- The checker compared every material texture texel for texel with its ROM sprite at the packed format's precision. That is valid only for uncompensated textures. RE-327's 145/145 held because no checked texture had been compensated. The pack did not record which textures had been compensated, so the check could not tell a compensation from a wrong image.

**Conclusion:** the packer is correct and the check was wrong.

## Change

- Pack v37 grows `TextureDesc` to 52 bytes. `texels` (the spare byte after `tile_mirror`) has `TEXELS_COMPENSATED` when level 0 is a filter compensation. `source_digest` is the FNV-1a of the source tile bytes the texture was converted from: `tile_period[1]` rows of `max(tile_source_width, tile_period[0])` texels.
- The packer records both for static, animated-sprite and second-pass textures (`record_texture_source`). `convert_mat_anim_sprite` now reports whether it compensated.
- `matsample::compare_texture` reads the sprite bytes through the recorded tile and requires their digest to match for every texture. It still compares uncompensated textures texel for texel. It pairs compensated textures by digest alone.

## Verification

- `romtool matcolors --pack`: 145 textures through their recorded tile, 0 differ. 79 are read through a mirrored or repeated period and 2 (160, 161) are filter-compensated and paired by digest. 33/33 static CLUTs, all 15 tracks and the four resolvers are exact over 600 frames.
- Control: flipping one bit of the recorded digest of textures 160 and 161 makes the check fail on both ("recorded source digest … is not sprites[0]'s").
- `SSB64_ROM=… cargo test --workspace`: 944 pass, including a v37 `TextureDesc` round-trip test.
- `tools/golden.sh verify`: 69 of 69 scenes match. Texel data is unchanged; only descriptors grew.
- Both PSP release builds pass.
- Pack v37: 22,746,176 bytes, SHA-256 `a0e31495e3666212fb6c587b93bf5efdf4ce9078bbe30ff6e750f5ba5c56f0b3`.

## Limit

The digest identifies the source bytes and tile layout. It does not check the compensated texels themselves. That is `romtool residuals`' job (RE-312).
