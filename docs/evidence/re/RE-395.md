# RE-395 — The battle timer and "TIME UP"/"GAME SET"

Status: IMPLEMENTED (decomp source, ROM decode, host tests, PPSSPPHeadless goldens captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: interface, match, pack, visual-regression
Relevant files: `crates/ssb-game/src/{hud,hud_tests}.rs`, `crates/ssb-rom/src/sprite.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-vs-time-up.png`

## Question

A timed VS battle kept its clock (RE-389) but showed none. What do
`ifCommonTimerProcDisplay` and the end announcements draw?

## Source

- **Timer digits** (`ifCommonTimerMakeDigits`, `ifCommonTimerProcDisplay`).
  - The timer is made only in a timed battle. It has four digit `SObj`s
    and a colon from file 165 (`gGMCommonFiles[3]`, `IFCommonTimer`),
    with `attr` `SP_TEXSHUF | SP_TRANSPARENT`.
  - The digits are centred on x `{232, 247, 273, 288}` and the colon on
    260, all on y 30, truncated to whole pixels.
  - They read tens of minutes, minutes, tens of seconds and seconds of
    `time_remain`, plus 59 below the limit, so the count rounds up. At
    zero the last digit becomes 0.
- **End announcements.**
  - When the time runs out, `ifCommonTimerFuncRun` calls
    `ifCommonAnnounceTimeUpInitInterface`, which makes "TIME UP" from file
    82's blue letters (`dIFCommonAnnounceTimeUpSpriteData`).
  - When one player is left, `ifCommonAnnounceEndMessage` makes "GAME SET"
    (`dIFCommonAnnounceGameSetSpriteData`).
  - Both stay up through the 90-tick end wait.
  - `ifCommonBattleInterfaceProcSet` then hides every interface `GObj`
    for the Set phase.
- **Draw order.** The timer is made after the damage displays, and the
  countdown (frame 91) after both.

## Implementation

- **Sprites.** `ssb_rom::sprite::TIMER` lists file 165's fifteen sprites
  from `reloc_data.us.h`. That makes 155 in the pack, which is 27,794,784
  bytes, SHA-256
  `2e1289b855351122e5c8e76578f09f43c962b8c32839e04e81652a30be2214ea`.
- **`ssb_game::hud`.** Adds `timer_digits`, `timer_origin`, the slot
  positions, and the `TIME_UP` and `GAME_SET` letter layouts.
- **`psp-game`.** `draw_training` takes the battle and draws, in order:
  - the damage displays;
  - the timer, in a timed battle;
  - the countdown;
  - the end letters for `Battle::end`.
  At Set it draws no HUD.
- **Capture.** The new `vstimeupsign` scene (`vstimeup`'s rules, tick
  4,040) captures "TIME UP".

## Verification

- **Tests.** Host tests cover the round-up, `0:01` to `0:00` and the
  centring.
- **ROM decode.** A ROM test decodes file 165's sprites.
- **Goldens.**
  - `f1-vs-cpu` shows 02:56 at tick 690. That is 298 ticks after the
    timer starts on the second Go frame, rounded up.
  - `f1-vs-countdown` shows 03:00.
  - The new `f1-vs-time-up` shows 00:00 and "TIME UP". It was identical
    in both captures.
  - `f1-vs-sudden-death` is unchanged: its stock rule shows no timer.
  - 102 of 102 goldens match.
- **Gates.** Workspace tests, Clippy and both PSP builds pass. The release
  `run` is 119,512 bytes.
