## Question

Which capture-frame timings of Kirby's inhale and Yoshi's egg differ from the original?

## Evidence

- **Catcher pose first.** A `proc_catch` that sets a status poses the catcher before the victim's `proc_capture` reads the joint (`ftYoshiSpecialNCatchProcCatch`); `ftCommonCaptureYoshiProcCapture` runs ProcPhysics.
- **Inhale first pull.** `ftCommonCaptureKirbyProcCapture` calls ProcPhysics, so the first of nine pulls lands on the catch frame. Eat frame sets `CaptureWaitKirby` in ProcPhysics; its ProcMap places the victim at Kirby +-10 the same frame (`ftcommonstatus.h:3510`).
- **Wind stop.** SpecialNCatch stops the wind effect once dist^2 < 9216 (`ftkirbyspecialn.c`).
- **Wiggle clock.** A bare `lbCommonAddFighterPartsFigatree` leaves `AOBJ_ANIM_CHANGED` pending; the next `ftAnimParseDObjFigatree` holds frame 0 without counting (`ftanim.c:75`); `ftMainSetStatus` consumes it.
- **Copy loss.** FGM plays right after the star push; flag2==1 release runs `ftKirbySpecialNInitPassiveVars` (`ftcommoncapturekirby.c:320`). Star reflect has no `dot < 0` guard (`lbCommonReflect2D`).
- **Spit landing.** First star tick emits Quake(2) plus ImpactWave (N64 t135, wave at (624, 1398.15)); Rust matched already, now guarded by a test.
- **Egg.** `ftCommonYoshiEggProcMap` sets only `ga`: no ground transfer, the egg stops dead on landing (N64 t296, x -1213). Lay sweeps from Yoshi to the egg (wall/ceiling stop) and applies velocity on the lay frame. Escape order: explode, EGG_BREAK, FGM shatter. Acid floor breaks on the next update.
- **N64 Castle traces.** Egg lay, double jump (74-frame JumpAerialF = 70 anim + 4 bumper hitlag frames) and Kirby down-wiggle (Castle line 0 is PASS; drop at t110) all match. Harness: write pkind=0 on the Training dummy at t100 so port 2 pad drives it; the CPU WIGGLE script never uses stick y.
- **Goldens.** Native px of 130560: `f1-training-yoshi-egg` 75270, `f1-training-kirby-spit` 3980, `f1-training-kirby-hat` 18, `f1-vs-four-magnifier` 96527 (aerial inhale catches Fox at t2760).
- **Drawn wiggle restart.** N64 (Castle, Kirby P1, Mario dummy, stick x -80 at t126): t120 af 0 but joints still run on (j6 `bcef1aa1`), t121 frame-0 pose, t122 frame 1; same at t134-136. The draw lags the wiggle by one frame. Port: `StatusState::clip_restarts` bumped by the play that poses frame 0; `tick_skeleton_animation` restarts the clip. Host replay matches t116-140 bit-exactly. Golden `f1-training-kirby-wiggle` (scene `kirbywiggle`, dummy mirrors from tick 207); disabling the restart changes 7512 px at 2x.
