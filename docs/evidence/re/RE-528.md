# RE-528 — Opening movie demo scripts carry EFFECT and PLAY_FGM events, and the movie world needs particle displays

Status: COMPLETE on host and PPSSPP; physical PSP not re-run
Topics: opening movie, demo script events, dust effects, particle displays, pack v117
Relevant files: `crates/ssb-game/src/motion/mod.rs`, `crates/ssb-game/src/fteffect.rs`, `crates/ssb-game/src/opening/movie.rs`, `psp-runtime/src/movie.rs`, `psp-game/src/opening_screen.rs`

## Question

Why was the run scene's dust puff missing?

## Findings

- Link's opening demo row 7 (`D_ovl1_8039198C`) has two events at time 0: `PLAY_FGM 0x62` and `EFFECT` kind 13 (DustHeavyDouble) at joint 0. `DemoScript::run` ignored both event opcodes, and the movie world had no particle display objects (`efDisplayInitAll`).
- `DemoScript::events` now records them (offset, scatter, `EFFECT_ITEM_HOLD` giving `is_scale_pos`, joint). `fteffect::make_at` creates the dust kinds at a given position. `psp-runtime/src/movie.rs` runs events after `set_status` and each tick (joint 0 only), plays the FGM, and places the effect at the root joint position × offset / MODEL_SCALE.
- The movie world gets particle displays (links 18/15/25/10, lists 0+2, 1, 3, 4; link 10 depth-tested), created first in `Run::new`. Per frame: `take_effects`, `make_at`, link-0 FuncRun, then the particle func_runs, as on the N64.
- Result: the dust matches the N64's position and shape at tic 54; MAE at tic 60 fell from 9.76 to 7.11.
- Demo fighters now run their demo-script rows on the battle runner (`ssb_game::demo_fighter::DemoFighter`, `motion::start_demo`, demo words via `DEMO_BIT`): effects on any joint (`psp_runtime::scene::sample_demo_joints`), colour animations, parts, FGM and voice; attack collisions and quakes skipped, `is_muted` gates sounds. Results, selects, Characters, campaign and the opening movie use it; `DemoScript` and `DemoParts` are deleted. Script clock = the clip's `anim_frame`.
- Results: `psp-game/src/demo_world.rs` holds the particle world. Golden `f1-vs-results-link` (tick 780, Link Win3 sparkle) vs an N64 decomp-rebuild warp (VS results, Link CP Win3): the N64 makes the sparkle in update 134 at anim frame 15 and shows it for updates 134-138; PSP shows it in ticks 778-782. White area per frame agrees within ratio 1.00-1.02, centroids within 0.5 px x and 2-3 px y.
- Deviations: `Skeleton::frame` is 0 after a non-looping clip ends (matters only for PauseScript/AsyncWait after End); Select/Characters costume 0 (effects ignore costume); campaign rows drop effects (no particle world; only link/samus/ness scsubsysdata hold EFFECT words); results animation may start one tick late (pose at PSP tick 764 = N64 update 120; PLAN).
- Hidden parts: all 54 scsubsysdata submotion flags set no `is_enabled_joints` bit, so skipping `apply_hidden_parts` is equivalent.
