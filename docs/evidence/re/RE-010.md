# RE-010 — `MObjSub` unknown fields

Status: COMPLETE (decomp source; no ROM census this batch)
Topics: material, animation, lighting, texture
Relevant files: `sys/objtypes.h`, `sys/objdisplay.c`, `sys/objanim.c`, `crates/ssb-rom/src/mobj.rs`, `crates/ssb-rom/src/matanim.rs`

**Question.** `MObjSub` had about fifteen fields named `unkNN`. Do any
affect rendering?

**Source.** Most of them are now consumed: `unk08`, `unk0A`, `unk0C`,
`unk0E`, `unk10`, `unk24`, `unk28`, `unk38`, `unk3A` and `unk44` feed the
tile and UV equations in `gcDrawMObjForDObj` and are read by
`ssb-rom::mobj` (RE-321, RE-327). A search of every C file for the rest:

| Field | Readers | Role |
|---|---|---|
| `unk36` | `objdisplay.c:1298-1334` | Row count of the `FRAC`/`ALPHA` next-image `gDPLoadBlock` (`block_dxt * unk36` texels). It sizes a TMEM load; it does not change sampling. |
| `unk48` | none | Unused. |
| `unk4C`, `unk68`, `unk6C`, `unk70`, `unk74` | none | Written only by material-animation command 22 (`ANIM_CMD_22`, `objanim.c:1205`): flag bits `0x01`, `0x04`, `0x02`, `0x10`, `0x08`. Never read. |
| `prim_pad` | none | Padding after `prim_l`/`prim_m`. |

**Result.** No remaining unknown field changes what a material samples or
how it is shaded. `unk36` matters only to a renderer that emulates TMEM
block loads; the PSP path uploads whole images.

**Limits.** `ssb-rom::matanim` still rejects command 22 as unmodelled. If a
material script uses it, the command sets `anim_wait` from its payload and
consumes one word per set flag bit; the values can be skipped. No ROM census
of command 22 was run for this record.

**Command 22 and census (batch 41).** `matanim.rs` now models command 22 (`anim_wait` set from the payload, one word skipped per flag bit 0x01..0x10). `matanim_census.rs` walks all 213 packed `MatAnimDesc` scripts: no command 22 and no opcode the decomp lacks; every script runs without error. Decomp `gcParseMObjMatAnimJoint` has no case for 13 (SetInterp) or 15 (SetFlags); the host skips 13 and adds the payload for 15 as the joint parser does. No packed script uses either. Windowing the blob remains a pack-format change (PLAN).
