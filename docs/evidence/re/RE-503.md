# RE-503 — Gameplay inverse trig and the light direction match the ROM bit for bit

Status: COMPLETE (host and PPSSPP; not hardware proof)
Topics: determinism, reverse-engineering
Relevant files: `crates/ssb-engine/src/math.rs`, `crates/ssb-engine/src/math/trig_golden.rs`, `tools/r4300/r4300.py`, `tools/r4300/trig_hashes.py`, `psp-runtime/src/meshdraw.rs`

## Question

Do the port's `syUtilsArcTan`, `ArcTan2`, `ArcSin` and `ArcCos` equal the original's, and does every call site use the decomp's function?

## Findings

- Oracle: `tools/r4300/r4300.py` interprets the ROM's own routines with the FCSR as `osInitialize` sets it (round to nearest, flush-to-zero, invalid trap). It reads the ROM at run time (`--rom`, `$SSB64_ROM`, or `refs/ssb-decomp-re/baserom.us.z64`, SHA-1 checked); no ROM bytes are committed. `trig_hashes.py` hashes outputs (FNV-1a of output bits) over synthetic inputs.
- Hashes: ArcTan 0x38f675e075a15c0b (n=132118), ArcTan2 0xfd0a8140286a588d (n=66625), ArcSin 0xb91a26e05467effc, ArcCos 0x197ab366d6610cb3; 0 traps. The Rust `trig_golden` test reproduces all four on the host. sinf 0x0ae64c80ba5c8ee7 and cosf 0x037f84ec89add89b are pinned for the next pass (no Rust port yet).
- Corner: ArcTan2 ratios that underflow differ (N64 flushes to zero, IEEE underflows gradually). Inputs exclude them; no gameplay site is known to reach them.
- Routing: every former `math::atan2` site is `syUtilsArcTan2` with the decomp's argument order. The decomp's only `syUtilsArcTan(y/x)` caller, `ftMainGetBumperDamageAngle`, is ported (`combat.rs`). Stick gates share `status::stick_angle` (50 degree gates compare `ArcTan2` against `F_CLC_DTOR32`; an exhaustive i8 grid test shows them input-identical to the old slope form). `syVectorAngleDiff3D` (`math::sy_vector_angle_diff_3d`) replaces the cosine thresholds: map 110, Pikachu halt 135, Ness halt 155, zip 42/CST90, Thunder Jolt 100; boundary witnesses differ from the old form. Fox up-special excludes `MAP_VERTEX_COLL_PASS` floors and uses `lbCommonCheckAdjustSim2D` with `F_CLC_DTOR32(20)`; a zero vector stays airborne. `syMatrixFastSin/Cos` have no decomp callers.
- Real mismatches fixed: PK Thunder head steering now uses `syVectorAngleDiff3D` (ArcCos) with the side from the cross product's z sign (`wpnesspkthunder.c:233-251`); Fox up-special sets stick direction unconditionally on the ground (`ftfoxspecialhi.c:318`); the twister spin uses the `lbCommonSin/Cos` table; `ftDisplayLightsDrawReflect`'s light direction uses the table form.
- Light direction is quantised to s8 (`rsp_light::reflect_light_dir`, RE-514).
- Chunks 1-3 goldens: 42 scenes (fox, cpufx, pikachu, jolt, ness, knock-ko, push-ko, vs-four, fighter sanity) all match; none rebaselined.
- Chunk 4: `weapon::reflector_rotate` (syVectorNorm3D, cross with (0,0,-/+1), ArcTan2, +/-90 degrees; wpmain.c:170); boss bullets call it. Boss goldens 14/14 match.
- Chunk 5: `FighterEffect::ImpactWave{pos,rotate}` (rotate = ArcTan2(-n.x, n.y), axis Z = 4) and `Quake(u8)` via `fteffect::surface_impact`. Wall damage (`reaction.rs`) and Ness bound (`ness.rs`): wave then quake. Capture-Kirby star (`capture_kirby.rs`): quake then wave. Quake(2) takes the late slot.
  - Deviation: the star wave position is `from + vel_air + vel_damage_air`; C's translate at proc_map would also include hazard `vel_push`.
- Chunk 6: `Fighter.topn_rotate_z` (Kirby Stone slope, Falcon Kick ground and air; consumers `slope_contour`, `item_throw::collision_axes`); joint-4 pitch and Pikachu scale via `model_pitch::PoseWrites` (FlyRoll, Ness jibaku, Fox and Pikachu air up-special), cleared on `ClipStart::Restart` (ftmain.c:4657). `boss.rs` uses `f_cst_dtor32(45)`; `camera.rs` fovy uses `f_clc_dtor32`; `is_have_tilts` gate is a no-op (stub-gated test over 27 fighters). `sy_tan` is bit-exact (hash 0x17ddb219f595dccc).
- Goldens: new `f1-training-fox-fire`, `f1-training-pikachu-quick`; rebaselined `f1-vs-four` (99024 native px) and `f1-vs-four-magnifier` (99606 native px): CPU Fox's Fire Fox pitched hitboxes now hit DK from tick ~619.
- Goldens: a probe over 201 scenes saw light-direction calls differ 220979/233740, ArcTan2 2535/56554, ArcCos 3/37. 152 goldens changed, at most 1 LSB per channel. With the old light direction and the new trig, all 25 scenes that exercise ArcTan2 or ArcCos match: every pixel change comes from the light direction. Stack peak 312,800 bytes, unchanged.

## Limits

Chunk 5 has no golden: a probe in `surface_impact` stayed unreached across 9 candidate scenes; unit tests (mutation-checked) only.

Not compared with an N64 capture for pitch: needs analog-stick input in the N64 harness.
