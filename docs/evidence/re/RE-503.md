# RE-503 — Gameplay inverse trig and the light direction match the ROM bit for bit

Status: COMPLETE (host and PPSSPP; not hardware proof)
Topics: determinism, reverse-engineering
Relevant files: `crates/ssb-engine/src/math.rs`, `crates/ssb-engine/src/math/trig_golden.rs`, `tools/r4300/r4300.py`, `tools/r4300/trig_hashes.py`, `psp-runtime/src/meshdraw.rs`

## Question

Do the port's `syUtilsArcTan`, `ArcTan2`, `ArcSin` and `ArcCos` equal the original's, and does every call site use the decomp's function?

## Findings

- Oracle: `tools/r4300/r4300.py` interprets the ROM's own routines with the FCSR as `osInitialize` sets it (round to nearest, flush-to-zero, invalid trap). It reads the ROM at run time (`--rom`, `$SSB64_ROM`, or `refs/ssb-decomp-re/baserom.us.z64`, SHA-1 checked); no ROM bytes are committed. `trig_hashes.py` hashes outputs (FNV-1a of output bits) over synthetic inputs.
- Hashes: ArcTan 0x38f675e075a15c0b (n=132118), ArcTan2 0xfd0a8140286a588d (n=66625), ArcSin 0xb91a26e05467effc, ArcCos 0x197ab366d6610cb3; 0 traps. The Rust `trig_golden` test reproduces all four on the host. sinf 0x0ae64c80ba5c8ee7 and cosf 0x037f84ec89add89b are pinned for the next pass (no Rust port yet).
- Corner: ArcTan2 ratios that underflow differ (N64 flushes to zero, IEEE underflows gradually). Inputs exclude them; no gameplay site is known to reach them.
- Routing: every former `math::atan2` site is `syUtilsArcTan2` with the decomp's argument order. The decomp's only `syUtilsArcTan(y/x)` caller, `ftMainGetBumperDamageAngle`, is not ported.
- Real mismatches fixed: PK Thunder head steering now uses `syVectorAngleDiff3D` (ArcCos) with the side from the cross product's z sign (`wpnesspkthunder.c:233-251`); Fox up-special sets stick direction unconditionally on the ground (`ftfoxspecialhi.c:318`); the twister spin uses the `lbCommonSin/Cos` table; `ftDisplayLightsDrawReflect`'s light direction uses the table form.
- Not modelled: the C stores `dir * 100` in the s8 `Light.l.dir`; the PSP keeps a float direction.
- Goldens: a probe over 201 scenes saw light-direction calls differ 220979/233740, ArcTan2 2535/56554, ArcCos 3/37. 152 goldens changed, at most 1 LSB per channel. With the old light direction and the new trig, all 25 scenes that exercise ArcTan2 or ArcCos match: every pixel change comes from the light direction. Stack peak 312,800 bytes, unchanged.

## Limits

Coverage gap: no golden exercises PK Thunder steering, the hazard spin or any ArcSin site (probe saw 0 calls), so those changes are verified by the oracle hashes and unit tests only. Not compared with an N64 capture; PPSSPP only.
