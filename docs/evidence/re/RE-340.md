# RE-340 — Costume picks, strict rendering, scene dependencies, extern linking and allocators

Status: COMPLETE (decomp source and host tests; validated against the ROM, pack v37, PPSSPP, N64 RDRAM and a PSP-2000 in RE-341)
Topics: asset-pipeline, rendering, texture, memory, input
Relevant files: `crates/ssb-game/src/costume.rs`, `crates/ssb-rom/src/strict.rs`, `crates/ssb-rom/src/scene_deps.rs`, `crates/ssb-rom/src/reloc_link.rs`, `crates/ssb-engine/src/memory.rs`, `tools/romtool/src/main.rs`, `psp-game/src/main.rs`

**Question.** Which deferred pipeline and runtime pieces can be built and
tested without the ROM, and what do they follow in the source?

**Results.**

| Piece | Source | Implementation | Validation still owed |
|---|---|---|---|
| Costume picks | `dFTParamCostumeIDs.royal`, `mnPlayers1PTrainingUpdateCostume`, `...CheckCostumeUsed`, `...GetFreeCostumeRoyal` | `ssb_game::costume`; `psp-game` takes a C-button tap on the Training menu entry and draws `Fighter::costume` | PPSSPP render of costumes 1–3 |
| Strict rendering | the references `meshdraw` resolves | `ssb_rom::strict::check`; `romtool strict <pack>`; `psp-game --features strict_render` rejects a failing pack (`BG_TRAINING_STRICT_FAILED`) | a run over pack v36 |
| Scene dependencies | objects → nodes (costume overrides) → meshes → prims → textures → material animations → palettes and LOD-blend textures | `ssb_rom::scene_deps::SceneDeps`, `footprint`; `romtool scene-deps` | per-scene residency numbers (RE-076/077) |
| Extern linking | `lbRelocLoadFilesExtern`, `lbRelocLoadAndRelocFile`: 16-byte `LBRELOC_CACHE_ALIGN`, depth-first placement during the extern walk | `ssb_rom::reloc_link::{layout, link}`; `romtool link <rom> <id>...` | a comparison with `lbRelocGetAllocSize` on real files |
| Allocators | `docs/memory.md` plan | `ssb_engine::memory::{Arena, Scope, ObjectPool}` with `AssetArena`/`GameArena`/`FrameArena` aliases | wiring into `psp-runtime` |

**Deviations.** The Training dummy keeps costume 0. The source would give
a same-fighter CPU the first free costume, which changes the Mario-on-Mario
goldens; that waits for a golden refresh (`TODO.md`).

**Verification.** Host unit tests for each module; the arena and strict
tests also pass under Miri. Both PSP builds pass, with and without
`strict_render`.

**Follow-up (RE-341).** Every "validation still owed" item above is done
there, and the Training dummy now takes the source's free costume.
`ssb_rom::strict` also covers material animations, animated palettes and
two-tile blends, and `reloc_link` gained `alloc_size` and `layout_after`.
