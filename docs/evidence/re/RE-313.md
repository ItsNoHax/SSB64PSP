# RE-313 — Texture-LUT semantics, short TLUTs and format-agnostic 3-point compensation

Status: COMPLETE (host measurement, original-game frame capture replayed through `angrylion-rdp-plus`, PPSSPP smoke; physical PSP not captured)
Topics: texture, asset-pipeline, pack, psp-ge, rdp

Relevant files: `crates/ssb-rom/src/texture.rs`, `crates/ssb-rom/src/mesh.rs`,
`tools/romtool/src/main.rs` (`convert_texture`, `STALE_TLUT_ENTRIES`,
`extend_short_tlut`), `tools/romtool/src/residuals.rs`,
`docs/rendering/three-point-residuals.md`

**Goal.** Fix the texture-semantics bugs RE-312 found before any manual
3-point override:

1. `convert_texture` never ran the compensator for RGBA16, RGBA32, IA or the
   RE-283 direct-colour bypass (225 variants, 165 materially bad).
2. Nine variants packed level-0 texels that differed from the decoded N64
   reference: I4/I8 textures drawn while a TLUT was loaded, and CI indices
   past a short TLUT.

## Part B — `G_MDSFT_TEXTLUT`

**Reference implementation.** `angrylion-rdp-plus` (commit on
`github.com/ata4/angrylion-rdp-plus` master, cloned 2026-09-24):

* `rdp_set_other_modes`: `en_tlut = bit 15`, `tlut_type = bit 14` of the
  high other-mode word. `gbi.h`: `G_TT_NONE = 0`, `G_TT_RGBA16 = 2 << 14`,
  `G_TT_IA16 = 3 << 14`. Value 1 sets only the type bit, so the TLUT stays
  off.
* With `en_tlut`, `fetch_texel_entlut_quadro` switches on
  `tlutswitch = size << 2 | (format + 2) & 3`. Every 4-bit format (CI, IA,
  I, RGBA) indexes the TLUT with `palette << 4 | nibble`; every 8-bit format
  with the whole byte (the tile's palette is ignored); a 16-bit texel with
  its high byte and a 32-bit texel with its red byte. The format no longer
  decides how the texel is read.
* The entry is expanded by `tlut_type`: RGBA5551 (bit-replicated, one-bit
  alpha) for `G_TT_RGBA16`; intensity = high byte, alpha = low byte for
  `G_TT_IA16`.
* Without `en_tlut`, `fetch_texel`'s `TEXEL_CI4` returns
  `palette << 4 | nibble` and `TEXEL_CI8` the byte, in all four channels;
  I4/I8 are intensity in all four channels.
* Each TLUT entry sits four times in upper TMEM. The four bilinear taps read
  copies 0-3 of their own texel's entry.

**SSB64 decompilation.** `sys/rdp.c` resets with `gsDPSetTextureLUT(G_TT_NONE)`.
`gcDrawMObjForDObj` (`sys/objdisplay.c`) loads a TLUT but never sets the
mode. `lbcommon.c`, `lbparticle.c`, `sprite.c` and `ftshadow.c` set
`G_TT_RGBA16` only around their own lookups and restore `G_TT_NONE`.

**ROM.** Every `G_SETOTHERMODE_H` covering shift 14 in the US archive is the
`gDPSetTextureLUT` form: 994 set `G_TT_NONE` and 982 set `G_TT_RGBA16`. No
list uses `G_TT_IA16`. The lists inspected enable the TLUT before their
lookups and disable it again afterwards, sometimes in a later node list of
the same task display list (file 112's Layer 0 enables it in `0x45D8` and
disables it at the end of `0x4C50`).

All four RE-312 I4/I8 cases draw with `G_TT_NONE`:

* `111:0xA90` sets `G_TT_NONE` itself before its I4 tile.
* `149:0x2EF0` enables the TLUT for two CI4 textures and disables it at
  `0x3130`, immediately before the I4 texture `0x1640`.
* `162:0x6C8` and `149:0x5F10` do not set the mode. Both are `list_id 1`
  (task display list 1) nodes. The TLUT a stage list-0 node left loaded, and
  enabled, leaked into them only because the converter threaded one state
  through both task lists.

The same leak produced three IA8 sprite frames of file 112 (`0x29F8`,
`0x2E00`, `0x3208`, drawn by list-1 nodes `0x6920`/`0x6980`), which RE-312
did not flag because their stale 16-entry TLUT happened to cover the
index range a mistaken lookup produced.

**Task display lists, measured.** `gSYTaskmanDLHeads[0]` and `[1]` are two
command streams. The frame captures below walked the real frame lists from
RDRAM (`sSYTaskmanDLBuffers`, `0x80046570`) and entered head 1 with
`G_TT_NONE` in every frame of all six captures.

**Implementation.**

* `texture::TextureLut` (`None`/`Rgba16`/`Ia16`) and `texture::decode_lut`
  implement the fetch rules above. `decode` keeps its old contract (CI through
  RGBA16) as a wrapper.
* `mesh::State` tracks the mode as `Unset | Known(mode)`, updated by any
  `G_SETOTHERMODE_H` whose range covers bit 14 or 15 (only the covered bits
  change). `SequenceItem::stream` names the task display list; each list keeps
  its own mode. List 1 starts at `G_TT_NONE`; list 0 starts unset.
* `TextureRef::tlut` carries the mode. When it is off, the `palette_*` fields
  are cleared, so a TLUT an earlier draw left loaded plays no part. An unset
  mode keeps the old reading: CI through RGBA16, everything else direct.
  Measured over the US pack before per-list tracking was added: 1,172
  distinct CI and 28 distinct I bindings reached a draw with the mode unset,
  and none of the I bindings had a TLUT loaded, so only CI relies on the old
  reading. Per-list tracking only turns unset list-1 draws into known ones.
* `convert_texture` picks the natural PSP format from the mode: a 4-/8-bit
  texel with the TLUT on is `PsmT4`/`PsmT8` whatever its N64 format, with the
  TLUT colours expanded by `tlut_type`. A CI texture with the TLUT off packs a
  grey index ramp. The texture cache key includes the mode.

## Part C — short TLUTs

`G_LOADTLUT` count is `((w1 >> 14) & 0x3FF) + 1`. Over the archive, 74 loads
have count 3 and 34 have count 255, among others that are not a multiple of
four.

**What the RDP loads.** A C harness over `angrylion-rdp-plus`'s own
`rdp_set_texture_image`/`rdp_set_tile`/`rdp_load_tlut` with a sentinel-filled
TMEM loads exactly `count` entries (count 3: entries 0-2; count 255: entries
0-254). Each entry is written to all four copies. BattleShip's
`interpreter.cpp` instead rounds a load up to 8 bytes (its "issue #4" fix for
this exact Break the Targets arrow, count 3). The hardware-accurate reference
does not, so BattleShip's rule was not adopted.

**What an index past the load reads.** Stale TMEM: whatever the previous load
left in that slot. That depends on draw order, so the original game's frame
lists were captured instead:

1. `refs/ssb-decomp-re` was temporarily patched to set `scene_curr` right after
   `gSCManagerSceneData = dSCManagerDefaultSceneData;` (RE-276 technique), and
   rebuilt. The patch was reverted; the rebuilt ROM's SHA-1 is again
   `e2929e10fccc0aa84e5776227e798abc07cedabf`.
2. `Mupen64PlusHarness` (the Rice plugin only drives game logic here) ran the
   scene and dumped RDRAM. Mupen stores RDRAM as host-endian 32-bit words;
   the dumps were byte-swapped for the walk.
3. A walker followed head 0 from `sSYTaskmanDLBuffers` (after the RDP reset
   list) through `G_DL` calls, branches and `G_MW_SEGMENT`, collected every
   `SETTIMG`/`SETTILE`/`LOADTLUT`/`LOADBLOCK`/`LOADTILE`/`SETTILESIZE` up to
   the target `LOADTLUT` (found by its palette bytes), and replayed them
   through `angrylion-rdp-plus` against the same RDRAM.

Results (TLUT slot, copies 0-3):

| Case | Scene | Frames | Slot | Contents | Source |
|---|---|---|---|---|---|
| `120:0x5A8` (via file 126) | Break the Targets, Donkey Kong | 3 idle + 5 moving (frames 400-794), 2 draws each | 3 | `1091 1091 114F 114F` | background file 119, last strip before the arrows |
| `121:0x6F0` (125) | Break the Targets, Fox | 3 frames, 4 draws each | 3 | same | same |
| `123:0xAC8` (132) | Break the Targets, Kirby | 3 frames, 4 draws each | 3 | same | same |
| `122:0x2D0` (133) | Break the Targets, Pikachu | 3 frames, 4 draws each | 3 | same | same |
| `52:0x9D70` | Opening room | 8 frames (60-frame steps), 2 draws each | 255 | `FE59 A391 FF9B FE59` | file 52 `0x42F0` room texture |

Every measured frame agreed. Both values are opaque. The arrows' index 3
(14 texels) is therefore dark blue (`0x1091` = (16,16,66)), not the unloaded
palette entry `0x7BC1` (light grey), not transparent black and not the
nearest loaded entry. The CI8 book's index 255 (4 texels) is light
(`0xFE59`), not the transparent black the decoder gave. BattleShip reported
"blue inside the chevron" as a port bug; it is what the original game draws.
The ending movie also draws file 52; a warp into `nSCKindEnding` hung at
frame 0, so that context is not measured.

**Implementation.** `STALE_TLUT_ENTRIES` records these five
`(palette file, offset, count) -> (slot, entry)` rows. `extend_short_tlut`
extends a TLUT only up to the highest index the texture uses. A recorded slot
gets its measured copy 0; an unrecorded one gets transparent black (the
decoder's value, so the packed texels still match the reference) and logs
`stale-tlut-unresolved`. The full US pack logs none. This is draw-order
evidence, not a per-texture 3-point override.

**Accepted deviation.** The RDP samples copies 0-3 for the four taps. Copy 0
is `0x1091`, copies 2/3 are `0x114F` ((16,41,57)), so a tap in the lower row
of the footprint reads a slightly different colour. A per-texel palette
cannot express this; the reference and the pack both use copy 0.

## Part A — format-agnostic compensation

`convert_texture` now sends every format through the one compensation path
(`mipped`): training and holdout coverage, alpha policy, index optimizers,
GE-exact integer refinement, the conservative texgen gate and the independent
holdout gate are unchanged and shared.

* RGBA16 keeps its natural `Psm5551`. The existing 5551 quantization and
  `refine_integer(Rgba5551)` path now runs. Promotion to `Psm8888` needs the
  existing gate (compensated SSE at most 75% of baseline, at most 64 KiB
  extra). A rejected RGBA16 texture packs its lossless source at `Psm5551`,
  not the old forced RGBA8888.
* RGBA32, IA16, IA8 and IA4 stay `Psm8888`.
* The RE-283 bypass still packs `Psm8888` and never uses the paletted
  transport, but its texels now enter the compensator. The residual recorder
  keeps the natural `PsmT4` and the palette so the report still names it
  `re283-direct-colour-bypass`.

`a_partial_other_mode_write_changes_only_the_bits_it_covers`,
`texture_lut_mode_is_tracked_per_task_display_list` (mesh);
`intensity_texels_read_the_tlut_only_when_it_is_enabled`,
`tlut_type_decides_how_an_entry_expands`,
