# RE-376 — Captain Falcon in Training: the Falcon Punch flame

Status: IMPLEMENTED (decomp source, host tests, PPSSPPHeadless golden captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: fighter, effect, visual-regression, rendering
Relevant files: `crates/ssb-game/src/captain.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-training-captain.png`

## Question

When does the Falcon Punch flame exist, where is it placed, and how does
it animate?

## Source

- `dEFManagerCaptainFalconPunchEffectDesc` has flags
  `EFFECT_FLAG_USERDATA` (0x2) only. Without bit 0x1 or 0x4,
  `efManagerMakeEffect` makes one DObj from file 333 + 0x760 (a direct
  display list, despite the `DObjDesc` label). It adds the MObjSub table at
  0x690 and the material animation at 0x830. There is no transform
  animation. The pack already converts this object as manager effect slot 31.
- The DObj's transforms are kind 0x50 (80) and `RotRpyR`. Kind 80 is
  `func_ovl0_800C99CC`: a translation to the world position of the DObj in
  `user_data`. `efManagerCaptainFalconPunchMakeEffect` sets that DObj to
  `fp->joints[16]` for Captain (joint 30 for Kirby's copy) and `rotate.y` to
  `lr * DTOR(-90)`.
- `ftCaptainSpecialNUpdateEffect` runs from both Falcon Punches'
  `proc_physics`. If no effect is attached and script flag 0 is 1, it makes
  the flame and clears flag 0. If an effect is attached and flag 0 is 1
  again, it stops the flame and sets flag 0 to 2. The motion script
  (`235_CaptainMainMotion.c`) sets flag 0 at `WaitAsync(42)` and again
  13 frames later, at frame 55.
- `ftCaptainSpecialNInitStatusVars` clears flags 0–2. Both setters pass
  `FTSTATUS_PRESERVE_NONE`, which stops any attached effect. The
  ground/air switches pass `FTSTATUS_PRESERVE_EFFECT`, so the flame
  survives them.
- The flame's update is `efManagerNoEjectProcUpdate`: it plays the
  animation every frame unless `ftParamProcPauseEffect` paused it for
  hitlag. It never ejects itself. `efManagerMakeEffect` plays it once when
  it is made.
- The display is `lbCommonDObjScaleXProcDisplay`. The flame's two kinds do
  not read `gGCScaleX`, so this draws the DObj as a plain one.

## Implementation

- `CaptainState::punch_effect` counts the flame's played frames.
  `captain::punch_effect_ticks` returns it only in `SpecialN` or
  `SpecialAirN`. The Falcon Punch setters now clear script flags 0–2.
- `psp-game` draws the flame under `T(joint 16 world) · Ry(lr * -90°)`,
  with its baked node matrix. An `EffectMaterialAnimator` (the old
  `LinkVisuals`, now `EffectVisuals`) plays its material scripts up to the
  tick count.
- The capture scene `captain` spawns Captain Falcon, presses B at tick 20
  and freezes at tick 69, some 7 flame frames in. It logs `anim_frame` and
  `punch_effect`.

## Deviations

- Joint 16's position is read at draw time. The source's matrix function
  reads it when the display list is built, after the same frame's update.
- The Falcon Kick flame (manager slot 29) and Kirby's copied Falcon Punch
  flame are not drawn.

## Verification

Host tests check that the flame appears on SpecialN frame 42 with one
played tick and is gone on frame 55, and that it survives the air switch
but not `Fall`. `tools/golden.sh verify --twice` matched all 83 scenes,
including the new `f1-training-captain`, which was identical in both
captures. Workspace tests pass with an absolute `SSB64_ROM` and one test
thread.
