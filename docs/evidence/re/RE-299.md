# RE-299 — Mario Super Jump Punch uses TransN root motion; the legacy flag macros are swapped

Status: COMPLETE
Topics: fighter, animation, asset-pipeline, gameplay
Relevant files: `crates/ssb-rom/src/anim.rs`, `tools/gen-anim-table.py`, `tools/romtool/src/main.rs`, `crates/ssb-game/src/status.rs`

**Question.** Is Mario's `SpecialHi` blocked on unimplemented
`FTAttributes.translate_scales`, as the prior status snapshot claimed, or can
the real animation data be recovered now?

**Evidence.** Mario's attribute record has `translate_scales = NULL`
(`refs/ssb-decomp-re/src/relocData/203_MarioMain.c`). Its two Super Jump Punch
motion descriptors both name `llFTMarioAnimSuperJumpPunchAirFileID` (archive
file 637) in `ftdata.c`, and the status table maps them to statuses 225 and
226. The descriptor uses the source macro `FTANIM_FLAG_XROTN_JOINT`
(`0x40000000`), but `FTAnimDesc`'s runtime bitfield calls that bit
`is_use_transn_joint`; conversely, the macro named `TRANSN` is the
`is_use_xrotn_joint` bit. The macro spellings are therefore reversed relative
to the runtime fields. `ftMarioSpecialHiProcPhysics` reads the TransN delta
through `ftPhysicsApplyAirVelTransNAll`/`ftPhysicsApplyGroundVelTransN`, which
matches the runtime flag rather than the misleading macro name.

File 637 has 25 figatree scripts for Mario's 24 model joints. Its leading
script is the TransN runtime joint, followed by the model tree. The existing
packer already retains that leading script as an `AnimJoint::NO_NODE` entry
and shifts model-joint bindings by one; it did not, however, carry this clip
because the animation table was limited to movement statuses.

**Implementation.** The generated fighter-animation table now includes
Mario's ground and aerial Super Jump Punch slots, both sourced from file 637.
`MarioStatus` maps statuses 225/226 to those slots. The packer terminology was
corrected to call an extra table entry a generic runtime joint: a raw figatree
table alone cannot identify whether its hidden entry is TransN, XRotN, or
YRotN. The completed runtime bridge saves TransN's pre-advance local pose,
then passes the next tick's delta and Z rotation to portable `RootMotion`;
this is the source's `transn - anim_vel` contract without making `ssb-game`
depend on the skeleton or pack.

**Verification.** `romtool anims --verify` decodes file 637 as 40 frames,
matching the decompilation. Rebuilding `assets/generated/ssb64.pak` produces
534 fighter animations. `romtool figatree --fighter Mario --slot
MarioSpecialHi --frames 40 --pack assets/generated/ssb64.pak` replays all
9,800 poses exactly against the ROM, including the extra runtime joint.

**Conclusion.** `translate_scales` is unrelated to Mario's up-B. The source
callbacks now consume the sampled TransN delta: grounded motion follows
`ftPhysicsApplyGroundVelTransN`; aerial motion switches at the script's
frame-9 `SetFlag1(1)` event to `ftPhysicsApplyAirVelTransNAll` and its 0.95
damping; the interrupt callback keeps its pre-launch stick steering and
one-shot launch-facing selection; the 40-frame clip then enters sourced
`FallSpecial`. Its opening,
coin-pulse, and finishing hitbox windows are transcribed from the same motion
script. No velocity arc was invented.
