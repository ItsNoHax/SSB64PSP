# RE-308 — Animated indexed N64 filter compensation

Status: COMPLETE (host and PPSSPP smoke; physical PSP not captured)
Topics: texture, material-animation, asset-pipeline, pack, psp-ge
Relevant files: `crates/ssb-rom/src/filter_compensation.rs`, `crates/ssb-rom/src/psp_texture.rs`, `tools/romtool/src/main.rs`

RE-305 skipped 114 material-animated indexed textures because frame-zero RGB
cannot identify an index uniquely: duplicate RGB entries may have different
colours in later `PaletteID` states. RE-307's single-palette coordinate descent
did not remove that exclusion. This follow-up uses the actual `MatAnimData`
palette pointer table. The converter replays the driving script and selects
only `PaletteID` slots that occur while the primitive's static texture or a
given `TextureIDCurrent` sprite slot is selected. The selected slots remain in
`PaletteID` order. Packed palette tables and their entry order are unchanged.

The source CI4/CI8 index field is read before RGB decoding and expanded using
the same mirror/clamp mapping as the visible image. Each coordinate-descent
step tests every legal index (16 for CI4, valid palette entries for CI8) and
sums exact GE-bilinear-versus-N64-3-point SSE over all reachable palettes and
the primitive's actual triangle UV coverage. Each palette state has equal
weight; no gameplay frequency was inferred. Like RE-307, a coverage sample
votes only on its dominant bilinear texel. Dense coverage is used for texgen.
The shared field is admitted only with at least 5% aggregate SSE reduction,
fewer errors >=8/255, and no per-state max-error or >=32/255 regression.

`pack_mipped_indices` writes the chosen indices directly. Re-quantizing
through frame-zero RGB would collapse equal-colour indices and break palette
animation. Each lower mip chooses an index against all reachable palettes as
well. The algorithm version is 5. The runtime still uses ordinary `GU_LINEAR`;
there is no new texture switch, palette rewrite, or draw pass.

## US-ROM archive census

The earlier blanket rule skipped 114 animated textures. This archive build
found 74 CI4 conversion variants with reachable palette states on the actual
material-animation tables (none CI8). Seven passed the joint indexed gate;
67 kept their original index field. The seven selected variants' combined
filtered SSE fell 1,699,037 -> 1,181,810 (30.44%). Across all 74 variants,
including unchanged ones, SSE fell 9,121,532 -> 8,604,305 (5.67%). These are
equal-weight palette-state and actual-coverage sums. Source and destination
remain CI4 for all seven, so each selected variant's level-zero VRAM size is
unchanged. The complete pack changed 29,920,832 -> 30,058,816 bytes
(+137,984, +0.46%); texture entries changed 1,997 -> 1,998, with no added
direct-colour variants. The one additional packed texture is an identity/
coverage variant; pack deduplication still coalesces unchanged variants.

Six rejected variants meet the high-error admission threshold. Independent
per-palette direct-colour solves would lower their combined measured SSE
6,977,257 -> 5,835,566 at best under the existing solver and acceptance
gates (16.36%), but would require at least 2,950,464 extra bytes of level-zero
texture data before mipmaps, pack descriptors, and runtime switching. No
direct-colour fallback was emitted: switching texture along with `PaletteID`
would need a separate integration for `TextureIDCurrent`, palette cycling,
deduplication, and runtime material-animation identity, and this measured
gain does not justify that cost in this batch.

Synthetic tests cover conflicting palette colours sharing one improved index
field, deterministic output, unchanged palette tables, duplicate RGB entries
retaining separate indices, and correct colour changes when the palette
switches. ROM-gated workspace tests pass. Both release PSP builds succeed.
The rebuilt pack loads back cleanly and one software PPSSPPHeadless viewer
smoke capture succeeds. Two independent pack builds compare byte-identical
(`8752b6491664d767…`). PPSSPP is not physical PSP proof.
