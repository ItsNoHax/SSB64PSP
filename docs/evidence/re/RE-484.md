# RE-484 — A size-class heap instead of a kernel call per allocation

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `profile_hw,capture_scene_file,no_audio` builds of `vs4@2400` from `ms0:/PSP/GAME/ssb64/` with pack v108, `profile_hw.txt` = `frame`, reports 1–18; PPSSPPHeadless `profile` builds for allocation counts and memory)
Topics: performance, hardware, toolchain, memory
Relevant files: `crates/ssb-engine/src/heap.rs`, `crates/ssb-engine/src/array_vec.rs`, `psp-runtime/src/heap.rs`, `psp-runtime/src/profile.rs`, `psp-game/src/play.rs`, `psp-game/src/main.rs`

## Question

RE-483 measured ~9,400 cycles and a cache flush for every allocate-and-free
through rust-psp's `SystemAlloc` (`sceKernelAllocPartitionMemory`). How
many allocations does a frame still make, and what does taking them off the
kernel save?

## Change

- rust-psp's `external-allocator` feature (fork commit `3ecf457`) forwards
  the global allocator to `__psp_external_alloc`/`_dealloc`/`_realloc`,
  which `psp-runtime/src/heap.rs` defines. A `#[global_allocator]` in the
  application does not work: rust-psp also builds as a `staticlib`, which
  then has none.
- Blocks up to 32 KiB, aligned up to 16, come from
  `ssb_engine::heap::SmallHeap`: 23 size classes (16, 24, 32, 48, ...,
  32,768), free lists over 256 KiB chunks taken from `SystemAlloc` and
  kept. Larger or more aligned blocks still go to the kernel, so scene
  loads and their out-of-memory screen are unchanged. A lock guards the
  lists (the audio thread allocates); a thread finding it held sleeps 1 µs
  so it never spins on a holder it preempted. A `realloc` within one class
  returns the same block.
- `profile` reports count `allocs` and `kallocs` (kernel) a frame and the
  small heap's `heap=chunk/live` bytes.

A trace of return addresses (not committed) put VS's eleven in `psp-game`:
`interrupt_pass`'s opponents (224 B) and `CpuSight::observe`'s item list
(304 B) per CPU, and `fighters_mut` (16 B, four a frame). They are now
`ArrayVec`s bounded by the game's own counts (3 opponents, 4 fighters,
`ITEM_ALLOC_MAX` items, two threats per `MAX_WEAPONS` weapon). Outside
scene loads no frame takes a kernel allocation.

## Memory

The small heap keeps its chunks and free lists: 512 KiB of chunks in VS,
How to Play and 1P (~320–380 KiB live), 768 KiB late in the opening.
Lowest free memory against `62f3f87`: PSP-2000 VS 36.37 → 36.09 MB;
PPSSPP VS −466 KB, opening −690 KB, How to Play −429 KB. PPSSPP
screenshots of `vs4@2400`, `opening@2500` and `explain@4460` are
byte-identical to `62f3f87`'s.
