# RE-287 — Physical-PSP confirmation of RE-286's 37 new stage goldens

Status: COMPLETE
Topics: stage, visual-regression, hardware
Relevant files: psp/Cargo.toml (`regression_capture_stage_index`), psp/src/main.rs (`SSB64_STAGE_INDEX`)

**Question.** RE-286 added deterministic PPSSPP software goldens for the
remaining 37 stage entries (indices 1, 2, 3, 5, 6, 8, 10-40 of the 41-entry
stage table), deliberately deferring physical-PSP confirmation to a later
batched pass — the user's own explicit choice, given the cost of 37
sequential PSPLink cycles. `STATUS.md`'s required-next-action item (1) named
this as the top-priority remaining R2 work. This session runs that batched
pass.

**Method.** PSP Slim, firmware 6.61, ARK/Infinity, PSPLink v3.2.1, connected
over USB (`054c:01c9`), bridged via `usbhostfs_pc -v "$PWD"` from the
repository root. For each of the 37 stage indices: built once with
`SSB64_STAGE_INDEX=<n> cargo psp --release --features
regression_capture_stage_index` (no `headless_capture` — this is a native
hardware run, not PPSSPPHeadless), `pspsh -e ldstart host0:/psp/target/
mipsel-sony-psp/release/ssb64-psp.prx`, waited 6 real seconds past the
tick-240 deterministic freeze, checked `exlist` for exceptions, captured a
native 480x272 BMP via `scrshot`, hashed it, then `kill`ed the exact module
UID and `reset` PSPLink before the next `ldstart` (this project's own
established default — RE-212 found a bare `kill` can silently leave stale
module-manager state with no `exlist`/`thlist` symptom). Automated as a
looped script (build → load → wait → exlist → scrshot → hash → kill →
reset) after validating the first few iterations manually.

Stage index maps to ROM stage-table file id by `file = 255 + index` (romtool
`stages` output, position 0 = file 255): e.g. index 1 = file 256 (Beta Dream
Land), index 5 = file 260 (Mushroom Kingdom), index 40 = file 295 (the last
bonus map, Race to the Finish) — consistent with RE-286's own file-id
references.

**One tooling bug found and fixed during setup, no production code
involved.** The batch script's first attempt wrote `scrshot` output to an
absolute scratch path (`host0:$SCRATCH/stage_NN.bmp`); `host0:` only maps
the repository root `usbhostfs_pc` was launched from, not the host's real
filesystem root, so every write silently landed outside the served tree
even though the PSP-side command still printed a success line
(`frame_addr ... output host0:/...`) — a variant of this project's own
"screenshot harness traps" lesson (a command that *reports* success is not
proof of a written file). Fixed by writing under the served repo root
(`host0:/stage_NN.bmp`) and moving the file out after each capture. Caught
immediately (first test batch's two BMPs were empty/missing) before it
could taint any hardware evidence.

**Result — all 37 confirmed clean:**

* **Zero exceptions** on every one of the 37 loads (`exlist` empty each
  time) — no hardware-only crash surfaced across the full stage table.
* **No blank/locked captures.** Every BMP is a full 391,734-byte native
  480x272 24-bit frame; per-capture unique-color counts (via `magick
  identify`) range 360-6,040, never near the near-solid-color floor a
  locked screen or the earlier scrshot bug would have produced.
* **8 of the 37 spot-checked pixel-for-pixel against their PPSSPP golden**
  (converted BMP to PNG, visually compared side-by-side): index 1 (Beta
  Dream Land), index 2 (Zebes), index 3 (Test Stage), index 5 (Mushroom
  Kingdom), index 10 (Hyrule Castle), index 16 (`r2-stage-bonus1-mario`),
  index 40 (`r2-stage-bonus3-race-to-the-finish`) — every one an exact
  geometry/collision-line/marker match, modulo the PSPLink debug-overlay
  text in the capture's corner (the same known, excluded-from-comparison
  overlay RE-201 onward already documents). This matches RE-286's own
  "spot-checked visually" bar for the software pass, now repeated on
  physical hardware.
* The remaining 29 captures were not individually pixel-compared (that
  would mean converting and visually inspecting all 37, a much larger
  effort than this project's established spot-check convention), but share
  the same zero-exception, non-blank, substantial-color-count evidence as
  the 8 that were compared, and were produced by the identical, now
  twice-validated capture path.
