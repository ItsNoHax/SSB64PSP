## Source and ROM findings

`if/ifcommon.c:ifCommonPlayer*`, `ft/ftdisplaymain.c:ftDisplayMainProcDisplay`,
`gm/gmcamera.c:gmCameraPlayerMagnify*` and the Training View callbacks are
the source. Tag lifecycle comes from `ftMainSetStatus`, update/interrupt
and the common damage, crouch, cliff, rebirth, capture and aerial-jump
setters, including Kirby's and Jigglypuff's multi-jumps. Entry and every
Appear phase hide the tag; the terminal Wait clears that gate. The source
DokanWait hide rule is retained while pipe traversal remains deferred.

| Behaviour | Source rule |
|---|---|
| Tags | Draw unless hidden/boss-end, when wait equals 1 or camera eye Z exceeds 6000. Project TopN plus `camera_zoom_base`, test inclusive ±150/±110 bounds, then truncate the centred sprite position to integers. |
| Wait | Wait, SquatWait and CliffWait set 120; Squat entry does not. Decrement only above 1, outside hitlag and with controls enabled, before update/interrupt. Level-3 knockback at least 130 sets 10. Rebirth and star/capture exits set 1. Source preserve masks carry it through aerial jumps, tumble/down and rebirth transitions. |
| Visibility | Shift the camera-offset probe toward camera.at before testing bounds. An off-screen fighter leaves the main draw even when magnifiers are disabled. Invisible fighters, star/screen KOs, magnify-ignore and rebirth use their separate source gates. |

AddAnim plays once and the rising-edge update plays again. Three ROM visibility scripts each repeat after nine ticks. Magnifier sound requests repeat after 30 ticks. |
| Magnifier | Scale is projected 600 units / 18, capped at 3. Intersect the direction ray with the viewport inset by 20×scale (plus five horizontally). | Training | The open menu hides Interface-link tags/arrows. The Magnify link still draws. Close-Up disables magnifiers immediately; Normal enables them after 180 process ticks. |

ROM file 166 contains the arrow tree at 0x188, its joint table at 0x270,
the pointer list at 0x30 and the linear IA8 16×16 frame quadrant at 0x2C8.
Mirror both axes to form the 32×32 image; sprite-row swapping is wrong for
this directly loaded image. Tags are file 38's 1P–4P, CP and Ally sprites.

Two wrappers matter: the arrow wrapper sets unlit `G_CC_PRIMITIVE`, red
PRIM at alpha 128 and a blending render mode; the pointer wrapper supplies
the player PRIM colour. Seed those registers before converting the trees.
Untextured flat PRIM alpha is classified separately from RGB. Comparing
the pack before/after that alpha classification changes only the three
arrow primitives (file 166 lists 0xB0/0xF8/0x140), flags 0x111 → 0x351.
The ROM-backed test checks colour, transparency and baked alpha.

## Native adaptation and projection

The original draws the IA frame as RGBA5551 **into the Z buffer**, then
paints it using fog/player colours before drawing the miniature. A square
scissor alone cannot reproduce that mask. The generic PSP backend samples
the original image with the existing three-point filter, packs RGBA5551,
decodes its compressed RDP Z and writes equal-depth horizontal pixel spans
with colour writes masked off. Then it paints the frame and draws the
fighter through the miniature camera. It does not invent circle geometry.

The RDP word has 14 depth bits and two dZ bits; depth expands to 18 bits.
Format reference: [paraLLEl-RDP z_encode.h](https://github.com/Themaister/parallel-rdp/blob/1cecd042b2619bc505c12bfdc713808386f2b54d/parallel-rdp/shaders/z_encode.h).
The PSP maps that depth to its inverted linear 16-bit range. This loses
two bits of depth precision; GE sampling/rasterisation has no RDP coverage
or dZ-based comparison tolerance. The native-pixel sampling also differs
from the original 320×240 fixed-point texture rectangle. Emulator captures
confirm the circular clipping and colours, not exact RDP edge equivalence.

The interface exposed two inherited projection errors: the game renderer
used a fixed 38° FOV and the full 320×240 area, while the portable camera
used the original live FOV and (10,10)–(310,230) viewport. Main models,
stage geometry and particle projection now share the source 300×220,
15/11 viewport and live FOV. Entry/pause zooms are no longer rendered at
38°. Tags use the interface camera's same scissor. Wallpaper padding and
other existing rendering differences are outside this change.

Gameplay timers/probes/rays live in `ssb-game`, ROM decoding in `ssb-rom`,
GE projection/depth writing in `psp-runtime`; the game only adapts assets
and orchestrates the cameras. Sound requests are preserved; dispatch
awaits the audio backend (TODO.md).

Pack v88 adds the Ally tag, magnifier image/pointer and arrow scripts using
existing descriptors, with no layout change. Size 35,785,808 bytes
(+7,664 over v87), SHA-256
`79294fc8fbbbff630df8a8779043877bd4ba9efd1bc59f7ceecf9175cc0cd9ca`.
