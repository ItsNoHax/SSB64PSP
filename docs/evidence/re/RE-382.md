# RE-382 — Items in `psp-game`: the PK Fire flame, Link's Bomb findings and `run`'s branch range

Status: PARTIAL (decomp source, ROM bytes, host test, `psp-asset-viewer` object capture, both PSP builds; the flame is not reached by any capture scene; Link's Bomb is not drawn; no physical PSP)
Topics: item, asset-pipeline, rendering, psp-platform
Relevant files: `crates/ssb-game/src/item/{mod,tests}.rs`, `crates/ssb-rom/src/pack.rs`, `tools/romtool/src/main.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`

## Question

How do items draw and animate? The two ported kinds are Ness's PK Fire
flame and Link's Bomb.

## Source

- `itManagerMakeItem` gives every item display link 11: the camera pass
  with the fighters (link 9), under the camera's default head modes.
  `is_display_xlu` picks `itDisplayXLUProcDisplay`
  (`gcDrawDObjTreeDLLinksForGObj`) or the OPA display. It adds
  `ITAttributes.anim_joints`/`p_matanim_joints` with `gcAddAnimAll` and
  plays them once. `itProcessProcItemMain` plays them again on each frame
  whose hitlag has run out, before `proc_update`.
- **PK Fire flame.** `dITNessPKFireItemDesc` is `TraRotRpyRSca`.
  `llNessSpecial1PKFireItemAttributes` (file 240 + 0x34) names file 336's
  four-node tree at 0xA08 and its transform table at 0xAF0 (scripts for
  nodes 2 and 3), with `is_display_xlu`. Node 3's desc id carries a ROM
  billboard kind. `itNessPKFireProcUpdate` sets the root scale from the
  remaining lifetime. The flame is made only by `wpNessPKFireProcHit`, a
  spark hitting a fighter; `wpNessPKFireProcMap` destroys a spark that
  meets the map without a flame.
- **Link's Bomb.** *Corrected in RE-383: the record below is
  `llLinkMainSpinAttackWeaponAttributes` (225 + 0x0C), not the Bomb's.*
  File 225's words from 0x0C name file 324's two-node tree at 0x11908,
  MObjSub table 0x110A8, transform table 0x11990 and material table
  0x11A40. The decomp declares all three
  tables as `{ NULL }` placeholders; the ROM bytes hold `[NULL, 0x114E8]`,
  `[NULL, 0x11998]` and `[NULL, 0x11C1C]`. Node 1's `DObjDLLink` (0x118F8)
  runs the list at 0x11680: nine MObj texture strips under an orange
  environment-colour ramp. `itLinkBombMakeItem` adds kind 0x2E (46) to the
  root and its child.
- In `gcPrepDObjMatrix`, kind 46 rewrites only the MVP's rotation rows.
  Its scale accumulates through `gGCScaleX` down the tree, and the
  modelview (translation) still composes normally.
- `itMainSetFighterHold` hangs a held item under a new parent DObj of
  kind 0x52 (82 on US; 0x51 elsewhere), whose `user_data` is the fighter's
  heavy or light item joint. It then resets the item's own DObj transforms
  to its desc.

## Implementation

- `Item::anim_ticks` counts `gcPlayAnimAll` calls: 1 at creation, plus one
  per update outside hitlag.
- Pack v58 (27,262,256 bytes) adds `AnimDesc::ITEM` and item slot 0, the
  PK Fire flame's table. `Pack::item_anim` reads it.
- `psp-game` draws each flame under `T(pos) · S(item.scale) ·
  MODEL_SCALE` with its posed tree. This happens in the item pass after
  the fighters and before the weapon and effect pass.
- `psp-game`'s `run` had reached 233 KB, past MIPS's ±128 KB branch range;
  the `golden_capture` build failed with `out of range PC16 fixup`. Moved
  out as `#[inline(never)]` functions:
  - the Training simulation frame (`training_step`);
  - the capture log (`log_capture_state`);
  - the item, weapon and effect draw (`draw_items_weapons_effects`).
  `run` is 163 KB in the release build, still over 128 KB, so a later
  growth can overflow a branch again.

## Findings

- The flame tree, captured alone in `psp-asset-viewer`
  (`SSB64_CAPTURE_OBJECT=336:0xA08`), draws a flame pillar over a
  flickering base.
- No Training capture reaches a flame. The dummy stands on the upper-left
  platform, out of reach of either spark.
- The graph drawn as the Bomb showed as an orange smear above Link's
  head, and drew nothing alone in the viewer. RE-383 found it was the Spin
  Attack weapon's ring, read from the wrong attributes record, and draws
  the real Bomb.

## Verification

A host test covers the item animation count, including the hitlag pause.
`tools/golden.sh verify --twice` matched all 92 scenes. Workspace tests
pass with an absolute `SSB64_ROM` and one test thread.
