## Question

How does the original run Final Cutter Draw/Up/Down/Trail, the landing, and effect pause in hitlag?

## Evidence

- **Effects.** `ftKirbySpecialHiUpdateEffect` runs first in all four physics procs. Slots: one per kind; a second Draw restarts it.
- **N64 timeline** (warp ROM, route `1:40:x=-127;64:1:y=80;65:1:b+y=80`): SpecialHi af1 at t65; Draw af2; Up af21; Draw af24; Down af46; Draw af50; Trail af52; Draw af58. AirHiFall keeps Draw; fall landing (af0, no first-frame play) stops it. Rust equals every frame.
- **Shapes.** N64 af22/31/47/54 vs PSP `kirbycutter@117/126/142/149`: Up fan, Draw blade, Down arc and Trail wedge match. Residual: N64 Down flare brighter; PSP sparkles denser (not cutter effects).
- **Landing.** `ftKirbySpecialHiLandingSetStatus` (ftkirbyspecialhi.c:276-277) ends in `ftMainPlayAnimEventsAll`: the setter enters at af1 (RE-474 convention). The fall landing is a separate setter, no play. `PRESERVE_EFFECT` only for SpecialHi/AirHi to Landing.
- **Hitlag.** Own-clock effect ticks (Link spin, Captain specialn/lw, Kirby cutter) now also run in the hitlag branch; `lag_pauses_effects` holds them only when set.
- **Flush fix.** A queued stop no longer clears an `is_effect_attach` made after it by a synchronous maker (frame 21 stop+Up left Draw/Down/Trail never drawn on PSP).
- **Golden consequences.** `f1-training-kirby` 77264 native px (landing a frame later); `f1-vs-team` 96571 native px (CPU Kirby SpecialHiLanding af1, first divergence tick 590). New row `f1-training-kirby-cutter`.
