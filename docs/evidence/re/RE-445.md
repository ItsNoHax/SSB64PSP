# RE-445 — Thrown-fighter attacks and throw ownership

Status: IMPLEMENTED (decomp/ROM evidence, host regressions, both production PSP builds and PPSSPP smoke; no N64 runtime or physical-PSP comparison)
Topics: fighter, combat, motion-scripts
Relevant files: `crates/ssb-game/src/{thrown,thrown_tests,grab,combat,stale,status,capture_kirby,fighter}.rs`, `crates/ssb-game/src/motion/{mod,scripts}.rs`, `crates/ssb-rom/tests/thrown_attacks.rs`, `tools/gen-motion-scripts.py`

## Questions

What attacks does a thrown fighter make, who owns them, and when does the
ownership start and end?

## Source evidence

- `ftCommonThrownReleaseThrownUpdateStats` stores the throw's `script_id`
  (forward and cargo 0, back 1) and, when `is_proc_status` is set, installs
  `ftCommonThrownProcStatus` before `ftCommonDamageInitDamageVars`.
  Falcon Dive passes `is_proc_status = FALSE`; `DamageRelease` never sets
  it. The percent update follows the damage status.
- `ftMainSetStatus` clears `throw_gobj` unless
  `FTSTATUS_PRESERVE_THROWPOINTER`, then runs `proc_status`
  (`ftParamSetThrowParams`: gobj, fkind, player, player_num, team) before
  the new motion's time-zero events. Kirby's spit and copy stars set the
  same parameters and enter their statuses with the preserve flag.
- `nFTMotionEventSetDamageThrown` does nothing without `throw_gobj`;
  otherwise it calls the subroutine at `table[script_id][throw_fkind]`.
- `ftCommonDamageCommonProcPhysics` clears all attack collisions once
  `|vel_damage_air| < 70` while `throw_gobj` is set; the pointer itself
  lives until the next status change. An electric throw enters
  `DamageE2` first, so its passive transition drops the pointer.
- Hits by a thrown body credit `throw_player`/`throw_player_num`, update
  the thrower's stale queue with the body's motion ID and count, and use
  `throw_team` for the team rule.

## ROM evidence

File 201 holds the table at 0x758: 2 × 27 intern pointers. Every slot
points at the common 0x728 script except the back row for Mario, Metal
Mario and Polygon Mario (0x740). All 12 playable fighters' damage scripts
reference it through an extern relocation. `crates/ssb-rom/tests/thrown_attacks.rs`
checks the pointers, each fighter's generated `SetDamageThrown` word and
the resulting collision fields against the ROM.

## Port

`crate::thrown` owns `ThrowOwner` and `ThrownState`. The release path
queues a one-shot pending owner; `set_any_status_preserve` clears the
owner unless preserved and consumes the pending owner right before
`motion::start`. The generator keeps the pointer table, including NULLs,
in its file layout.

Deviation: the port counts motions per fighter, not globally. Thrown-body
stale entries therefore carry their origin port, so two bodies' local
counters cannot suppress each other as duplicates. Body attacks have no
attack ID and bypass the staling lookup, so this changes no damage.
