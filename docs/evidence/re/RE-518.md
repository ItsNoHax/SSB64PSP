# RE-518 — Status changes reset the catch flag and the capture-immune mask

Status: COMPLETE (host tests)
Topics: grab, catch, capture, status
Relevant files: `crates/ssb-game/src/status.rs`, `crates/ssb-game/src/grab.rs`, `crates/ssb-game/src/reaction.rs`, `crates/ssb-game/src/kirby.rs`, `crates/ssb-game/src/stage/jungle.rs`, `crates/ssb-game/src/stage/hyrule.rs`

## Question

On the PSP, grabs rarely connected and, after a grab, the opponent could not be damaged. Why?

## Findings

- C `ftMainSetStatus` (ftmain.c:4505, 4522) clears `is_catchstatus` and `capture_immune_mask` on every status change. `set_any_status_preserve` did neither. A Catch or CatchPull that ended any way but the release path (a hit, a ledge fall, a Kirby or Yoshi switch) kept `is_catchstatus`, and combat then skipped that fighter's own hitboxes.
- `set_down_wait` set the immunity and nothing cleared it, so a fighter knocked down once was ungrabbable for the rest of the match.
- The immunity is a u8 mask (`FTCATCHKIND_MASK_*`, `grab::catch_kind`): YOSHI_SPECIAL_N 0x1, KIRBY_SPECIAL_N 0x2, TARU_CANN 0x4, TWISTER 0x8, COMMON 0x10, CAPTAIN_SPECIAL_HI 0x20, ALL 0x3F. `ftParamSetCatchParams` picks the catcher's mask: KIRBY for Inhale, YOSHI for Egg Lay, CAPTAIN for Falcon Dive, COMMON otherwise. A catch is refused when `victim.mask & catch_mask != 0`.
- DownWait sets CAPTAIN|COMMON|KIRBY|YOSHI (ftcommondownwaitbounce.c:55), so the barrel and the tornado still take a downed fighter. CliffCatch and CliffWait set TARU_CANN only. Kirby SpecialN End and the Turn path set no mask. The Jungle barrel tests TARU_CANN (grjungle.c:148); the Hyrule tornado tests TWISTER (grhyrule.c:442).
- `ftMainProcSearchCatch` runs `proc_capture` inside the search. `search_catch` now claims the victim there, so two catchers cannot take one victim in a frame.
