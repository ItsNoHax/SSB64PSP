# RE-317 — Attribution and rebaseline of the eight known-failing goldens

Status: COMPLETE (PPSSPP software: commit-by-commit captures since a77e539; 8 goldens rebaselined, all 67 pass; physical PSP not captured)
Topics: visual-regression, texture

Relevant files: `tests/golden/`, `tests/golden/scenes.tsv`,
`psp-runtime/src/gu.rs` (`Gpu::begin_frame`)

**Question.** Eight goldens had differed from current output since before
RE-313 and were never re-investigated: `r2-metal-texgen`, `-rotated`,
`-linear`, `-camera-rotated`, `r2-depth-mask-diagnostic`,
`r1-mvopeningroom`, `f1-training-fireball`, `f1-training-shadows`. Which
commits changed them, and is each change intended?

## Method

Each scene was captured with its per-feature build at every commit that
changes code or pack inputs between `a77e539` (the PSP toolchain migration,
2026-09-20) and `b72fa5b`. Every capture uses a pack built from the ROM by
that commit's own `romtool`. The machine was otherwise idle: a first pass
run alongside another capture job showed a false 45–54k pixel change at
`81eeca6` (Fox moveset). Before RE-315 the viewer ticked material animation
per render frame, so a slow host changes the pose. Idle captures at
`2ffbb96` and `81eeca6` repeat exactly and are identical to each other.

## Causes

- **Texture sampling and compensation.** RE-304 changed GE sampling
  alignment and RE-305 to RE-310 changed pack texels. Other goldens were
  rebaselined across this series (for example `7b69e5c`, `bc060d4`,
  `5657795`, `3f2d3ae`); these eight were already failing and were
  skipped. The texgen scenes show shifted reflection samples; the `psp-game` scenes show the sharper compensated
  Dream Land textures that the passing `r0-dream-land-default` golden
  already pins.
- **Pillarbox.** Before `5657795`, `Gpu::begin_frame`'s clear ran under the
  previous frame's pillarboxed scissor, so one of the two swap buffers never
  had its pillarbox cleared. Which buffer a capture showed depended on the
  render-frame parity at tick 240. RE-305's pack changed load timing and
  flipped it in the viewer (black to the clear colour; the whole
  `r2-depth-mask-diagnostic` difference). `5657795` clears the full screen on
  both buffers; in `f1-training-fireball` that removed stale menu bars from
  the left pillarbox.
- **Scenes 7/8/9 before `a77e539`.** The remaining 1,204 / 5,044 / 4,412
  pixels predate the toolchain migration. Idle captures with the old
  toolchain (`cargo-psp` 0.2.9, `nightly-2026-08-01`) at `8051b2b`,
  `a44e320` and `d916b71` are stable across those commits but match neither
  the goldens nor `a77e539`. That is consistent with the per-render-frame
  animation timing RE-315 removed, but not proven. These pixels cannot be
  attributed to a commit. Current
  output no longer depends on that timing (RE-315).

## Result

All eight goldens were replaced by current output, captured twice with
`tools/golden.sh rebaseline` (each repeat identical), and are byte-identical
to the RE-316 references. Their manifest rows are now `pass`.
