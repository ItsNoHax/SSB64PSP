# RE-012 — Nightly toolchain pin

Status: SUPERSEDED
Topics: toolchain
Relevant files: psp-game/rust-toolchain.toml, psp-asset-viewer/rust-toolchain.toml

**Question.** Why was the PSP crate pinned to a specific nightly?

**Evidence at the time.** `rust-psp` 0.3.13 imported
`core::panic::PanicPayload` in its panic handler (`psp/src/panic.rs:15`). That
path no longer resolved on `nightly-2026-08-26`, and the then-current upstream
master had the same import.

**Implementation at the time.** `psp/rust-toolchain.toml` pinned
`nightly-2026-08-01`, which still exported it.

**Superseded (2026-09-20).** Upstream commit `998cd52` moved the import to
`alloc::panicking`; SSB64PSP now pins its `rust-psp` dependency and
`cargo-psp` tool to fork commit `a89142b`, which contains that upstream fix,
the project's `MEMSIZE` Psp.toml support, and skips its unused Rust-source
submodule during Cargo dependency resolution. Both PSP applications pin
`nightly-2026-08-26`. A successful compile remains insufficient release
evidence: the resulting EBOOT must boot in PPSSPP before considering this
transition fully verified.
