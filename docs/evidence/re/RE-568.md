## Question

Does the host CPU track an item, start 1P stages with the N64 level and trait, wake Link, and enter VS with the N64 entry focus?

## CPU tracks an item (`cpu34a`)

- Warp: `warp_link.z64` copy (Link CPU vs Mario dummy, Castle). P1 `fp->team` poked to 0 at t <= 2: no target, so `ftComputerProcDefault` reaches the item branch. Training does not reset teams.
- Route `cpu34a.route`: CP option stepped to Default, Beam Sword spawned from the menu. 900 frames, deterministic across reruns.
- Logger: `FTStruct.computer` = +0x1CC (found at runtime by scanning for `ftComputerProcDefault`). Fields: objective +0x00, objective_base +0x01, behavior +0x03, trait +0x05, `item_track_wait` +0x12 (u16).
- Timeline: menu lock 70-179; Default proc from 180; sword lands (-1391.12, 1838.27) at ~224; `item_track_wait` counts from 225; TrackItem (objective 5) at t=375; LightGet (status 100) at 463; objective Attack after pickup; wait reset at 466.
- Host: `a_cpu_tracks_a_dropped_item_as_on_the_n64` (`item_replays.rs`, table `CPU_TRACKS_A_DROPPED_SWORD`) matches through t=600, max error 0.0050. No `ssb-game` divergence.
- Negative checks (both fail): track wait +1 (`attack.rs`, fails t=375); team poke removed (fails t=180).
- Table holds positions, ticks and state numbers from the trace, like `castle_replays.rs` (D-048).

## 1P stage start

- Warp builds `warp1p_N.z64`: `scManagerRunLoop` patched to `nSCKind1PGame`, `spgame_stage` = N, Mario, player 0 (reverted, never committed). Easy, 2 stocks. Luigi (stage 14) needs START on the challenger screen.
- Stages read: Link, Yoshi x3, Fox, Mario Bros, Pikachu, DK, Kirby x2, Samus, Metal Mario, Polygons x3, Master Hand, Luigi. Every CPU's team, level, handicap and trait equal `Game::setup_stage_all`. Initial `behavior_change_wait` = 1440 - 240*level, saturating. Master Hand reads 0 (not processed).
- Not compared: ally and Polygon fkinds (RNG shuffles).
- Test `stage_start_levels_traits_and_handicaps_match_the_n64` (21 rows plus human level). Negative check: Normal fails.
- Fix 1: `spgame::BattlePlayer::default().level` 1 -> 3 (`dSCManagerDefaultBattleState`); not observable in play.
- Fix 2: `process_trait` leaves `objective_base` unchanged for Stand, Walk, Evade, Jump, Unk4, Unk5 (`ftComputerProcessBehavior`). N64 Link reads base 0 while standing; the host had set Attack. Not observable (only `proc_default` reads it). Test `the_link_trait_...`; the old `_ => Attack` fails.
