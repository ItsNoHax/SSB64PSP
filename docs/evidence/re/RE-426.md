## Questions and source

RE-425 left eyes/mouths on texture 0, make-time parts on the selects/results,
and high detail in every battle. Which image does the source swap, what
happens on status/material changes, and which rule selects low detail?

- `FTAttributes` + 0x330 names two texture-part records: joint and
  material-chain index at each detail. DK and Samus have none.
- `ftparam.c:1070–1177`: Init reapplies the current ID; Set changes
  the material's texture_id_curr and records it; Reset applies the base.
  Hidden joints/missing materials decline writes. A model remake zeroes
  its new material's ID but retains the recorded ID. Kirby Stone head
  (part 2) and Ness alternate head (part 1) have no named face material
  in either detail; ROM-backed tests pin these exceptions.
- `ftmain.c:597–605` decodes the part and sprite ID. This handles the
  369 battle-script events plus demo events. There is no separate C call
  to SetTexturePartID outside the interpreter: damage/blink/sleep/KO faces
  are script writes. Status entry restores base detail and resets modified
  faces unless FTSTATUS_PRESERVE_TEXTUREPART (`ftmain.c:4408–4450`).
- `gcDrawMObjForDObj` loads sprites[texture_id_curr] with the same tile
  and palette. The pipeline tags material-owned primitives and converts
  reachable sprites through each costume's palette/tile. Later explicit
  image/material binds clear ownership. Unselected NULL sprite slots
  (Kirby IDs 1–4) do not invalidate selected entries.
- `scsubsysdata*.c` supplies Null, Win1–4 and Lose demo rows. Their flow
  interpreter retains ordering, waits, loops, subroutines and jumps and
  applies model/texture events when made, assigned a status and ticked.
  Host tests pin Mario's repeated blink and Kirby Win1 mouth ID 5 at
  script tick 158. Preserve tables and demo words are generated from source.
- `scvsbattle.c:188`, `sc1ptrainingmode.c:1809`, `sc1pgame.c:1379`:
  desc.detail is high with fewer than three active fighters, low otherwise.
  `ftmanager.c:704` initializes current/base from it. This fighter
  model selection is separate from the engine's other LOD controls.
  Both detail trees, parts, costume materials, accessories and skeletons
  work. Missing low lists retain high lists/materials. Pause temporarily
  draws the zoomed fighter high; resume restores it. DeadUpFall draws
  high; later status entry returns to base. Both trees share the pose.

Low saves **324,608 bytes (30.9%)**. Two 512×272×4 framebuffers and
512×272×2 depth leave **704,512 bytes** of VRAM: low still exceeds this
by **22,412 bytes**. This is packed residency demand, not a hardware
allocation measurement. The runtime samples pack textures from main RAM;
other stages/costumes can need more. Residency remains open.

The pack uses 33.75 MiB; production ELF text/data/BSS total 3,326,984
bytes before dynamic allocations. Game/viewer goldens load v78 in
MEMSIZE=1 64 MiB mode. No new physical PSP or PSP-1000 proof.
