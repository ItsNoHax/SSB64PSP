# RE-309 — GE-exact integer refinement after 3-point compensation

Status: COMPLETE (host and PPSSPP smoke; physical PSP not captured)
Topics: texture, asset-pipeline, pack, psp-ge

Relevant files: `crates/ssb-rom/src/filter_compensation.rs`, `tools/romtool/src/main.rs`

**Problem.** The projected-gradient solve uses continuous bilinear channel
values. The final pack stores integers, and the GE samples them with 4-bit
fractional weights and truncating arithmetic. Rounding the continuous result
therefore leaves measurable GE-exact error on the table.

**Implementation.** `refine_integer` starts from the rounded solve and visits
each texel/channel in fixed order. It tests the current stored value and its
clamped +/-1 and +/-2 neighbours, then repeats up to eight sweeps or until a
sweep changes nothing. A precomputed influence list includes only coverage
samples with a nonzero GE bilinear weight on the texel. Candidate scoring
recomputes only those samples through `compose_bilinear`, the same exact
integer arithmetic used by the reference sampler; cached contributions and
an error histogram keep the global objective current.

The objective is lexicographic: lower squared error, then fewer samples with
error >=32, then fewer with error >=8, then lower maximum error, then smaller
distance from the rounded seed's stored value, then lower stored value. A move
must strictly improve this tuple. This ordering can allow a per-variant
threshold count or maximum to increase when SSE falls; archive aggregates
below show those changes explicitly. Opaque alpha remains fixed at 255.
Translucent visible (premultiplied) SSE cannot exceed the seed's. Every cutout
sample keeps the seed's alpha-test pass/fail classification, and the existing
final silhouette gate still applies where the format decision uses it.

RGBA8888 searches byte channels directly, including when an indexed source
is promoted to direct colour. RGBA5551 starts from the quantized solve and
searches 5-bit RGB codes and the 1-bit alpha code; every candidate is exactly
representable. CI4/CI8 variants retained as indexed continue through the
separate palette-index optimizer. UVs, runtime code, GE state, and palette
tables are unchanged. The compensation cache version moves from 5 to 6.

**Synthetic proof.** A 2x2 saddle fixture runs the actual float solve and
shows the rounded result has strictly higher GE-exact SSE than its integer
refinement. Tests also prove repeated results are byte-identical, opaque alpha
stays 255, RGBA5551 output requantizes to itself, and a cutout threshold is
preserved while translucent visible SSE does not regress.

**US archive census, same build with and without only this refinement.** The
pre-refinement pack already present in `assets/generated/ssb64.pak` was
30,058,816 bytes, SHA-256 `8752b6491664d7678655c884c2575fbf5a911d88f2dba0dbe964902c8a33c9f6`.
The refined pack is the same size, SHA-256
`918e850220fa0653d50c12f6864a969e4db101ead452b91b11b2fb98609bd059`.
All 427 compensated variants retain their format (318 CI4, 109 RGBA8888;
no CI8 or RGBA5551 variant reached this stage). The 109 final direct-colour
variants all improve SSE, with no SSE regressions:

| Exact metric summed over 109 direct variants | Rounded solve | Refined | Change |
|---|---:|---:|---:|
| Squared error | 276,336 | 248,507 | -27,829 (-10.07%) |
| Samples with error >=32 | 17 | 17 | 0 |
| Samples with error >=8 | 534 | 503 | -31 (-5.81%) |
| Sum of each variant's max error | 1,676 | 1,643 | -33 |

Eight individual variants increase their `>=8` count and three increase
their maximum error while lowering SSE, as the documented objective allows.
The indexed optimizer and its metrics are unchanged. Two independent refined
pack builds and their diagnostic logs compare byte-identical. The packer's
loadback check passes. ROM-gated workspace tests, both release PSP builds,
and a software PPSSPPHeadless asset-viewer smoke capture pass. PPSSPP is not
physical PSP proof.
