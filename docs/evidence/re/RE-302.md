**Source behaviour.** `ftManagerMakeFighter` creates one `nGCCommonKindShadow`
GObj per non-demo fighter unless its descriptor opts out. Its display callback
is on link 13. `ftShadowProcDisplay` loads the first 128 bytes of file 84's
`dEFCommonEffects2_Shadow_TextureImage` at `0x3A68` as a 16×16 I4 texture,
with mirror+wrap on both axes. It derives the horizontal half-width directly
from `FTAttributes::shadow_size` (200 for the normal playable roster, 350 for
Donkey/Giant Donkey, 800 for Boss); it neither scales nor fades by altitude.

Grounded fighters use `coll_data.floor_line_id`; airborne fighters call
`mpCollisionCheckProjectFloor` down from the root. After the source's wall
occlusion guard, the code clips `center ± shadow_size` to the selected floor
line and follows its polyline through at most two internal vertices. The
result is four, six, or eight vertices at Z ±200 with interpolated floor Y;
the source texture coordinates span 0..1984 S10.5 units (62 texels), retaining
the visibly tiled/mirrored pattern. This is why an ellipse/quad would be
incorrect on stage edges or slopes.

`dFTShadowNoPrevLinkDL` supplies `G_RM_AA_XLU_SURF`,
`G_CC_MODULATEIA_PRIM`, threshold alpha comparison against blend alpha 0x0F,
no lighting/shading/culling, and an I4 texture. Primitive colour is default
black `(0,0,0,0xA0)` or team red/blue/green `(0x80,0,0,0xB4)` etc. `NoNext`
restores the ordinary opaque/depth/light state. `is_invisible` and
`is_shadow_hide` gate all geometry; entry, death/sleep, rebirth and selected
capture states set the latter. Invincibility is not a special case.

**Port.** `ssb_game::shadow::build` retains the four-point/fixed-capacity source shape,
including floor-edge UV clipping and sloped Y interpolation. `scene::fighter_shadow`
selects the standing/projected source line and gates it on the portable source
`is_invisible`/`is_shadow_hide` fields; common entry/KO/sleep/rebirth
transitions maintain the latter, while capture/other visual systems can set it
directly. The pack builder explicitly extracts the source
frame, pre-baking a 32×32 mirrored period and marking it with a semantic
texture role. `meshdraw::draw_fighter_shadow` maps source state to the GE:
linear filtering, repeat address, Modulate RGBA, `SrcAlpha/OneMinusSrcAlpha`,
depth test on/depth write off, alpha `> 0x0F`, culling and lighting off. It
copies the fixed transient vertices into `sceGuGetMemory` and invalidates
`DrawState` afterward, so raw state cannot leak into subsequent meshes.

Stage geometry draws first, then each shadow, then weapons/fighters. Current
Training supports fixed static map lines; the source's wall-occlusion gate and
team-colour match option need the later moving-map/full-match systems. This is
an explicit scope boundary, not a substitute shadow design.

**Verification.** Host tests cover source half-width, floor-edge clipping,
ascending and descending sloped bends, altitude invariance, lifecycle gates,
no-floor reset and independent fighters; the pack role round-trips. `romtool
pack` rebuilt the local ignored pack from the verified USA ROM (1 extra
semantic shadow texture). Both PSP release applications build. The existing
13-fighter deterministic matrix is zero-diff, and the PSP release build plus
PPSSPPHeadless software capture completed using
`regression_capture_shadows`; its deterministic golden is
`tests/golden/f1-training-shadows.png` (SHA-256
`61e814d8b2624c12dd9dbcef75cbfdf0e06b5d647b9ea7d0453c6519d762c06e`).
