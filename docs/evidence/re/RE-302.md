# RE-302 — Fighter floor shadows

Status: COMPLETE for the current fighter-runtime scope
Topics: fighter, rendering, texture, collision, psp-ge, visual-regression
Relevant files: `refs/ssb-decomp-re/src/ft/ftshadow.c`,
`refs/ssb-decomp-re/src/ft/ftmanager.c`,
`refs/ssb-decomp-re/src/ft/ftcommon/{ftcommonentry,ftcommondead,ftcommonrebirth}.c`,
`refs/ssb-decomp-re/src/relocData/84_EFCommonEffects2.c`,
`crates/ssb-game/src/shadow.rs`, `psp-runtime/src/{scene,meshdraw}.rs`,
`tools/romtool/src/main.rs`

**Source behaviour.** `ftManagerMakeFighter` creates one `nGCCommonKindShadow`
GObj per non-demo fighter unless its descriptor opts out. Its display callback
is on link 13. `ftShadowProcDisplay` loads the first 128 bytes of file 84's
`dEFCommonEffects2_Shadow_TextureImage` at `0x3A68` as a 16×16 I4 texture,
with mirror+wrap on both axes. It derives the horizontal half-width directly
from `FTAttributes::shadow_size` (200 for the normal playable roster, 350 for
Donkey/Giant Donkey, 800 for Boss); it neither scales nor fades by altitude.

Grounded fighters use `coll_data.floor_line_id`; airborne fighters call
`mpCollisionCheckProjectFloor` down from the root. After the source's wall
occlusion guard, the code clips `center ± shadow_size` to the selected floor
line and follows its polyline through at most two internal vertices. The
result is four, six, or eight vertices at Z ±200 with interpolated floor Y;
the vertex texture coordinates span 0..1984 S10.5 units (62 texels), but
`dFTShadowNoPrevLinkDL`'s `gsSPTexture(0x8000, 0x8000, ...)` halves them, so
each axis samples 31 tile texels: one mirrored 16-texel period, a single
blob centred on the strip. (This record first called the unscaled 62-texel
span the intended "tiled/mirrored pattern"; that was wrong, and the port drew
a 2x2 grid of four blobs per fighter. Corrected below.) The strip still
follows the floor line, which is why an ellipse/quad would be incorrect on
stage edges or slopes.

`dFTShadowNoPrevLinkDL` supplies the 0.5 texture scale, `G_RM_AA_XLU_SURF`,
`G_CC_MODULATEIA_PRIM`, threshold alpha comparison against blend alpha 0x0F,
no lighting/shading/culling, and an I4 texture. Primitive colour is default
black `(0,0,0,0xA0)` or, in a team battle without `is_not_teamshadows` (the
1P Game sets it, `sc1pmanager.c`), team red/blue/green `(0x80,0,0,0xB4)` etc.
A grounded fighter on the rebirth halo (`floor_line_id == -2`) draws none.
The wall guard hides the shadow when a left or right wall line crosses the
drop from the fighter (to `y - 65536`) above its floor. `NoNext`
restores the ordinary opaque/depth/light state. `is_invisible` and
`is_shadow_hide` gate all geometry; entry, death/sleep, rebirth and selected
capture states set the latter. Invincibility is not a special case.

**Port.** `ssb_game::shadow::build` retains the four-point/fixed-capacity source shape,
including floor-edge UV clipping and sloped Y interpolation. `shadow::fighter_shadow`
selects the standing/projected source line on the live map surfaces (moving
groups included), applies the `-2` and wall gates and the portable source
`is_invisible`/`is_shadow_hide` fields; `shadow::color` picks the primitive
colour; common entry/KO/sleep/rebirth
transitions maintain the latter, while capture/other visual systems can set it
directly. The pack builder explicitly extracts the source
frame, pre-baking a 32×32 mirrored period and marking it with a semantic
texture role. `meshdraw::draw_fighter_shadow` maps source state to the GE:
linear filtering, repeat address, Modulate RGBA, `SrcAlpha/OneMinusSrcAlpha`,
depth test off/depth write off (corrected by RE-514: the source clears `G_ZBUFFER`), alpha `> 0x0F`, culling and lighting off. It
copies the fixed transient vertices into `sceGuGetMemory` and invalidates
`DrawState` afterward, so raw state cannot leak into subsequent meshes. Its
texture coordinates are `shadow::tile_texel` (the source's `TEX_SCALE` 0.5)
over the 32-texel period, plus the linear filter's half-texel offset
(RE-304).

Stage geometry draws first, then each shadow, then weapons/fighters.

**Four-blob correction (N64 capture).** Warp-booted decomp builds (Training
and a VS team battle, captured with headless Mupen64Plus/Rice with and
without `ftShadowProcDisplay`'s body) show exactly one ellipse under each
fighter on the Kongo Jungle slope, Dream Land's main floor and a Dream Land
platform, tinted red for a red-team fighter. The PSP build before the fix,
diffed against the same scene with shadows off, showed a 2x2 blob grid per
fighter. A host test models the RDP mirror addressing and fails without the
0.5 scale.

**Verification.** Host tests cover source half-width, floor-edge clipping,
ascending and descending sloped bends, altitude invariance, lifecycle gates,
no-floor reset, independent fighters, the one-blob texture scale, team
colours, the `-2` and wall gates and moving floors; the pack role round-trips. `romtool
pack` rebuilt the local ignored pack from the verified USA ROM (1 extra
semantic shadow texture). Both PSP release applications build. The existing
13-fighter deterministic matrix is zero-diff, and the PSP release build plus
PPSSPPHeadless software capture completed using
`regression_capture_shadows`; its deterministic golden is
`tests/golden/f1-training-shadows.png` (SHA-256
`61e814d8b2624c12dd9dbcef75cbfdf0e06b5d647b9ea7d0453c6519d762c06e`).

**Physical smoke.** A connected PSPLink device loaded the current
`regression_capture_shadows` PRX against the current pack. After ten seconds
`exlist` was empty and `main_thread` remained live; its native 480×272 BMP
capture (SHA-256 `e02078d382b9ee747fa843a2fd1ecf4a25c1dcf9aba15b4ddd12d542dfc7c5a4`,
kept under ignored `target/`) visibly shows the two-Mario Dream Land case,
with one grounded and one airborne. The prior Memory Stick pack was backed up
and restored after the smoke test.
