# RE-544 — Fighter attribute tables from the ROM: the hurtbox offset, US Luigi's torso box and Master Hand's hidden part

Status: COMPLETE (decomp source and US ROM SHA-1 e2929e10 through `crates/ssb-tablegen`; host tests; no hardware run)
Topics: tablegen, hurtbox, modelpart, fighter, d048
Relevant files: `crates/ssb-tablegen/src/hurtbox.rs`, `crates/ssb-tablegen/src/model_parts.rs`, `crates/ssb-game/src/hurtbox.rs`, `crates/ssb-game/src/modelpart.rs`

## Question

[D-048](../../decisions/D-048.md) moves the fighters' committed attribute
tables to build-time generation from each fighter's `*Main` file. The
committed values were transcribed from `relocData/*Main.c`. Three things
needed checking before the ROM could replace them:

1. Where `FTAttributes::damage_coll_descs` lies. The struct gives it no
   offset comment.
2. Whether the transcriptions equal the US ROM, entry for entry.
3. What to do with Master Hand, whose `hiddenparts` holds a root joint the
   port's filter keeps.

## Evidence

- **The hurtbox array is at `FTAttributes + 0x104`.** `setup_parts` is at
  0x29C ([RE-425](RE-425.md)). Before it come `hit_detect_range` (one
  `Vec3f`, 0x290) and eleven 36-byte `FTDamageCollDesc` rows, which puts
  the array at 0x290 - 11 × 36 = 0x104. The ROM bears this out: in file
  203 at 0x428 + 0x104, Mario's rows read the decompilation's US rows
  exactly, ending with a `joint_id` -1 row. Bit by bit, every fighter's
  generated rows equal the committed rows except the one below.
- **Row count.** `ftParamResetFighterDamageCollsAll` skips a row whose
  `joint_id` is -1 and does not stop the loop. In all 27 `FTKind`s every
  used row comes before the first -1, so the generator emits the rows up
  to that point. It fails the build if a used row follows a -1 row.
- **US Luigi's torso box is 160 tall, not 200.** `221_LuigiMain.c`'s
  `damage_coll_descs[1]` is `{ 155, 200, 150 }` under `REGION_JP` and
  `{ 155, 160, 150 }` otherwise. The US ROM holds 160. The committed
  `LUIGI` table had the JP 200, live half-height 100 instead of 80, even
  though [RE-458](RE-458.md) already gave US 160 and its Polygon Luigi
  comment said so. Polygon Luigi (`223_NLuigiMain.c`) keeps 200 in the US
  ROM. No other row of any fighter differs. The base-fighter sharing the
  committed code assumed (Polygon Fox equals Fox, and so on) holds in the
  ROM.
- **Hidden parts.** The generated `hiddenparts` (counts from each
  `d<Name>Main_hiddenparts[N]`), texture parts and Falcon Dive's capture
  offsets (`dCaptainMainMotion_0x0000`, file 235 + 0) equal the committed
  tables for all 27 `FTKind`s. `dBossMain_hiddenparts` is
  `{2,0},{1,0},{3,2},{5,4}`: root 5 passes the 4..37 filter. The port gives
  Master Hand no model-part state (`modelpart::joint_masks` is `None`, so
  `apply_hidden_parts` never runs), and the committed table was empty. The
  generator emits Master Hand's row empty (`NO_HIDDEN_PARTS`) so that
  nothing changes.

## Outcome

- `ssb-tablegen` generates `HIDDEN_PARTS`, `TEXTURE_PARTS`,
  `DAMAGE_COLLS` and `CAPTURE_OFFSETS`. Only offsets, row sizes, the
  hidden-part counts and Master Hand's exclusion are committed.
- US Luigi's torso hurtbox is now the ROM's 160 (half 80). This is a
  gameplay change. The box is centred on joint 12's y = 81 and now spans
  1..161 instead of -19..181 in joint space. A hit that only reached the
  20 units the old box had beyond either end now tests the next box in
  order, or misses. Golden scenes where Luigi is hit there can change.
