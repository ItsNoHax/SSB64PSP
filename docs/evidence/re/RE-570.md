# RE-570 — Battle scene light for list-coloured lit stage prims; N64 warp harness cause

Status: IMPLEMENTED (decomp source, N64 RDRAM register trace, N64 framebuffer, PPSSPP goldens; physical PSP pending)
Topics: rendering, lighting, stage, n64-trace, harness
Relevant files: `psp-game/src/main.rs`, `psp-asset-viewer/src/main.rs`, `crates/ssb-rom/src/anim_color.rs` (`light_scope`), `psp-runtime/src/meshdraw.rs` (`set_scene_light`)

## Question

Which light colours and direction do lit stage and effect prims see on the N64 in battle?

## Finding

- `sc1PGameFuncLights`, `scVSBattleFuncLights`, `sc1PTrainingModeFuncLights`, `sc1PBonusStageFuncLights`: `G_LIGHTING` plus `ftDisplayLightsDrawReflect(gMPCollisionLightAngleX/Y)`; it writes only `l.dir` (col stale, zero in traces).
- Colours come only from the display lists' `G_MW_LIGHTCOL` writes.
- F3DEX2 DMEM: LIGHT_1 0x220, LIGHT_2 0x238; `G_MOVEMEM` idx 10 writes 0x1F0+o; `G_MW_NUMLIGHT` n*24 at 0x1DC.
- Meta Crystal (VS, gkind 13, t400): 242 lit verts see LIGHT_1 ffffff, LIGHT_2 4c4c4c, dir (-30,-30), 1 light; four lists write both colours themselves.
- Board the Platforms Mario (t300): lit loads see b3b3b3 / 808080, dir (20,45), equal to the pack literals.
- Rebirth halo (t321): ffffff / b3b3b3 or cccccc, stage dir.
- Before: battle called `set_stage_light`, so these prims took the (20,45)/0.35 bake and ignored colours.
- Now: `set_scene_light` in battle and the asset viewer; a lit prim whose list writes both colours is lit on CPU (RE-514 model) with those colours under the stage direction.
- Second reading, N64 framebuffer: Board the Platforms beam front face N64 (226,0,39), PSP before (180,0,32), after (221,0,39); truss peak N64 (103..108,4,32), after (102,6,32); Rebirth halo dY -15.1 -> -4.3.
- Census (pack v134): all-prims-coloured: Sector 109, Metal 117, PupupuBeta 101/102, Bonus 124-149, effect 85, Arwing 161. Lit without colour writes (bake kept, open): Yoster 111 (1), Last 114 (7), YosterSmall 118 (1).

## Hyrule correction

Batch 42's Hyrule floor gap (RE-065, RE-529) was a misaligned region script that ignored the N64's 10 px border. Aligned, Hyrule is -1..-3 luma; every Hyrule stage vertex load is unlit (RE-423).

## Harness fact

- Patched decomp builds (warp patch) shift `.data/.bss` by +0x180 (`gSCManagerSceneData` 0x800a4ad0 -> 0x800a4c50; `gSCManagerBattleState` 0x800a50e8 -> 0x800a5268); a script polling stock addresses never saw the scene start.
- `~/ppsspp-test/b42/train_fb.py` now reads symbols from `<rom>.map`. Tools live outside the repo.
- Framebuffer dump: little-endian u16, halfword pairs swapped (addr^2), RGBA5551.
