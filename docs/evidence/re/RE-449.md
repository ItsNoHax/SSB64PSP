## Integration and boundaries

`Session::configure_fighter` attaches an event queue. VS and Training retain
hit provenance without allocating that queue. `collect_fighter` drains it
after callbacks and samples the fighter's current percent. `collect_fall`
collects first, then consumes `dead.scored` once with the actual stage's
team order and last-hit record. The host must collect before replacement,
rebirth/result reads and `finish_battle`; do not also report the same hit
through the older manual `Session::damage` boundary.

Rebirth resets fighter stat fields but retains undrained callbacks and the
campaign attachment. It also preserves `spgame_rule` and team bounds,
which the prior portable reset lost. Shared fighter weapons now pass their
actual owner to combat instead of using the ownerless low-level wrapper.

The PSP application resets the shared sequence when it creates a battle.
It still does not create the campaign frontend/session or invoke the new
collectors. Authored frontend draws, campaign orchestration, bonus-stage
controllers, Master Hand, ending and persistence remain in `TODO.md`.
This batch accounts for the damage actually applied by existing portable
callbacks; it does not establish full runtime equivalence of every move.
