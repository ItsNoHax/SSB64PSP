## Vertex replay (`VertexTape`)

- A frozen model's expanded vertices stay in the per-list VRAM region of `gu::ge_vertices`. Region reset per `sceGuStart`; with double-buffered lists, list N is intact while N+1 is built.
- Replay emits the same GE commands, block allocations and addresses; skips `light_prepass`, skin compute and writeback, guard clip, corner writes.
- Replay needs all of:
  - tape valid; `tape.list + 1` == current list serial; region `next` == `tape.start`;
  - key hash equal: base and posed matrices, look, object, `DrawState` light, fog, camera, clip, caller key (object, costume, shade, kind).
- Spoilers (never replay): VRAM spill; guard clip `Some`; effect colours; per-corner float UV; skinned vertices submitted directly; `color_override`; `mat_anim`, effect, `only_node`, hidden, `node_override`; second object under one arm.
- `finish_tape` validates end offset and spill count. Only `campaign_screen` frozen models arm a tape.
- Output unchanged: replayed bytes are the previous list's bytes for identical inputs.

## Code placement sensitivity

Same logic, no tape in vs4, moved vs4 by code layout alone:

| Variant | vs4 busy (ms) |
|---|---:|
| base | 19.75 / 19.74 |
| state in `DrawState`, inline hash (+31 KB .text) | 20.08 |
| statics, cold `open_tape` | 19.83 |
| const-generic instances, `inline(always)` | 20.66 / 20.67 |
| shipped: single cold `taped_corners` / `replay_corners` | 19.64 / 19.64 |

- Rule: leave hot `meshdraw` function bodies unchanged; put new branches in `#[cold] #[inline(never)]` helpers; keep state in statics.
- Probably explains the unattributed +0.73 ms of RE-574 (not proven).
