# RE-321 — RDP two-tile fractional blend (`SetLFrac` + `TextureIDNext`) on the GE

Status: COMPLETE (PPSSPP exact-formula check, N64 reference, PSP-2000 timing and capture)
Topics: material, animation, texture, combiner, psp-ge, pack, stage, visual-regression, hardware
Relevant files: `crates/ssb-rom/src/{lod_blend,mobj,mesh,pack,skeleton}.rs`,
`tools/romtool/src/main.rs` (`lod_blend_desc`), `psp-runtime/src/meshdraw.rs`
(`draw_lod_blend_pass`), `crates/ssb-capture/src/lib.rs`

**Question.** RE-086 and RE-301 left `SetLFrac`/`TextureIDNext` as a
documented limitation: the RDP blends two tiles per pixel and the GE samples
one texture per draw. Which materials use it, what exactly do they compute,
and can a multipass GE lowering reproduce it?

## Source behaviour

`gcPlayMObjMatAnim` writes `SetLFrac` to `mobj->lfrac` and `TextureIDNext` to
`mobj->texture_id_next` (`objanim.c:1304-1342`). `lfrac` starts at
`prim_l / 255.0F` (`objman.c:1321`). `gcDrawMObjForDObj`
(`objdisplay.c:1218-1330`) then:

- under `PRIMCOLOR | FRAC | 0x8` emits `gDPSetPrimColor(prim_m, lfrac *
  255.0F, primcolor)`. The second argument is the `PRIM_LOD_FRAC` byte; gbi's
  `_SHIFTL` truncates the single-precision product to `u32` and keeps eight
  bits. Only `MOBJ_FLAG_FRAC` re-derives both texture ids from `lfrac`; no
  `MObjSub` sets it (RE-194).
- under `FRAC | SPLIT` names `sprites[texture_id_next]` and, with
  `FRAC | ALPHA`, block-loads it through tile 6;
- under `0x40` sets tile 1's window from `ScrU`/`ScrV`
  (`gDPSetTileSize(1, ...)`), independently of tile 0's `TraU`/`TraV`.

`LOD_FRAC` does not participate: SSB64 never enables RDP LOD (RE-127). The
fraction reaches the combiner only as `PRIM_LOD_FRAC`.

`romtool stages` replays 61 stage script attachments; exactly two drive
`SetLFrac`/`TextureIDNext`, both on Dream Land's render layer 2 (file 104,
graph `0x2450`). The mesh converter's detector fires on exactly these two
primitives archive-wide (`romtool pack`: "2 of 2 classified two-tile blend
primitive(s)").

|---|---|---|---|---:|---|---|
| 2 | `0x2540` | `0x1F78` (flags `0x6B`) | `0x22C8` | 6 | CI4, TMEM 0, mirror+clamp S, clamp T, window 128x128 | CI4, TMEM 64, clamp S/T, same static window |
| 3 | `0x2620` | `0x1FF0` (flags `0x6B`) | `0x2380` | 6 | CI4, TMEM 0, clamp S/T, window 32x64 | same shape as tile 0 |

Both are horizontal octagons at `y = 0`: the two ponds on the foreground
grass. `0x6B` is `ALPHA | SPLIT | 0x8 | 0x20 | 0x40`.

- **Images.** `sprites[0]` = file 103 `0x1BE0` (32x32 CI4, every texel
  opaque, teal-to-white water); `sprites[1]` = file 103 `0x1E10` (sparkle
  pattern, 556 of 1024 texels on index 15, alpha 0, RGB 148/180/246). One
  16-entry TLUT (file 103 `0x1BB8`), bank 0 on both tiles.
- **Combiner** (`hi 0x00272C04`, `lo 0x1F0C93FF`, two-cycle):
  cycle 1 RGB and alpha `(TEXEL1 - TEXEL0) * PRIM_LOD_FRAC + TEXEL0`;
  cycle 2 RGB `COMBINED * SHADE`, alpha `COMBINED * PRIM` (`PRIM` = `FFFFFFFF`).
- **Render mode** `0x0C193048`: `G_RM_PASS` then `G_RM_AA_TEX_EDGE2`
  without Z (`IN·A_IN + MEM·A_MEM`, no `FORCE_BL`): an opaque cutout, not a
  translucent surface. `G_AC_THRESHOLD` against blend alpha 0. No depth test
  or write.
- **Fraction.** Initial `prim_l` `0x73` gives 114. Both scripts sway `lfrac`
  between 0.45 and 0.60 (`PRIM_LOD_FRAC` 114..153) with a 1080-tick period;
  `TextureIDCurrent` stays 0 and `TextureIDNext` 1. `ScrV` scrolls tile 1 a
  full period each cycle and `ScrU` sways differently from `TraU`, so the
  highlight moves across the water independently.

Out of scope: nine other `0x6B` `MObjSub`s (file 114 `0x9818`..`0x9B60`,
file 157 `0x8D8`) sit in graphs that are not stage layers and have no
`SetLFrac` script; the detector requires an animated `MObj`, so they, and
RE-079's static `PRIM_LOD_FRAC` combiners, keep their existing path.

## Algebra

Per channel, with `f` = `PRIM_LOD_FRAC`:

```text
RDP:  C = (T0 + (T1 - T0)·f/256) · S           A = (T0a + (T1a - T0a)·f/256) · PRIMa
GE :  pass 1  T0·S, replacing the framebuffer
      pass 2  T1·S, blend Add(Fix fa, Fix fb), fa = round(f·255/256), fb = 255 - fa
```

`SHADE` distributes over the lerp, so each pass modulates its own texel. The
decomposition is exact only when pass 1 replaces the pixel and the alpha gate
cannot tell `T0a` from the blended alpha. The packer (`lod_blend_desc`)
enforces both and otherwise keeps the single-texture path:

- no GE blending (a translucent material with a classified alpha formula
  declines);
- the gate is off, or a zero threshold with `PRIMa = 255` and every
  `TextureIDCurrent` image opaque: blended alpha is then at least
  `1 - 255/256`, which never fails, and pass 1's alpha is 255;
- no `PaletteID` track and no texgen.

`TEXEL1` images convert through the ordinary texture pipeline shaped by tile
1's own `G_SETTILE` (so node 2's `TEXEL1` has no S mirror), under the opaque
alpha policy: the RDP interpolates `TEXEL1`'s colour even where its alpha is
zero. Pass 2 re-bases the packed UVs onto tile 1's live window
(`MaterialAnimator::resolved_lod_blend`), which requires tile 1 to share tile
0's static window, shift and clamp axes; the converter checks all three.

Both Dream Land primitives pass: **2 exact, 0 approximate.** Cycle 2's alpha
never reads the shade, so the vertices carry `PRIMa` (the source vertex alpha
is 0, which is why the ponds rendered nothing before: `Modulate` plus the
`alpha > 0` cutout discarded every pixel).

## Runtime

- `flags::LOD_BLEND` (bit 20) plus a `LodBlendDesc` table (52 bytes per
  record, keyed by `MatAnimDesc`). Pack v33; the header grows to 92 bytes.
  Primitives without the flag never look anything up.
- `draw_mesh` keeps its one vertex submission and `draw_lod_blend_pass`
  redraws it: texture and mapping through the normal cache, alpha test off,
  `Fix`/`Fix` blend, depth writes masked, depth test and function unchanged
  (identical vertices give identical depth, and `GreaterOrEqual` accepts
  equal depth whether or not pass 1 wrote it). `last_flags` is cleared so the
  next primitive re-issues blend, alpha test and depth mask. `frac == 0`
  skips the pass.
- Fraction, `TextureIDNext` and tile 1's window resolve from the same joint
  in the same frame as `TextureIDCurrent`, so no pair is a tick apart.

- Host tests: 6 `lod_blend` (frac 0, frac 255, midpoint, all fractions and
  shades within 2 steps, weights, `prim_l` round trip), 4 `mesh` (the water
  list classified with tile 1's shape, per-tile palette banks, `PRIMa`
  alpha, five decline cases), 3 `skeleton` (animated fraction with
  current/next switching on one tick, tile-1 scroll, no record), 3 `pack`
  (round trip after every table, zero cost without records, flag needs its
  record).

  (+24,080 bytes over v32: four `TEXEL1` textures, two records, header).
  A pack with only the mesh changes differed from v32 in exactly the 16
  water vertex-alpha bytes, proving the tile-builder refactor inert.
- **Exact-formula capture.** New scene `dream_land_water` (object view of
  graph `0x2450`, orbit 60° down). Diagnostic builds

  `T1·S`. Over all 21,377 pond pixels where they differ, the two-pass capture

## Cost

One extra draw per affected primitive per frame whenever `f > 0` (always,
here: `f >= 114`): +2 draws on Dream Land. No extra vertex memory (pass 2
reuses the same submission). Runtime memory: the pack's +24,080 bytes; one
`Option` field in `DrawState`.

## Limits

- `MOBJ_FLAG_FRAC`, palette animation, texgen and a GE-blended material
  decline to the single-texture path; none occurs in the ROM.
- GE rounding differs from the RDP by at most one step per channel (two with
  a non-white shade; host-tested).
- The RDP's coverage-based anti-aliasing on these `TEX_EDGE` pixels is not
  modelled, as for every other cutout (RE-069).
- Tile 1's texture carries the same filter compensation coverage as tile 0;
  its window scrolls, so the compensation is a static approximation, as for
  every UV-animated material.
