# RE-327 — Recorded texture tiles, `unk10 == 1`, and effect material clocks

Status: COMPLETE (decomp comparison, ROM census and texel check, host tests, PSP builds, PPSSPP smoke; no physical-PSP capture)
Topics: material, animation, texture, uv, pack, effects, visual-regression
Relevant files: `crates/ssb-rom/src/mobj.rs`, `crates/ssb-rom/src/pack.rs`, `crates/ssb-rom/src/skeleton.rs`, `tools/romtool/src/main.rs`, `tools/romtool/src/matcolors.rs`, `tools/romtool/src/matsample.rs`, `psp-runtime/src/meshdraw.rs`, `psp-asset-viewer/src/main.rs`

**Question.** RE-326 left the texel check choosing a render format and mirror layout by best match, omitted `MObjSub.unk10 == 1`, and read a manager effect's UV window from the pack-lifetime stage player.

## Source and ROM evidence

- `ssb-decomp-re/src/sys/objdisplay.c:1173-1178` halves `scau` and transforms `trau` and `scrollu` using `unk24`, `unk28` and `unk44` before any tile-size or `gSPTexture` command. The later commands use those values at lines 1353-1420.
- `romtool mobj --expect` combined paired table chains with decomp-identified offsets and found 21 `MObjSub`s with `unk10 == 1`; none has a tile-window or `gSPTexture` flag. The table chains alone find 16, also with no such flag. Thus the branch needs a host test to exercise it and does not change a current ROM draw.
- A render tile's `G_SETTILE` format, source row width, narrowed period and mirror bits are present in `mesh::TextureRef` during conversion. The pack had discarded them. The sprite comparison therefore could only search candidate formats and layouts.

## Change

- Pack v36 records the render tile in each ordinary `TextureDesc` and the three halving inputs in each `MatAnimDesc`. The writer sets tile metadata for static, animated and second-pass textures. The texel check reads this metadata directly, including the source row stride.
- Static `MObj` reading and live `MaterialUv` resolution apply the decomp's halving before deriving the U window or scale. Animation tracks keep the raw fields written by scripts.
- A selected manager effect starts and ticks its own `EffectMaterialAnimator`. Image, palette, tile-0 UV, second-pass blend and colour all resolve from that player. An unset effect track keeps its packed rest state; it cannot fall back to an advanced stage player. The viewer freezes this player with the other simulation clocks during deterministic captures.

## Verification

- `romtool matcolors --pack`: 103 entries, 600 frames each; all 15 tracks and four resolvers exact. All 145 bound textures match `sprites[]` through their recorded tile, including 79 read through a mirrored or repeated period; all 33 static CLUTs match. Tile-0 (114,966 moving samples) and tile-1 (19,200 samples) have zero samples beyond 1/64 texel. The effect and stage players agree when started together.
- The v36 pack rebuilt to `target/re327.pak` is byte-identical to `assets/generated/ssb64.pak`: 22,247,328 bytes, SHA-256 `010291620b7ef25fb207ec7e658d03df13b55b126fcdb2e32679e6b6d1abbc58`.
- Host tests cover the halving formula in the static reader, independent RDP check and live resolver. A late-spawn test keeps the stage player's UV ahead while the effect UV restarts, then verifies the effect advances on its own ticks.
- Workspace tests, both PSP release builds and a PPSSPP Final Destination golden smoke pass. Physical PSP was not tested in this batch.

## Limit

No reachable ROM material currently combines `unk10 == 1` with a window or texture-scale flag. No manager-effect entry moves its UV window over the diagnostic's 600 frames, so the effect UV clock regression uses a synthetic script. The runtime behavior is implemented, but neither case can be demonstrated from a current ROM capture.
