# RE-505 — `gSYSinTable` is ROM data, not a formula; the third trig family

Status: COMPLETE (host and PPSSPP; not compared with an N64 capture; not hardware proof)
Topics: determinism, reverse-engineering
Relevant files: `crates/ssb-tablegen/src/sin_table.rs`, `crates/ssb-engine/build.rs`, `crates/ssb-engine/src/math.rs`, `crates/ssb-game/src/camera.rs`, `crates/ssb-game/src/spgame/staffroll.rs`

## Question

Does the port's camera projection use the same cotangent as the original's `syMatrixPerspFastF`?

## Findings

- `gSYSinTable` is a `u16[2048]` at ROM 0x3C550 (the bytes the audio
  section's `n_env` also reads): a half wave over [0, pi) scaled to 32768,
  `[1024]` = 0x8000, `[2047]` = 0.
- It is not a formula: `sin(i*pi/2048)*32768` misses 1510 of 2048 entries
  rounded and 1018 floored. It is therefore generated from the ROM at build
  time by `ssb-tablegen` ([D-048](../../decisions/D-048.md)), and only its
  layout is committed.
- `syGetSinCosUShort` macro: `id = (s32)(angle*(2048/PI32)) & 0xFFF`; sin is
  the table at `id & 0x7FF`, negated when bit 0x800 is set; cos is the same
  at `id + 0x400`. Ported as `sy_sin_cos_ushort`.
- `syMatrixPerspFastF` takes `cot = table cos / table sin` of
  `fovy*0.008726646`. The battle camera's cotangent is therefore quantised to
  4096 steps a turn (0.088 degrees); fovy 38 uses index 216. It differs from
  exact `1/tan` by at most 0.2%.
- `Camera::project` and the staffroll `camera_matrix` now use `sy_persp_cot`.
  Two goldens changed: `f1-training-piranha-plant` (1260 px; the magnifier
  bubble radius, through the float `magnify_scale`) and
  `f1-training-interface-restored` (8 px, tag position).

## Limits

The r4300 oracle has no `PerspFast` entry, so the check is table == ROM bytes
plus macro vectors, not a run of the original code. The display-matrix
chains (`from_trs`, item root) and the GU `sceGumPerspective` fovy still use
exact trigonometry (PLAN.md).
