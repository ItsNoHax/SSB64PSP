# RE-536 — Per-port fighter effects, reflector tables, Charge Shot spin start, and the entry-effect eject rule

Status: COMPLETE (PPSSPP and N64 status timelines; no N64 pixel captures; pack v118)
Topics: effects, fighters, n64-trace, kirby, memory
Relevant files: `psp-game/src/main.rs`, `crates/ssb-game/src/status.rs`, `crates/ssb-game/src/kirby_copy.rs`, `crates/ssb-game/src/samus.rs`, `crates/ssb-rom/src/effect.rs`, `crates/ssb-rom/tests/fox_reflector_tables.rs`

## Question

How does the original game draw every fighter's special effects, and what must the port do so CPU and other-port fighters show them as the player does?

## Findings

1. Per-owner architecture. `EffectVisuals` holds `ports: Vec<PortFx>` (one `FxSlot` each for Magnet, Sing, Spin Attack, Falcon Punch, Falcon Kick, plus `ReflectorFx`) and `weapons: Vec<WeaponFx>`. Slots index `scenes_ref` order, not `fighter.port`. `FxPlayers` (StageAnimator plus EffectMaterialAnimator, about 27 KB) are boxed lazily while the effect lives (RE-475 headroom). A slot whose owner has no effect is cleared on the same sync; the `PortFx` vector is rebuilt with each `EffectVisuals`, so a scene end drops every slot. `draw_fighter_effects` runs once per port from the Effects15 pass (Charge Shot for Samus and the Kirby copy, held egg, Magnet, Sing, Spin Attack, reflector hexagon, Falcon Punch on joint 16 or 30 for a Kirby copy, Falcon Kick).
2. Draw order. The N64 puts effects on DL link 15 in GObj creation order, same-frame makers in ascending port order. The port draws per type, then per port: an approximation that can differ only where alpha effects overlap.
3. Assets for CPU-only fighters load: `Session::enter` builds `battle_roots` from the whole roster. `sync` runs in `Screen::Training`, which covers opening, demo and VS; Results draws no battle effects.
4. Reflector tables. `efManagerFoxReflectorSetAnimID` selects through `reflector.index` among Start, a 10-frame Loop, Hit and End, driven by Fox's flag2 = 4 protocol; `start_changed` plus one tick on SetAnimID. Ported exactly; `fox_reflector_tables.rs` replays the N64 trace.
5. Weapon visuals are keyed by pool slot (`WeaponPool::animated()`), standing in for the weapon GObj. `MAX_WEAPONS` is 32, equal to `WEAPON_ALLOC_MAX`; `MAX_JOLT_VISUALS` is gone. The golden peak stayed at 20.43 MB (RE-475 budget).
6. Hitlag. The Spin Attack pauses (`ftParamProcPauseEffect`). Falcon Punch and reflector effect clocks keep ticking: their makers set no `proc_lagstart`.
7. Charge Shot spin. The N64 RDRAM trace shows rotate.z = -pi/10 on Loop frame 0, because `wpSamusChargeShotProcUpdate` runs in the make frame. The counter now starts at 1 on Loop entry (Samus and the Kirby copy). Effect: `f1-training-samus` changed by 1208 px, all inside x 572-621, y 310-361 (the shot); a build with only that line reverted differs by exactly those pixels.
8. Entry-effect eject rule. An `EFDesc` with flags 0x4 and no `EFFECT_FLAG_USERDATA` gets `efManagerNoStructProcUpdate` in `efManagerFuncRun`, whatever its `proc_update` says; that update ejects the effect when `GObj::anim_frame <= 0`, at the loop wrap (frame 120). Link's entry Wave and Beam lived forever on the PSP (their alpha column reappeared every 120 frames). `EntryVisual.ejected` now latches that; the other entry parts (pipe, barrel, capsule, egg, star, rays) end on the same frame as before.

## N64 method and evidence

Warp ROMs (decomp patched to boot a 4-fighter VS, controller 0 mirrored to ports 1-3, built with the mips shim, then the decomp restored; baserom SHA-1 e2929e10) give RDRAM traces. PSP tick = N64 el + 399; the press is at el 30; the N64 reads the release a frame late, so the PSP holds 41 (d), 31 (u), 61 (n, k) ticks. Scenes: `cpufx-d/u/n/k`.

The comparison is status timelines, not pixel captures. All four match: d Hold 44, Loop 33, End 71/74, Wait 84/89, Fall 91, Landing 99; u Link End 89, Yoshi Wait 101; n Samus Loop 45, Kirby Loop 49, Kirby End 91; k Loop 45. Differences are trace-sampling artefacts (a status's first frame shown with af 2; a duplicated frame at 72/73). Visual checks were 2x crops against N64 screenshots by eye.
