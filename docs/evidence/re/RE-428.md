## Questions and source

How does Sector Z's Arwing fly, fire and carry fighters (`grsector.c`)?

- `grSectorInitAll` builds the ship from Fox's entry-Arwing tree (file 161,
  `llFoxSpecial3EntryArwingDObjDesc` 0x2C30) with `grModelSetupGroundDObjs`
  and `dGRSectorArwingTransformKinds`: node 0 draws through
  `grSectorArwingLaser3DFuncMatrix` (US kind 0x53 in
  `dLBCommonFuncMatrixList`), node 1 `TraRotRpyR`, nodes 2–10 `Tra`
  (2–5, 8, 10 add the 0x2C billboard), node 11 no matrix. The GObj draws on
  link 6.
- `MPGroundData::map_nodes` of `GRSectorMap` (file 262) lands on file 153
  + 0. The labels the controller adds to `map_head` (`llGRSectorMapArwing*`,
  and `llFoxSpecial3_1B34/1B84_AnimJoint`, despite their names) are file
  153 offsets; only `llFoxSpecial3_2E74/2EB4_AnimJoint` are file 161's
  (`map_file`). File 153 holds eight `GRSectorDesc`s whose node-0 and
  node-11 scripts open with `SetInterp` (opcode 13) and key the `TraI`
  track (bit 3), five pilot scripts, the muzzle scripts and the lasers'
  display list (0x1C50, textures in file 161).
- `gcPlayDObjAnimJoint` clamps `TraI` to [0, 1] and writes
  `syInterpCubic(aobj->interpolate, value)` to the translation
  (`src/sys/interp.c`): an arc-length fraction, found per segment from the
  keyframe table, then bisected against a Simpson-rule integral of each
  segment's speed quartic. The paths are Catmull-Rom (kind 3, tension 0.5)
  and, for pattern 4, a uniform B-spline (kind 2).
- The bisection's `do … while` compares the length left *after* taking the
  half it measured. A remaining length equal to that half exits at the
  midpoint. A uniform test segment hits it exactly; kept as is.
- `grSectorArwingPrepareLaserCount` returns 2 only for
  `syUtilsRandIntRange(3) >= 3`, which never happens: every volley is four
  shots. `grSectorArwingWeaponLaser3DMakeWeapon` passes an uninitialised up
  vector to `func_ovl2_80106730`; only node 11's path writes it, so the
  port passes +Y as the matrix function does.
- `grSectorArwingUpdateCollisions` calls `mpCollisionSetYakumonoPosID`
  twice when it turns the wing on, so the wing's first frame has no speed.
- Both lasers are `WEAPON_FLAG_PARENT_GROUND`: player 4, team 4, default
  handicap and staling. 2D: 16 damage, size 300, `map_coll` width 564,
  hops, reflects and is absorbed. 3D: 18 fire damage, passes shields,
  absorbed only; it bursts on the map within |z| < 1000 or on any hit into
  a 16-frame, radius-200 hitbox with a cleared attack record.

## Port

- `ssb_rom::interp` ports `interp.c` (all four kinds) with the source's
  operation order. `objanim::StageJoint` now stores `SetInterp`'s pointer
  and plays `TraI`.
- `ssb_rom::sector::Arwing` is the twelve-node runtime object inside
  `GroundObjects`: per-node scripts from either file, `anim_wait`/flags,
  path queries, and node 0's stored matrix. Pack v79 stores files 153 and
  161 whole under `AnimDesc::SECTOR` and the laser list keyed by
  (262, 0xBC). No layout change.
- `ssb_game::stage::sector` translates the controller: sleep/wait/patrol,
  type cycle, pilot windows, line toggles, hull swap, flare, volleys, both
  makers, wing group 1, and `root_matrix`. The runtime reaches it through
  `StageObjects::arwing` (`ArwingObject`).
- `WeaponPool` gains `Weapon::Laser` (`weapon/sector_weapon.rs`) with its
  own hit search (`laser_hit`): no owner credit, `can_shield` per kind,
  2D hop and reflection refaced by the Arwing's roll, 3D burst. Audio is
  not ported.

## N64 evidence

A temporary decomp patch (reverted; rebuilt and original ROM SHA-1
`e2929e10…`) booted Training on Sector Z, Mario against Mario (warp ROM
SHA-1 `89965c22…`). A Mupen64Plus script read `gGRCommonStruct.sector`
(0x801313F0) and `map_dobjs[0..1]` each frame for 9,500 frames. Mupen
stores RDRAM in native-endian words; the reader swaps each word. A
screenshot taken inside the frame callback consumes one frame, so samples
are compared by recorded frame number.

- Training starts in Wait; patterns start at frames 601 (0), 2271 (4,
  `target_x` 9000), 4080 (2) and 8032 (5), as the port's 600-frame wait
  predicts. Pattern 2 ends at 2,167 frames, when pilot 5 stops node 0.
- Node 0's translation, played from the pack, equals every traced frame
  of patterns 4, 2 and 5 to four decimals (749, 2,167 and 399 frames), and
  all 599 frames of pattern 0 in a first, screenshot-free run.
- Pattern 4 volleys four 2D shots at frames 2584, 2614, 2644 and 2674.
- At frames 5200–5260 the N64 shows the Arwing's wing entering the top
  right of Training's camera; the port's tick-1800 frame shows the same
  wing, shape and shading.

## Verification and limits

`packed_arwing_flies_the_sector_controller` runs the controller on the
pack for six minutes: the first pattern at frame 601, every fourth
pattern a background one, the wing on only for plane patterns and off at
every end, and the 2D volleys in pairs. `packed_arwing_paths_match_the_n64_trace`
pins six traced positions. Host tests cover the spline (including the
quirk), the descriptor reader, script lookup, laser facing and the burst.

New golden `f1-training-arwing` (`trainingsector` at tick 1800) is
identical twice. Seven `r2-stage-bonus2-*` goldens change (480–10,464
pixels at 2×): Board the Platforms' moving blocks also use `TraI` paths
and now move. With the `TraI` write disabled, `r2-stage-bonus2-pikachu`
matches its old golden. Those blocks were not compared with the N64.
The full 150-scene matrix ran twice: the seven bonus scenes changed, and
three VS time-up scenes timed out under 24-way load and match when rerun
three at a time.

- Workspace: **1,599 tests pass**, one thread with absolute SSB64_ROM.
- Pinned 1.98.0 Clippy (warnings denied), rustfmt and the gameplay/ROM
  no_std build pass.
- Both production PSP release builds pass; five existing viewer warnings.
- Production PPSSPP smoke: 20 s windowed run, no faults; no screenshot
  tool on this desktop.
- `run`: **28,696 code bytes**, **18,608 frame bytes**. Largest frame:
  `enter_training`, **166,536 bytes** (the Arwing in `GroundObjects`),
  below the 256 KiB main-thread stack. ELF total **3,481,012 bytes**.

Pack v79: **35,412,176 bytes**, SHA-256
`f0054b2d8d421194654d66be4c421059841a4d75a3e872ee21f58890c82b88ca`.

Not verified: the lasers' look (no traced volley crossed either camera),
the 3D patterns' orientation (`root_matrix` from node 11's path), pilot
manoeuvres and wing collision against the N64 frame by frame (the port's
RNG picks other patterns in Training), audio, and physical PSP.
