# RE-384 — The shield bubble in `psp-game`

Status: IMPLEMENTED (decomp source, ROM bytes, PPSSPPHeadless golden captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: shield, effect, asset-pipeline, rendering, visual-regression
Relevant files: `crates/ssb-rom/src/mesh.rs`, `tools/romtool/src/main.rs`, `crates/ssb-rom/src/pack.rs`, `psp-runtime/src/meshdraw.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `tests/golden/f1-training-shield.png`

## Question

RE-369 raised a live shield in Training but did not draw the bubble. How
does the original draw it, and in which colour?

## Source

- `efManagerShieldMakeEffect` makes `dEFManagerShieldEffectDesc`: file
  163's tree at 0x300 (`llFTManagerCommonShieldDObjDesc`) on display link
  15, the effect pass after the fighters. The root's `user_data` is the
  fighter's `YRotN` joint.
- The root is matrix kind 0x4F (79, `func_ovl0_800C994C`): the joint's
  whole matrix, which also sets `gGCScaleX`. The guard writes the shield
  size into the root scale, so the scale is the joint scale times the
  health-derived size (`combat::shield_transform`). The drawn node is kind
  0x2C (44), a camera-facing quad sized by that accumulated scale.
- `efManagerShieldProcDisplay` sets `G_SETPRIMCOLOR` and `G_SETENVCOLOR`
  from `dEFManagerShieldColors[id]`, both at alpha 0xC0, then draws the
  tree. PRIM is white for every row. ENV is red, green, blue and black for
  players 1–4 (CPU uses row 4), and light grey (0xC0) for the damage row.
- The tree's list sets the same PRIM and reads ENV in its combiner. Under
  the RDP reset seed, ENV was unknown, so the pack had declined the
  texture blend.
- `ftCommonGuardSetOffSetStatus` sets `is_damage_shield`, which selects
  the grey row. `efManagerShieldProcUpdate` clears it on the effect's next
  update, so the grey shows for one frame.

## Implementation

- `InitialMaterial` gains `env_color`, and `SHIELD_EXTERNAL` seeds the
  shield tree (163, 0x300) with player 1's ENV at alpha 0xC0. The prim now
  carries a `TEXTURE_BLEND` from ENV to white.
- Pack v60 (27,262,288 bytes) holds that seed; there is no layout change.
- `DrawState::color_override` replaces a prim's PRIM and ENV at draw
  time, so one packed mesh draws in each player's colour.
- `psp-game` draws the bubble for the player and the dummy while
  `guard.is_shield` is set. It places each mesh node at the shield
  transform's point for the node's rest translate, as a billboard sized by
  `MODEL_SCALE` times the shield scale times the node's rest scale.
  Yoshi is skipped; his egg shield is a different effect.

## Deviations

- The one-frame grey damage colour is not drawn.
- Yoshi's egg shield is not drawn.

## Verification

The rebaselined `f1-training-shield` golden shows a red, translucent
bubble around Mario's guard pose at the posed `YRotN`. It was identical in
both captures, and was the only golden that changed. RE-369's collision
centre (75, 255, 0) is unchanged.
