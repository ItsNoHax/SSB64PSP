# RE-383 — Link's Bomb in `psp-game`: the right attributes record and the held parent

Status: IMPLEMENTED (decomp source, ROM bytes, PPSSPPHeadless golden captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: item, asset-pipeline, rendering, visual-regression
Relevant files: `tools/romtool/src/main.rs`, `crates/ssb-rom/src/pack.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-training-link-bomb.png`

## Question

Which graph is Link's Bomb, and how does it draw loose and in the hand?

## Source

- `llLinkMainBombItemAttributes` is file 225 + 0x40. Its `data` is file
  353's three-node tree at 0x18D8, its `anim_joints` 353 + 0x1990 (a scale
  pulse for node 2), and it has no MObjSub or material table. Its flags
  word 0xB8000000 sets `is_display_xlu`, `is_display_colanim`,
  `is_give_hitlag` and the light weight. The decomp's split labels the data
  word `dLinkSpecial2_SpinAttackMatAnimJoint_MatAnimJoint_data_at_0x5E0`,
  but it resolves to 353 + 0x18D8.
- RE-382 read the Bomb from 225 + 0x0C. That is
  `llLinkMainSpinAttackWeaponAttributes`, whose `data` is file 324's
  spinning ring at 0x11908 (MObjSub 0x110A8, transform 0x11990, material
  0x11A40). That ring is what drew as the orange smear.
- `dItLinkBombItemDesc` gives every node `Tra`; `itLinkBombMakeItem` adds
  kind 46 to the root and node 1 only. So node 1, the bomb body, is a
  camera-facing quad sized by the root scale times its own. Node 2, the
  fuse spark, keeps plain `Tra`: no rotation or scale of its own, in the
  parent frame.
- The root's translate is the item position while loose.
  `itMainSetFighterHold` hangs a held item under a kind-82 parent (US,
  `func_ovl0_800C9F70`): the item joint's matrix with its scale divided
  out (`func_ovl0_800C9A38`), plus the shuffle offset. It then resets the
  item's DObj transforms to the desc. `itLinkBombExplodeWaitUpdateScale`
  writes the bloat to the child's scale while held and to the root's while
  loose.

## Implementation

- Pack v59 (27,262,288 bytes):
  - Item slot 1 is the Bomb's table (353 + 0x1990). The file is small, so
    there is no window.
  - The Spin Attack weapon graphic (324, 0x11908) is paired with its
    MObjSub table (0x110A8), named by its own record.
- `psp-game` draws node 1 as a billboard and node 2 as a plain quad. Both
  sit in the item joint's frame, scale divided out (`grab::held_root_axes`),
  while held, and at the item position in world axes while loose. Loose,
  the root takes `Item::scale` (the bloat).
- The capture scene `linkbomb` presses Down+B at tick 20 and freezes at
  tick 55, with the Bomb in Link's hand.

## Deviations

- The held bloat on the child's scale is not shown: the host records only
  the loose bloat (`Item::scale`), and the child's animation writes its
  scale each frame.
- The shuffle offset on the held parent is not applied.
- The colour animation (`is_display_colanim`, the critical flash) is not
  drawn.

## Verification

The `f1-training-link-bomb` golden shows the blue bomb with its highlight
and fuse cap at Link's raised hand, and was identical in both captures.
`tools/golden.sh verify --twice` matched all 93 scenes. Workspace tests
pass with an absolute `SSB64_ROM` and one test thread.
