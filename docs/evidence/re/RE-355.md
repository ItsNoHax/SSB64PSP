Status: IMPLEMENTED (decomp tables, host tests, pack v41 rebuilt from the ROM, both PSP builds, full PPSSPPHeadless golden matrix; no physical PSP)
Topics: animation, pack, status machine, combat, visual-regression
Relevant files: `tools/gen-anim-table.py`, `crates/ssb-rom/src/anim.rs`, `crates/ssb-rom/src/anim_table.rs`, `crates/ssb-rom/src/pack.rs`, `crates/ssb-game/src/status.rs`, `psp-runtime/src/scene.rs`, `tools/romtool/src/main.rs`, `tests/golden/f1-training-jab.png`, `tests/golden/r2-stage-bonus2-{samus,kirby}.png`

## Question

RE-351 left the damage statuses (`DamageHi1`…`DamageFlyRoll`, `DamageFall`)
and most fighters' normals on the Wait slot, so a landed hit was invisible
in captures. Which clip does each of those statuses play, per fighter?

## Source

`dFTCommonActionStatusDescs[status − 6].mflags.motion_id` names an
`FTCommonMotion`, and `dFT<Name>MotionDescs[motion_id]` names the figatree.
Both are the same pairing the reaction and cliff slots already use.

The generator's `motion_enum` was wrong from `nFTCommonMotionAttackAirStart`
on. `ftdef.h` spells `nFTCommonMotionAttackAirN = nFTCommonMotionAttackAirStart`
and `nFTCommonMotionAttackAirEnd = nFTCommonMotionAttackAirLw` (and the same
for `LandingAir`). The old regex read only numeric values, so the alias's
right-hand name was counted as a further enumerator, and every motion after
184 was shifted. `AttackAirN` resolved to `AttackAirF`, and `LandingAirF`
resolved to `Appear1`. No earlier slot used a motion that high, so the
regenerated table before the new slots is byte-identical. The parser now
follows C enumerator rules (a value is a number or an earlier name; otherwise
the previous value plus one).

## Implementation

- 53 shared slots after the cliff slots, for all twelve playable fighters:
  `DamageHi1`…`DamageFlyRoll`, `DamageFall`, `FallSpecial`,
  `LandingFallSpecial` (`SLOT_DAMAGE_HI1` = 487), then `Appeal` through
  `LandingAirNull` in status order (`SLOT_APPEAL` = 509). `MarioAttack13`
  (540, Mario and Luigi) gives Mario's jab finisher a clip. `SLOT_COUNT` is
  541 and pack `VERSION` is 41.
- A fighter without the motion has no file in the slot and keeps its pose,
  as before. There are 106 such holes: mid-angle tilts and smashes,
  `AttackHi3F`/`B`, and null `LandingAirX` motions (`set_landing_or_landing_air`
  already sends those to `LandingAirNull`).
- `Status::anim_slot` maps these statuses to the shared slots. The
  per-fighter common-attack tables in `tick_skeleton_animation` and
  `pikachu`/`ness`/`purin::common_anim_slot` are removed. Before removal,
  every entry was checked against the generic slot's file id. All matched,
  except Ness's `LandingAirLw` slot: it named `LandingAirX`, but his
  `LandingAirLw` motion is null, and the status that plays is `LandingAirNull`
  (the same file). The older per-fighter slots stay in the table so earlier
  ordinals stay stable. The pack stores each file once.
- `status::clip_speed` gives the clip's playback rate. It returns
  `AnyStatus::anim_speed` for every status except `LandingAirNull`, whose
  landing-lag rate (`F_PCT_TO_DEC(flag1)`) exists only in the stored timing.
- `set_landing_air`'s doc comment said the status had no length. It already
  read `motion::anim_length`; the comment is corrected.

## Verification

- `romtool anims --verify`: 27 fighters decode, and 1,727 lengths agree with
  the decompilation (1,053 in RE-351).
- New `damage_and_attack_slots_match_the_anim_table` checks each slot's name
  against its `Status`. It also checks, for all twelve fighters, that the
  pack length equals `motion::anim_length` and that a fighter with a motion
  has a file. `only_the_moves_a_character_lacks_are_absent` pins the 106
  holes.
- `cargo +1.98.0 test --workspace` with absolute `SSB64_ROM`: 1,171 pass.
  Clippy (`-D warnings`) and rustfmt pass. Both PSP release builds pass, and
  the game builds with `regression_capture,strict_render`.
- Pack v41: 25,197,920 bytes (+604,368), SHA-256
  `fa0c02848bfa2f1a9e69ff17671f3bd241e19bfa3b751f3417fbc15c5b46b719`,
  27/27 fighters.
