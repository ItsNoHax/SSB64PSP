# RE-378 — Kirby in Training: Final Cutter wave, and TransN for every status

Status: IMPLEMENTED (decomp source, ROM display lists, host tests, PPSSPPHeadless goldens captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: fighter, weapon, animation, asset-pipeline, visual-regression, rendering
Relevant files: `tools/romtool/src/main.rs`, `crates/ssb-rom/src/pack.rs`, `crates/ssb-game/src/weapon.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-training-{kirby,captain,captain-kick,yoshi-bomb}.png`

## Question

What does Kirby's Final Cutter wave draw, under which transforms and
render state? And why did a grounded Final Cutter in `psp-game` never
rise or land?

## Source

- `dWPKirbyCutterWeaponDesc` has flags 0x03 (`WEAPON_FLAG_DOBJDESC |
  WEAPON_FLAG_DOBJLINKS`) and transform `TraRotRpyRSca`.
  `llKirbyMainCutterWeaponAttributes` (file 229 + 0x08) names file 328's
  `DObjDesc` tree at 0x1D388 and `anim_joints` at 0x1D410, with no
  `MObjSub` or material table.
- The tree has two nodes, each with one list on DL link 1. The root
  (translate 0, 225, 0) runs 0x1D238, which loads the texture and palette
  and draws nothing. Node 1 (translate 0, 0, 225) runs 0x1D308, one quad.
  Decoded from the ROM bytes, neither list sets a render mode: 0x1D238
  sets alpha compare and primitive colour 0xFFFFFFCC, and 0x1D308 sets the
  combiner `TEXEL0 * SHADE`, alpha `TEXEL0 * PRIM`. So the tree draws under
  `wpDisplayDrawNormal`'s state (`G_ZBUFFER` cleared, `G_RM_AA_XLU_SURF`),
  as the Yoshi Bomb star does (RE-375).
- The `anim_joints` table has no script for the root. Node 1's script
  (0x1D418) sets `RotZ` 0/π and `ScaZ` 1/1.25 on alternate frames, then
  loops with `SetAnim`.
- `wpManagerMakeWeapon` puts the weapon's position into the root's
  translate, replacing the desc value. `wpKirbyCutterMakeWeapon` calls
  `wpMainVelSetModelPitch`: root `rotate.y` is +90° for a rightward
  `vel_air.x`, else -90°. `wpKirbyCutterProcReflector` calls it again.
  While the wave is grounded, `wpKirbyCutterProcUpdate` sets root
  `rotate.z` to `-atan2(floor_angle.x, floor_angle.y)`.

## Finding: TransN was fed only to a status list

`FighterScene::tick_fighter_interrupt` sampled the clip's TransN into
`Fighter::root_motion` only for Mario's and Samus's up-B, the reaction
clips, cliff phase 2 and `LightThrowDash`. Every other status whose
`proc_physics` applies TransN got zero motion in `psp-game`:

- Kirby's Final Cutter (`ftPhysicsApplyAirVelTransNYZ`) never rose. It
  ended with `vel_air.y = 0` and `SpecialAirHiFall` has no gravity, so
  Kirby hovered at floor height and never landed or made the wave.
- The Falcon Punch and Falcon Kick (RE-376, RE-377) and the Yoshi Bomb hop
  (RE-375) did not move Falcon or Yoshi as their clips do.

All the `ssb-game` physics that reads `root_motion` is already gated on
its own statuses. `psp-runtime` now samples TransN every tick.

## Implementation

- Pack v55 converts graph (328, 0x1D388) under
  `InitialMaterial::WEAPON_EXTERNAL` (`WEAPON_SEEDED_GRAPHS`). It adds
  weapon anim slot `WEAPON_ANIM_KIRBY_CUTTER` (1). File 328 is Kirby's
  whole model, so only the 0x1D410..0x1D4B8 window is packed. Its two
  internal pointers (the table entry and the `SetAnim` target) are rebased
  to the window. Pack v55 is 27,096,240 bytes; without the window it was
  27,216,928.
- `KirbyCutter` gains `model_rotate_y`, `rotate_z` and `anim_ticks`, for
  presentation only.
- `psp-game` draws each wave under `T(position) · MODEL_SCALE`. Its posed
  nodes are premultiplied by `R(0, model_rotate_y, rotate_z) · T(-root
  desc translate)`, with `Mat4::from_trs`'s x-then-y-then-z order.
- The capture scene `kirby` presses Up+B at tick 20 and freezes at tick
  83, with the wave some 6 frames old.

## Golden changes

Sampling TransN for every status changed three goldens, all
TransN-driven specials:

| Golden | Change |
|---|---|
| `f1-training-captain` | The Falcon Punch now carries Falcon forward |
| `f1-training-captain-kick` | The ground kick now travels along the floor |
| `f1-training-yoshi-bomb` | The Yoshi Bomb now hops. It lands near tick 59, not 51, so the capture moved from tick 60 to tick 68 to keep the stars 6 frames old |

## Findings

- A grounded Final Cutter rises high enough to land on Dream Land's top
  platform, and the wave rides that platform.
- The wave shows blue streaks that trail into a white leading bar, at the
  primitive's 80% alpha.

## Deviations

- The wave has not been compared against an N64 capture.

## Verification

A host test covers the wave's yaw, slope roll and animation tick. Capture
logs show Kirby in `SpecialHiLanding` with one wave at tick 83, where
before he hovered in `SpecialAirHiFall`. `tools/golden.sh verify --twice`
matched all 85 scenes. Workspace tests pass with an absolute `SSB64_ROM`
and one test thread.
