# RE-512 — Sword trail renderer and Pikachu Thunder Shock spark

Status: COMPLETE, checked against four N64 RDRAM traces (Link and Beam Sword swings, Pikachu forward smash, forced magnifier)
Topics: fighters, rendering, effects, reverse-engineering
Relevant files: `crates/ssb-game/src/afterimage.rs`, `crates/ssb-game/src/fteffect.rs`, `crates/ssb-game/src/pikachu.rs`, `crates/ssb-game/src/fighter.rs`, `crates/ssb-rom/src/effect.rs`, `psp-runtime/src/meshdraw.rs`, `psp-game/src/main.rs`, `tools/r4300/afterimage_hashes.py`

## Question

How does the original draw the Link sword and Beam Sword afterimage (`ftDisplayMainDrawAfterImage`), and how does Pikachu's Thunder Shock spark spawn, live, pause and mark TopN?

## Findings

Trail render state (Link 537 records, Beam Sword 104, same words):

- The trail DLs change only combine (`00ffffff:fffe793c`) and geometry mode
  (`00200005`, ZBUFFER|SHADE|SMOOTH; lighting, cull and fog clear). Othermode is
  the leftover end of head 0: hi `00082c00`, lo `005049d8` (XLU, Z_CMP, no
  Z_UPD, FORCE_BL, AA_EN), from `gmCameraDefaultProcDisplay`'s head-1
  `G_RM_AA_ZB_XLU_SURF` before the link 6..12 capture. Port: depth test on,
  depth write off, alpha blend, untextured smooth shade. AA_EN edge coverage
  has no GE equivalent.
- Modelview is identity (mvdepth 1), vertices are world-space s16 in 16-byte
  `Vtx`, at most 0x400 bytes, in head-1 order after head 0; the projection is
  the last camera pass's. The live afterimage vertices equal the head-1 ones
  in all 774 records. The Rust vertex builder matches the r4300 oracle hash
  `0x67c084cf3477b6cf` (1200 cases, 14238 vertices;
  `tools/r4300/afterimage_hashes.py`).
- Timing: the first trail frame is the one where `drawstatus` reaches 2, one
  frame after drawstatus 1. Link jab 1 from motion start 452: ds1 456, ds2 457
  (first draw), ds3 463, drawn 457..467. Beam Sword status 126 from 491: 495,
  496, 505.

Magnifier pass (forced-magnifier trace, 133 records, camera 1005):

- The trail is drawn only in the camera-1005 pass, not in the 46x46 miniature
  viewport: full viewport (10,10)-(310,230), identity modelview, projection
  `gmCameraOrthoLookAtFuncMatrix` (0.00665283, 0.00907898, -0.000152588,
  -0.858261), world-space vertices.
- Camera 1005 has `COBJ_FLAG_DLBUFFERS`; `syTaskmanUpdateDLBuffers` runs its
  head 1 right after its own head 0, before the interface and effect cameras.
  It sets no head-1 render mode, so the trail inherits
  `ifCommonPlayerMagnifyProcDisplay`'s `G_RM_AA_OPA_SURF` (lo `00552048`, no
  Z_CMP, no Z_UPD, no blend). Port: no depth test, no depth write, no blend.
- The trace also shows lo `00552078` in 112 records. That is a trace-walker
  artifact: every one used the bounded walk, which runs all of head 0 to the
  frame end and so reads later cameras' state; all 21 natural-order records
  read `00552048`. The real state is `00552048` every frame.

Thunder Shock spark (Pikachu forward smash, 36 sparks):

- Spawn: joint 11 world position, then `func_ovl2_800EE018` converts it to
  TopN-local (inverse of the TopN transform with yaw and scale); the six trace
  pairs match within 2 ulp. Grandchild translate (0, 0, 160.2), x negated when
  facing right. Random gfx variant 0/1/2 per spark; variants 1 and 2 use the
  extra animations at file 347 0x1850 and 0x1970, which the pack stores from v110
  (`AnimDesc::EFFECT` slots from `PIKACHU_THUNDER_SHOCK_ANIM_SLOT`).
- Life is 6 frames (animation frame 0..5) for every variant. Six sparks per
  smash, first at status frame 20, then every 3 (20, 23 .. 35); at most 2 alive.
- The spark pauses while its fighter is in hitlag (animation frame frozen at 0):
  hitlag 16 gives life 21, hitlag 9 gives 14; sparks made after the hitlag end
  live 6. Hitlag starts the frame the first spark is made.
- `ftParamProcStopEffect` ejects attached effects on a status change. Not
  observed directly on the N64: a hit before the first spark leaves no sparks,
  but a live spark was never seen ejected.

TopN query mark (raw s3 frames):

- The spark root DObj uses matrix kind `func_ovl0_800C994C`, which at display
  calls `func_ovl2_800EDBA4(TopN)`: it sets `transform_update_mode` 1 and
  `unk_dobjtrans` byte 5 (world matrix built), walking up until byte 5 is set.
  The spawn path `800EE018` does the same.
- Clears: `ftParamsUpdateFighterPartsTransform` in `ftMainPlayAnim` clears all
  parts; `ftParamsUpdateFighterPartsTransformAll(TopN)` after `proc_slope`
  clears TopN's mode and word and descendants' word only. Neither runs in
  hitlag, so the mark lasts a burst while a spark draws every frame.
- Frames (status 204 at 454, hitlag 16): marked 474..509, mode-only 510, clear
  511; (at 597, hitlag 9): 617..645, 646, 647. The mode-only frame is the
  attack collision joint query the frame after the last spark. (The first
  write-up of the trace read these one frame late.)
- Port: `Fighter::world_joints` models byte 5; `mark_joint_world`,
  `topn_world_matrix`, `clear_joint_queries`.

## Spark ejection on a hit

N64 VS trace (Pikachu fsmash 204 vs Mario Fireball): one spark t460-461, hit t462 (status 40, hitlag 7), spark gone at t462 (`ftParamProcStopEffect` on the hit frame). Host matches; test `item_replays.rs` `a_hit_ejects_the_thunder_shock_spark_as_on_the_n64`.
