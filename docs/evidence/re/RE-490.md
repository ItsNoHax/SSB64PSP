# RE-490 — The wallpaper carried 60% of the GE's texel cost; drawn in 64-texel strips it saves 1.3 ms a frame

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `profile_hw,capture_scene_file,no_audio` builds of `vs4@2400` at `8650b0b` with pack v108 from `ms0:/PSP/GAME/ssb64/`, reports 1–18, interleaved runs)
Topics: performance, hardware, psp-ge
Relevant files: `psp-runtime/src/meshdraw.rs`, `psp-runtime/src/texprobe.rs`

## Question

RE-489 measured the GE's texel reads at 2.2 ms of CPU memory stall a
frame. Which textures carry that traffic, and therefore what would VRAM
residency or smaller formats have to cover?

## Method

The `texture_probe` feature (`psp-runtime/src/texprobe.rs`) tags each
textured draw with a category: stage (layers, platforms, objects), fighter
(models and magnifiers), wallpaper, or other (items, weapons, effects,
particles, shadows, interface). A `texoff.txt` beside the PRX turns
texturing off per category or per texture, and the probe writes a census of
every bound texture over frames 1500–1559 to `texprobe.log`. The probe
build costs about 0.6 ms of CPU frame over HEAD on its own, so its runs are
compared with its own base, not with HEAD.

## Findings

### Texel cost by category

One run per category, base twice; CPU frame and frame memory stall are the
`hw` spans at 333 MHz.

| Texturing off | CPU frame µs | Δ ms | Frame memory stall µs | FPS |
|---|---:|---:|---:|---:|
| none (base, two runs) | 21,214 / 21,227 | — | 11,478 / 11,491 | 40.2 |
| stage | 20,725 | −0.49 | 11,062 | |
| fighter | 20,776 | −0.44 | 11,078 | |
| wallpaper | 19,449 | −1.77 | 9,721 | 45.3 |
| other | 21,031 | −0.18 | | |
| all | 18,228 | −2.99 | 8,656 | 49.5 |

The categories add up to 2.88 ms, close to all-off. The wallpaper alone
is 60% of the texel cost.

### What is bound

Census of `vs4@2400` (Dream Land, four fighters), unique textures and
their bytes:

| Category | Textures | Bytes |
|---|---:|---:|
| other | 62 | 263,680 |
| stage | 35 | 151,936 |
| fighter | 23 | 249,728 |
| wallpaper | 1 | 262,144 |

- The wallpaper is a single 300 × 220 RGBA5551 sprite, swizzled, with a
  512-texel stride (256 KiB with padding), bound once a frame and drawn as
  one `GU_SPRITES` rectangle across the 4:3 picture.
- The largest fighter textures are 32-bit 8888 with mipmaps (224 × 64,
  87,040 bytes; 96 × 64, bound four times a frame). The largest stage
  textures are CLUT4 with mipmaps (21,760 bytes each).

### Strips recover most of the wallpaper's cost

The GE fills a sprite one screen row at a time. A 300-texel row of 5551 is
600 bytes; a full row of 8-line swizzle blocks is 4.8 KiB, and the
bilinear filter needs two block rows at each boundary, more than the 8 KiB
texture cache holds. Each block row is fetched again for later screen
rows. Drawing the same sprite as vertical strips keeps a strip's blocks
resident until the strip is done (the PSPSDK `blit` sample's 64-pixel
slices).

HEAD (`1a77cb05cb9e6d3e`) against strip builds (64 texels
`75a0036628093d73`, 32 texels `8195344ef96b1308`), interleaved, two rounds:

| Build | FPS | CPU frame µs | Draw µs | Frame memory stall µs | `vblank` µs |
|---|---:|---:|---:|---:|---:|
| HEAD | 42.02 / 41.93 | 20,604 / 20,634 | 12,662 / 12,690 | 10,894 / 10,923 | 2,738 / 2,748 |
| 64-texel strips | 45.84 / 45.83 | 19,313 / 19,310 | 11,240 / 11,238 | 9,603 / 9,600 | 2,017 / 2,019 |
| 32-texel strips | 45.62 / 45.64 | 19,377 / 19,382 | 11,305 / 11,309 | 9,659 / 9,664 | 2,040 / 2,041 |

- 64-texel strips save 1.30 ms of CPU frame, all of it memory stall
  (−1.29 ms), and the whole frame goes from 42.0 to 45.8 FPS. That is
  73% of the wallpaper's 1.77 ms; about 0.5 ms remains.
- 32-texel strips are no better (five times as many primitives for no
  fewer refetches).
- Cache misses do not change; each one waits less.

### The strips are not bit-identical

The GE steps texture coordinates per primitive, so a split rectangle
samples at a slightly different bilinear phase. In PPSSPP the vs goldens
change by up to a few tens of thousands of pixels, almost all by 1 or 2
LSB (maximum 9, on Yoshi's Island's high-contrast wallpaper), spread
evenly over the wallpaper with no seam at the strip edges. Putting the strip
edges on whole screen pixels instead of whole texels changes different
pixels by the same amounts, so the split itself causes the difference, not
the edge placement. The texel-aligned split is kept: each strip covers
exactly eight swizzle-block columns.

## Consequences

- The wallpaper now costs about 0.5 ms of texel traffic; stage and
  fighter textures about 0.45 ms each; the rest 0.2 ms. That is about
  1.6 ms left of RE-489's 2.2 ms (counted before strips).
- VRAM residency of the wallpaper now buys at most 0.5 ms. Its 220 rows
  at a 512-texel stride are 220 KiB, more than the 180 KiB free, so it
  needs the photo region or a smaller format.
- Fighter textures are 32-bit; a CLUT format where a texture fits its
  palette would cut their bytes by four or eight without VRAM.
- Any other large textured rectangle drawn in the battle loop should be
  stripped the same way before anything else is tried.
