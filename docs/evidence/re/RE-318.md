# RE-318 — Lowering tiles whose bake exceeds the GE 512-texel limit

Status: COMPLETE (host equivalence tests, PPSSPP software A/B and hidden-primitive controls, 10 stage goldens rebaselined; physical PSP not captured)

**Question.** RE-314 capped the declared GE size of 48 textures whose
padded width or height exceeds 512. Texels at 512 and above were then
unreachable. Why does the converter produce these sizes, which extent do
the primitives really sample, and what exact lowering fits the GE?

## Cause

Every one of the 88 render tiles has the same shape: `mask` narrows the
texture to a small period (8 to 64 texels), `G_TX_CLAMP` is set, the
origin is 0, and the drawn rect is 576 to 960 texels on the wide axis. The source texels
are small, for example `123:0x7E0` is 32×32 CI4 and `68:0x8C8` is a
2,048-byte 64×64 CI4 texture. Neither the load block nor `G_SETTIMG`
width is involved. `mesh.rs`'s `current_texture` narrows the texture to
the period correctly (RE-044). `texture::mirror_extend` then bakes the
repeat out to the whole drawn rect on a clamped axis (RE-221, RE-232), so
the GE receives textures up to 960 texels wide or 928 tall.

## What the primitives sample

The RDP repeats the period across the rect and clamps only at its edges
(`n64_addressing::address_axis`). The far clamp engages once the
coordinate reaches `lrs = W − 1` and then holds texel `W − 1` with a zero
filter fraction. Below `W − 1` the tile is exactly periodic.

Static UVs (S10.5) of all 88 primitives lie in `[0, W)`. 60 of them reach
the last column: their maximum is exactly `W − 1/32`. So the full extent
is sampled, but only one period of distinct texels plus the clamped far
column matter. A plain repeat of the period would blend texel 0 into the
last column of those 60 primitives. No coordinate is negative, so the near
clamp never engages.

Four affected primitives carry a material animation (anims 2, 80, 99).
None moves tile-0 UVs: 2 and 99 write `TraU/TraV/ScaU/ScaV` only at their
rest values, 80 only swaps texture IDs.

## Lowering

`wide_tile::lower` runs on each mesh in `pack_mesh`, before textures are
converted. For each wide axis each triangle gets one of two tiles that
address the same texels as the RDP:

| Tile | Used for | Texture | Wrap | UVs |
|---|---|---|---|---|
| Repeat | triangles whose coordinates stay below `W − 1` | the period (mirrored pair if mirrored), clamp bit cleared | `Repeat` | unchanged |
| Window | triangles that reach the far column | the rect's last `W − L` texels | `Clamp` | shifted by `−L` |

`L` is a multiple of the baked period, so the shift keeps the phase, and
`W − L ≤ 512`. Among valid `L`, the one splitting fewest triangles wins,
ties to the smaller window. A triangle that reaches the far column but
also samples below `L` is split along `coordinate = L`. Every triangle of
that primitive crossing `L` is split, so no split edge meets an unsplit
neighbour inside the primitive. Consecutive triangles with the same tiles
stay one primitive, preserving submission order.

A split vertex interpolates from the endpoint with the lower coordinate,
so neighbours sharing the edge get the same vertex. The split coordinate
is exact; positions round to the nearest unit. The worst UV gradient on a
split primitive is 0.135 texel/unit, so the rounding moves sampling by at
most 0.07 texel along the seam. All 68 split points lie on edges whose
endpoints have identical colour and normal (instrumented pack build), so
the baked shading at every new vertex is exact.

The lowering refuses, as a pack-build error, any wide tile it cannot
prove exact: unclamped, unnarrowed, nonzero origin, texgen, negative
coordinates, mixed lit/unlit split edges, or a material animation that
`uv_writes_hold` plus the replay cannot prove UV-static. None occurs.

**Pack.** 0 textures over 512 (was 48). The 88 primitives become 249;
34 triangles are split. Textures 1,856 → 1,869, draws 8,182 → 8,343.

their 8–64-texel periods. SHA-256

## Verification

- Host: `wide_tile::tests` lower a full-rect quad for four real shapes
  (32 over 608; 8 mirrored over 576; 64 mirrored over 576, not a whole
  number of mirrored pairs; 32 over 960) and check every sampled S10.5
  coordinate and its bilinear neighbour against `address_axis`, plus each
  output vertex's UV against the source mapping. Breaking the band
  classification, the Repeat clamp bit, or the window shift each fails a
  test. Other tests cover pass-through, repeat-only, winding and refusals.
- `tools/golden.sh verify --twice`: shipped pack 67/67 match; candidate
  pack changes exactly 10 stage goldens, each deterministic on repeat.
  Stage 21's only site (`129:0x1EE8` prim 2) samples `v` up to 512.34 and
  never reaches its far column, so the RE-314 cap already drew it the same.
- Hidden-primitive control (`romtool pack --hide-wide-tiles`, and the
  shipped pack with the 88 primitives' index counts zeroed): 10 of 11
  affected stages byte-identical. Stage 35 differs by 34 native pixels in
  prim 3 of `144:0x34E0`, which is not lowered and is byte-identical in
  both packs. Its texture is 16×208 T4 at stride 16 (8-byte rows).
  PPSSPP reads it with a 16-byte pitch, 3,328 bytes from a 2,048-byte
  texture, so it samples the pack bytes that follow it. Copying the
  shipped pack's 2,048 following bytes into the candidate makes stage 35
  byte-identical too. This measures RE-314's source-only row-pitch finding.
- Rebaselined (2x pixels): `r2-stage-kongo-jungle` 516,
  `r2-stage-hyrule-castle` 11,340, `r2-stage-bonus1-kirby` 5,744,
  `r2-stage-bonus1-ness` 1,400, `r2-stage-bonus2-fox` 1,412,
  `r2-stage-bonus2-link` 1,632, `r2-stage-bonus2-captain-falcon` 624,
  `r2-stage-bonus2-kirby` 22,772, `r2-stage-bonus2-pikachu` 8,788,
  `r2-stage-bonus2-ness` 18,704. Visually the RE-314 clamped streaks
  (flat blocks right of Kongo Jungle's platform, streaked pillars in
  Board the Platforms) become the repeating texture.
- Workspace tests (826) and both PSP release builds pass.

Not captured. On hardware, check stages 10, 36 and 39 (largest changes):
`Repeat` on the small period textures, `Clamp` on the window textures at

half. Also check whether the GE, like PPSSPP, reads sub-16-byte T4 rows
with a 16-byte pitch. The 7.1 MiB smaller pack is relevant to PSP-1000
support (RE-288).
