## Findings

1. `Pack::mat_anim` full decode in animator ticks = 4.2% of vs4 instructions. `mat_anim_file_at` reads only the entry's file range: -3.9% instructions.
2. `Plan::safe_point` scanned every file each frame: 1.1M of 49.6M intro trace words, 0.5M in vs4. Now gated by `Plan.leaving`, set only in `enter_end` (the only `Keep::Leaving` writer). vs4-20: `run` words 541k to 8.4k + `safe_point` 1.9k.
3. Trace and timer layout: `frame_end`/`vblank` out of line, report write behind a `black_box` const, override parsing in cold `apply_overrides` in every `capture_scene_file` build, `safe_point` out of line.
   - trace vs timer: 2070 functions, size-diff 0; ordered names 356 of 357 at the same address; 0 non-relocation code words differ.
   - release vs timer: ordered names equal except the tail; `run` starts at the same address but capture code keeps it larger (0x82bc vs 0x41ec).
4. Trace defect: trace builds (`capture_scene_file` only) ignored `onepstage=`, so 1P traces were another stage. Intro `replay_corners` 0.66M vs 4.0M words, audio `render_frame` 10.4M vs 3.4M. This explains the earlier intro "regression" (+1.1-2.6 ms) of searched orders. With the scene fixed, as-linked model misses rank hardware: HEAD 225k < code+unification 259k < +mat_anim 319k = hw 19.44 < 20.29 < 20.73 ms.
5. Layout sensitivity without re-search: mat_anim code at HEAD's order intro +1.27, opening Run/Yoster/Clash +0.5-0.6; HEAD code + unification + lever at HEAD's order intro +0.80, others -0.03 to -0.31.
