**Physical-hardware smoke test.** PSP Slim, 6.61, ARK/Infinity, PSPLink
v3.2.1, connected over USB (`054c:01c9`), bridged via `usbhostfs_pc -v
"$PWD"` from the repository root, `host0:` `ldstart` of each
`regression_capture` PRX in turn (`psp-hardware` Skill procedure), `kill` +
`reset` between them.

The specific residual risk RE-297 flagged: `psp-runtime::gu::Gpu::end_frame`
now calls `sceGuDebugFlush()` unconditionally for `psp-game` too, which
never called it before this refactor. RE-202's own root cause — the
hardware crash lives in `sceGuDebugPrint`/`sceGuDebugFlush`'s state once
glyphs are actually queued, not in a bare `Flush` against an empty buffer —
predicted this would be safe. Confirmed:

* `psp-asset-viewer` (`ssb64-psp-asset-viewer.prx`, UID `0x041B525B`):
  `ldstart`, 6 s past the deterministic freeze, `exlist` empty, `main_thread`
  alive. Native `scrshot` capture (391,734 bytes, 10,041 unique colors,
  SHA-256 `5a963f2a3fbac94bab214f7349d48a5cef7c51c162991e128386c16338b5d0c2`)
  shows Dream Land, correctly pillarboxed, matching the PPSSPPHeadless
  golden — the first physical-hardware confirmation of Step 4's shared
  `Gpu::set_viewport_pillarboxed()`/full-screen-default design (RE-297's own
  fix was PPSSPP-only evidence until now).
* `psp-game` (`ssb64-psp-game.prx`, UID `0x041B525B`, reused after
  `kill`/`reset`): `ldstart`, sustained **28+ seconds** past the
  deterministic freeze (RE-202's own crash reproduced within seconds of
  sustained per-frame `sceGuDebugPrint`/`Flush` use, so this comfortably
  exceeds that window) — `exlist` empty throughout, `main_thread` alive.
  Native `scrshot` capture (391,734 bytes, 17,247 unique colors, SHA-256
  `b276d98a8ff140fcf459098ed6f62e02dadeb79256cb8f4e82b95bbd0a86dfe9`) shows
  the real two-Mario Training scene, jab range, matching the PPSSPPHeadless
  golden — the pack loaded successfully under this `ldstart` session (no
  `OutOfMemory` fallback color this run; per RE-255/256/296, `ldstart`
  memory availability is session-dependent and not a `psp-runtime` concern
  either way, since the frame loop exercising `sceGuDebugFlush` runs
  identically whether or not the pack loads).

Zero exceptions, zero crashes, on real hardware, for both applications.
RE-297's residual risk is closed: the shared, unconditional
`sceGuDebugFlush()` call is confirmed safe for `psp-game`.

**Verdict.** All acceptance criteria pass, software and hardware. The PSP
runtime refactor (Steps 1-10) is complete. F1 feature development may
resume per `STATUS.md`.
