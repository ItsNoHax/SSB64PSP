## Source and ROM findings

`sc/sc1pmode/sc1ptrainingmode.c`: the `sc1PTrainingModeMake*`, sprite
update and display callbacks, `...SetMenuGObjFlags`, enter/leave and
stat-counter processes. `ft/ftparam.c:ftParamUpdatePlayerBattleStats`
counts accepted damage from another player; `ftMainProcUpdateInterrupt`
clears both counters after update/interrupt when outside hitlag and no
longer in hitstun. The fighter, weapon, item, POW and throw paths call
the stat updater when their damage registers.

`reloc_data.us.h` gives Training file 254 and four tables: positioned
display labels at 0, 39 display options at 0x20, positioned menu labels
at 0xBC and 31 menu options at 0x13C. The 84 used sprite pointers are
external relocations into file 29. File 254 is 672 bytes, with 118
external pointers and no internal relocations. The port resolves each
pointer through the archive and decodes the original sprite; it retains
the signed Vec2h positions rather than reproducing them as constants.

Two source details needed investigation:

- Opening Training's menu calls `ifCommonInterfaceSetGObjFlagsAll`:
  every Interface-link object hides, including the battle HUD and the
  Training stats. The menu belongs to the separate PauseMenu link.
- `SC1PTrainingModeMenuOptionSprites` calls entry 26 Normal and entry 27
  Close-Up, but the callback uses `view_menu_option + 26`, with Close-Up
  option 0 and Normal 1. The ROM and runtime show that 27 is Normal and
  26 Close-Up. Preserve the callback indexing; do not reverse it using
  those enum names.

## Implementation

| Source behaviour | Port |
|---|---|
| Stat interface | Purple DAMAGE/COMBO/ENEMY/SPEED labels, green digits/options, percent sign and the player's held-item icon between brackets. Damage caps at 999; combo at 99. |
| Counter display | Last digits stay for 90 process ticks after their source counter clears. Drawing twice does not restart the wait; a new hit replaces the digits immediately. Hidden counters' processes keep running, but their display callback does not observe new values. Slowed speeds skip those processes with the world. |
| Open menu | Blue panel `(68,47)-(253,198)`, six orange labels, four selected option sprites, ROM border sprites, cursor orb, red arrows and underline. The underline's fill-cycle endpoint is inclusive. Reset/Exit hide the arrows. |
| US layout | Options centre at x 191 with integer half-width; Motion-Sensor Bomb sits two pixels higher, with compensated arrow y. Cursor and underline follow the selected label's ROM position and size. |
| Hit accounting | Accepted fighter, weapon, item and player-owned direct hits count the actual captured/resisted damage, independently of the ten-entry hit-log limit. Throws/lifts and Kirby's capture damage count through their existing stat paths. World/self and invincible hits do not count. Thrown-fighter credit uses the source thrower's port. |

Gameplay layout and counters live in `ssb-game`; ROM extraction and pack
metadata in `ssb-rom`/`romtool`; `psp-game::training_screen` only adapts
the packed sprites/positions to the existing PSP drawing functions.
The counters are carried by each portable Fighter, in place of the
original battle state's player entry. No PSP backend change is needed.

Pack v87 adds sprite aliases keyed `(254, pointer_slot)` and the first
0x1B8 bytes of file 254 in `AnimDesc::TRAINING_LAYOUT`'s metadata payload,
as the existing translation-scale payload does. No descriptor layout
changes. Size 35,778,144 bytes (+330,272); SHA-256
`c5727de42ec3b91c2022998c3adc16c7e35a8b748348eec2ca79d5a130f55ac2`.
Generated pack and extracted assets remain untracked.
