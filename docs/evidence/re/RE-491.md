# RE-491 — Most direct-colour textures fit a palette: storing them as CLUT4/CLUT8 is lossless and saves 0.45 ms a frame

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `profile_hw,capture_scene_file,no_audio` builds of `vs4@2400`, reports 1–18, two interleaved rounds; 198 of 198 goldens unchanged in PPSSPP)
Topics: performance, hardware, psp-ge, texture, pack, asset-pipeline
Relevant files: `crates/ssb-rom/src/psp_texture.rs`, `crates/ssb-rom/src/pack.rs`, `psp-runtime/src/meshdraw.rs`, `tools/romtool/src/matsample.rs`, `crates/ssb-rom/examples/texture_palette_fit.rs`

## Question

RE-490 left about 1.6 ms of CPU memory stall a frame from the GE's texel
reads in four-player VS; fighter textures, stored as 32-bit 8888, were
0.45 ms of it. Can the direct-colour textures be made smaller without
changing a pixel?

## Findings

### Most direct-colour textures have few colours

`texture_palette_fit` counts the distinct texels of every 8888 and 5551
texture in pack v108 (all stored levels, padding included):

| Format | ≤ 16 colours | 17–256 colours | > 256 colours |
|---|---:|---:|---:|
| 8888 | 839 (11.1 MB) | 594 (7.4 MB) | 328 (7.2 MB) |
| 5551 | 54 (1.0 MB) | 72 (1.3 MB) | 30 (5.3 MB) |

Filter compensation (RE-305–RE-313) and IA formats both produce 8888
textures, but their level 0 rarely uses more than a few dozen colours.
The largest fighter texture bound in `vs4@2400` (224 × 64, 87,040 bytes
with mips) has 26 colours.

### CLUT storage is lossless on the GE

The GE looks each texel up in the CLUT before it filters, so a CLUT of a
texture's own colours (8888 entries, 5551 expanded as the GE expands it)
samples exactly what the direct-colour texture did.
`psp_texture::palettize_lossless` re-encodes level 0 as `PsmT4` (≤ 16
colours) or `PsmT8` (≤ 256), at `ge_buffer_stride`'s stride for the new
width, swizzled when the original was. It keeps only level 0, the only
level the GE is ever given (RE-127). `PackWriter::add_texture` applies it to
every texture and flags it `TextureDesc::TEXELS_PALETTIZED` (pack v109, no
layout change). A primitive's animated palette (RE-326) is not loaded over
a palettized texture: before, such a load was harmless on a direct-colour
texture.

In PPSSPP all 198 goldens keep their pixel hashes. After the change, only
direct-colour textures with more than 256 colours remain (295 of 8888,
29 of 5551). The pack goes from 64,174,736 to 46,954,960 bytes.

### Hardware

A is RE-490's 64-texel-strip PRX (`75a0036628093d73`) with pack v108 from
`ms0:/PSP/GAME/ssb64/`. B is this change (`6bf4f513cc129f04`) with pack
v109 beside the PRX on `host0:`. Both read every battle file before the
measured window (`io` 0 in reports 1–18).

| Build | FPS | CPU frame µs | Draw µs | Frame memory stall µs | Draw I-misses | Free RAM in battle |
|---|---:|---:|---:|---:|---:|---:|
| A | 45.73 / 45.74 | 19,324 / 19,336 | 11,253 / 11,255 | 9,613 / 9,626 | 18,400 | 36,090,624 |
| B | 47.31 / 47.29 | 18,884 / 18,885 | 10,844 / 10,844 | 9,160 / 9,161 | 17,850 | 40,281,344 |

- −0.44 ms of CPU frame, all memory stall (−0.45 ms), and 45.7 → 47.3
  FPS. That matches RE-490's 0.45 ms for fighter textures.
- The battle reads 4,783,518 bytes of files instead of 8,463,902, and
  4.0 MiB more RAM stays free.
- The two load times are not comparable: B read from `host0:`, A from
  the Memory Stick.

## Consequences

- About 1.15 ms of texel stall remains: the wallpaper (0.5 ms, 3,031
  colours, does not fit a palette), stage textures (already CLUT4) and
  the rest.
- Direct-colour textures with more than 256 colours could take a lossy
  palette only where goldens prove the difference invisible; none of this
  record's gain depends on that.
- Unpalettized textures still store mip levels the GE never samples
  (RE-127); dropping them would save memory, not bandwidth.
