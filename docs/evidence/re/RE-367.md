# RE-367 — Shield tilt pose and clip start frame

Status: IMPLEMENTED (decomp, US ROM pack tests, host tests, pack v49 rebuilt from the ROM, both PSP builds, full PPSSPPHeadless golden matrix, PPSSPP boot smoke; no physical PSP)
Topics: animation, pack, status machine, shield, asset-pipeline
Relevant files: `crates/ssb-game/src/{status,grab}.rs`, `crates/ssb-rom/src/{fighter,pack,skeleton}.rs`, `crates/ssb-rom/tests/shield_pose.rs`, `tools/romtool/src/main.rs`, `psp-runtime/src/scene.rs`

## Question

RE-366 left two gaps. `Guard` held `GuardOn`'s last frame without the
stick-driven tilt, and every clip started at frame 0. What does the
original do for each?

## Sources

- `ftMainSetStatus` (`ftmain.c`) and `lbCommonAddFighterPartsFigatree`
  (`lbcommon.c`): the figatree starts at `frame_begin` on every entry,
  even into the same status.
- `ftcommonguard1.c`, `ftcommonguard2.c`: `ftCommonGuardUpdateShieldAngle`,
  `ftCommonGuardUpdateJoints`, `ftCommonGuardInitJoints` and their callers.
- `ftParamUpdateAnimKeys` (`ftparam.c`): `is_anim_joint` selects
  `gcParseDObjAnimJoint`.
- `FTAttributes` (`fttypes.h`): `dobj_lookup` at 0x2D8 and
  `shield_anim_joints[8]` at 0x2DC.
- `relocData/314_FoxShieldPose.c`, `327_LinkShieldPose.c`.

## Findings

### Clip start frame

`ftMainSetStatus` passes `frame_begin` to
`lbCommonAddFighterPartsFigatree`, and it restarts the figatree on every
call. The port's renderer restarted a clip only when the status *changed*,
and always at frame 0. The callers that pass another frame:

- `Pass`, `GuardPass` and Donkey's `ThrowFFall` out of a pass: 1
  (`ftCommonPassSetStatusParam`). The port passed 0.
- `RebirthDown`: 100. The halo waits, not the clip, end the status.
- Walk-to-walk, `CatchPull`, and the specials that swap between ground and
  air variants: the current frame. The port already passed these, but the
  renderer dropped them.

The hammer, gun and Fire Flower statuses also start later, but have no
gameplay port yet.

### Shield data

Each fighter's `*ShieldPose` file holds two things `FTAttributes` points at:

- `dobj_lookup`: a `DObjDesc` array. It is the neutral shield pose, not
  the model's rest pose (Fox's first model joint: translate (15, 225, 15)
  against the model's (0, 249, 0)).
- `shield_anim_joints[i]`: a joint table for stick sector `i` (45 degrees
  each, `FTCOMMON_GUARD_ANGLE_MAX` 359). The scripts are `AObjEvent32`
  streams, 45 frames long, one frame per degree.

`ftCommonGuardUpdateJoints` indexes `YRotN` as the count of joints from
`XRotN` on, minus one. So a table walks `XRotN`, the model joints, then
`YRotN`, which is N + 2 entries for N model joints. The pack build checks
this against `dobj_lookup`: its terminator (`id` 18) must sit at entry
N + 2. All 26 fighters with shield data pass. Fox has 28 entries, and
`YRotN`'s neutral translate is (0, 300, 30): the shield's centre.

Only Link's tables script `XRotN`, and only with translate (0, 0, 0). A
host test checks that the script leaves the joint at rest for every sector.

### Shield pose

- `ftCommonGuardUpdateShieldAngle`: `atan2(stick_y, stick_x * lr)` in
  degrees, wrapped to 0..360 and clamped to 359. `angle_i` is the sector
  and `angle_f` the degrees into it. `shield_rotate_range` is the stick
  deflection over 80, at most 1.
- `ftCommonGuardUpdateJoints` (`GuardOn` and `GuardOff`, while `is_shield`):
  updates the angle, restarts `YRotN` on the sector script at `angle_f`,
  plays one tick, then blends toward `dobj_lookup` by the range.
- `ftCommonGuardInitJoints` (`Guard` entry and update, `GuardSetOff`
  update): does the same for every joint the table names. `GuardSetOff`
  keeps the angle it was hit at. A joint the table leaves null keeps its
  pose; a named joint stops its own clip (`anim_wait = AOBJ_ANIM_NULL`).
- With the stick at rest the range is 0, so the fighter takes the neutral
  shield pose.

## Implementation

- `StatusState` records `anim_frame_begin` and an `entry` counter.
  `tick_skeleton_animation` restarts the clip on each entry, at
  `anim_frame_begin`. `-1`/`-2` statuses still keep the previous clip.
- `set_pass_status` passes 1; the Donkey pass path passes 1;
  `set_rebirth_down` passes 100, with its length counted from there.
- `GuardState` gains `angle_i`, `angle_f` and `shield_rotate_range`, set
  where the original calls the two joint functions.
  `ssb_game::status::shield_pose` says which one applies.
- Pack v49: `AnimDesc::SHIELD_POSE` entries, `slot = kind * 8 + sector`,
  208 tables for 26 fighters. The script bytes are the whole ShieldPose
  file, and `frames` holds the `dobj_lookup` offset.
- `ssb_rom::skeleton::apply_shield_pose` plays each named joint with the
  32-bit `StageJoint` player and blends it. `FighterScene` applies it after
  the clip tick and keeps `YRotN` in its own pose.
- `FighterScene::sample_gameplay_joints` now fills joint 3 (`YRotN`) while
  a shield pose applies. `combat::shield_transform` used to fall back to
  the fighter's feet; it now centres the shield sphere on `YRotN`.

## Deviations that remain

- **Luigi's `translate_scales`.** Luigi is the only fighter with
  `translate_scales`. The original scales his joint translations
  (`lbCommonPlayTranslateScaledDObjAnim`) during clips and in
  `ftCommonGuardGetJointTransformScale`. The port applies neither.
- **`XRotN`/`TransN` under `YRotN`.** The port places `YRotN` directly
  under the fighter's root. `XRotN` stays at rest in every shield status,
  and the port ignores `TransN` for the body too.
- **Shield bubble.** The bubble effect is not drawn. The shield collision
  now uses the posed `YRotN`.
