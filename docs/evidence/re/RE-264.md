# RE-264 — Fox's white extremities reveal a disabled PSP light channel; Ness shares Kirby's reconstruction artifact

Status: COMPLETE
Topics: fighter, lighting, stage, texture, material

**Question.** Why are Fox's white gloves and boots gray in the PSP capture,
and are Ness's inward eye spikes the same failure already isolated on Kirby?

**Source and ROM evidence.** The supplied original-game Sector Z image shows
Fox's gloves and boots as white, with ordinary directional shading rather than
a flat replacement colour. Fox model file 313 confirms that the relevant
untextured materials are already authored correctly: hand nodes 6/12 and the
main boot surfaces on nodes 18/23 write white `LIGHT_1` (`255,255,255`) and
gray ambient `LIGHT_2` (`76,76,76`); only the separate sole primitives use the
darker `128/51` pair. Sector Z's `MPGroundData` is file 262 at `+0x14` and
stores light angles `[0, 90]`. The decompilation's
`ftDisplayLightsDrawReflect` converts those values and loads one directional
light immediately before the fighter draw. The PSP path programmed light 0
with `sceGuLight` but enabled only global `GU_LIGHTING`, never the independent
`GU_LIGHT0` channel. A `+90`/`-90` A/B was therefore byte-identical and both
showed only the gray ambient term. This is a missing PSP state transition, not
bad Fox material data.

Ness model file 335's default 32x32 CI4 face is at `+0xB7A0` (default TLUT
`+0xC060`). Its decoded pixels contain the same single-texel eye stair steps as
Kirby's neutral face; raw PSP linear magnification turns them into the same
false inward spikes.

**Implementation.** `DrawState::configure_fighter_light` now enables
`GuState::Light0` after configuring it, and `finish_fighter_light` disables the
channel with the global lighting state. Scene 6 applies Sector Z's packed,
source-file-selected light instead of the generic object-view baked fallback,
so it exercises Fox under the context shown by the supplied reference. No Fox
colour is overridden. `romtool` adds only Ness's exact `(file 335, offset
0xB7A0)` key to RE-263's centre-weighted reconstruction table and keeps the
result unquantized as `Psm8888`; a unit test pins both face keys and rejects
nearby file/offset aliases.

**Verification.** With `GU_LIGHT0` enabled, the previously identical Fox
light-direction A/B diverges as expected; the source Sector Z direction makes
the upward-facing glove and boot surfaces white while retaining shaded facets.
The refreshed PPSSPP-software goldens change 128 pixels on Dream Land's small
Mario, 12 on Saffron City's small Mario, 57,220 on Fox, and 20,368 on Link,
all confined to runtime-lit fighter surfaces. Ness changes 8,800 pixels around
the reconstructed face and now has two smooth upright eyes. Current hashes are
Dream Land `4979febc5824...`, Saffron City `de666a5c1b3e...`, Fox
`a3fb34835383...`, Ness `5d81b418a8fd...`, and Link `1d5ff77266e1...`; each
accepted image compares exactly to its capture, and two independently built
Fox and Ness captures are byte-identical. The rebuilt pack retains 2,044
meshes, 36,772 triangles, 8,169 draws, and 1,762 textures, grows to 26,288,016
bytes, and reloads cleanly (SHA-256
`495a4bcd52f0cfe720d5007a0e9d45b8453e2fb09cb89283993926713a7568db`).
`cargo test --workspace` passes all 616 tests, formatting is clean, and the
feature-free PSP release build succeeds with the existing warnings.
Physical-PSP confirmation remains part of R2.

**Confidence.** Certain for the Fox state bug and source material/light values;
high for Ness's bounded reconstruction correction. The latter remains an
evidence-backed approximation of N64 filtering, as in RE-263.
