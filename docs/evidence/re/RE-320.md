# RE-320 — PSP-2000 confirms the 16-byte T4 texture-row pitch

Status: COMPLETE (physical PSP A/B stripe diagnostic and stock-pack smoke)
Topics: texture, psp-ge, hardware, pack, visual-regression

Relevant files: `crates/ssb-rom/src/psp_texture.rs`
(`ge_buffer_stride`), `psp-runtime/src/meshdraw.rs` (`bind_texture`),
`docs/evidence/re/RE-319.md`

**Question.** RE-319 proved in PPSSPP that the old pack's 4- and 8-byte
`PsmT4` rows were read at a 16-byte pitch. Does a physical PSP reproduce the
same row selection, and does pack v32 restore the missing rows?

## Hardware and build

- User-confirmed PSP-2000 (Slim), firmware 6.61 (`pspsh -e pspver` returned
  `0x06060110`), ARK CFW (`ARKCompatLayer` and `Stargate` loaded; the prior
  unit record also reports Infinity), PSPLink v3.2.1 over USB `054c:01c9`.
  `meminfo` showed a 57,671,680-byte user partition.
- Source commit `e0ee71f5b994a19660f7590a5eccb3c419899038`.
  Built `psp-asset-viewer` with
  `SSB64_CAPTURE_OBJECT=138:0x2998 cargo psp --release --features regression_capture_object`.
  PRX SHA-256
  `bdb46c3597d81dbae13021602a12c287ed4c0423fdb9d06fb37b41cc300b47af`.
- Served the checkout as `host0:` with `usbhostfs_pc`; a symlink beside the
  PRX selected each pack. Killed the exact game module and reset PSPLink
  between loads. The runs were captured after the deterministic 240-tick
  freeze; `exlist` was empty for all three, and the stock run's
  `main_thread` remained alive.

## Controlled packs

RE-318 changed texture numbering. In graph `138:0x2998`, primitive 4284
uses texture 803, a 16×400 `PsmT4` pillar. The old pack stores it at stride
16 texels (8 bytes per row), while v32 stores it at stride 32 texels
(16 bytes per row). Texture 803 was filled with palette index 1 (red) on
even rows and index 2 (green) on odd rows. The same palette and logical
texels were used in both packs; v32's widened data was swizzled as packed.

| Pack loaded by the same PRX | SHA-256 |
|---|---|
| RE-318 v31 layout, version field patched to 32 for the current runtime, then striped | `792bde819403869d3371e2e150686d2f1cc585ce170c76a29380ca2a70545ac9` |
| RE-319 v32 layout, striped | `9179a6efaf9cf2310026c8d3a5034da8e139d49b701331dde07bdf597391bcde` |
| Unmodified v32 production pack | `4a972a600fe5bec0edc3fcea14d1ce580f72426cce1af6df2f9692055098763e` |

The original RE-318 v31 pack was 22,010,384 bytes, SHA-256
`af3236384d34fed25d8a441cdd700c555bb637791b2a6dbaebc6df8b11bcd835`.
The version-field patch changes only the compatibility header; it cannot
alter the texture row layout.

## Native captures

PSPLink `scrshot` produced 480×272 BMPs. Captures are gitignored under
`assets/generated/`; none are committed.

| Run | Capture SHA-256 | Pillar observation |
|---|---|---|
| Old 8-byte row | `aec5d41d4a4783425dc56e94b8e0c94872cb6b1957181a10e2e820e029a2f56c` | 191 probe pixels, all exactly `(89, 0, 0)` |
| Fixed 16-byte row | `cf46fc9179a1320e1eda9a73e3a0c6f92dd6845397597490830bfb7bcacd76cf` | At those same 191 coordinates, 185 contain green; 163 have green ≥16; 6 remain pure red |
| Unmodified v32 | `88977ee9317f24a542591ce0cd4f292aab4c1c8942abac2a3c565c8bc7ec9b88` | Original pillar texture renders; no stripe colours or exception |

The 191 old-pack red pixels occupy `x=307..309, y=107..170`. Fixed-pack
examples at the same coordinates are `(50, 39, 0)` and `(22, 67, 0)`.
These are red/green bilinear blends. With 8-byte stored rows, the GE reads
only even source rows at a 16-byte pitch. With 16-byte stored rows, it reads
both parities. This directly confirms RE-319's pitch diagnosis on this
PSP-2000. A zoomed comparison is saved locally as
`assets/generated/re319-hw-stripe-compare.png` (SHA-256
`b37a8534ef104d1c97a062e3de2a5b41708d0b633d541873d81248eefea5f7a6`).

**Conclusion.** Pack v32's row widening fixes the measured short-row
`PsmT4` defect on physical PSP hardware. The stock v32 pack loads and
renders without an exception. This test establishes the 16-byte pitch for
this texture and device. It does not replace a full on-device golden matrix
or prove the pitch rule for other formats and PSP models; all 304 short rows
in the shipped v31 pack were `PsmT4` (RE-319).
