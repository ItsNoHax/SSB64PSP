Status: MEASURED (PSP-1000 hardware, PSPLink; PPSSPP goldens)
Topics: hardware, psp-1000, rom-free, performance, memory, rendering, meshdraw, audio
Relevant files: `psp-runtime/src/gu.rs`, `psp-runtime/src/meshdraw.rs`, `psp-game/src/campaign_screen.rs`, `psp-installer/`

## Setup

- PSP-1000, 6.61 ARK, PSPLink v3.2.1; `usbhostfs_pc` pinned to its USB port; pack v149 (`2fe2dd842aaa476c`); build 106e87ad.
- User memory 24 MiB (MEMSIZE ignored, RE-288); free at installer start about 22.3 MB under PSPLink.

## Findings

1. On-PSP pack build (`INSTALL.PBP`, RE-588 item 15 "PSP-1000"): `ms0:/PSP/GAME/ssb64/` with `rom.z64`, release EBOOT hand-off.
   - Gate `Ok`, 496.9 s (8.28 min). Phases (s): tables 38.2, load_all 18, meshes 270, anims 49, particles 42, finish 61.
   - Lowest free 10,359,040 B; end free 17,431,808 B; stack free 176,132 B (as PSP-2000).
   - Output 42,688,680 B, `cmp`-identical to the host-built pack; no `.tmp` left.
2. Scripted playthrough (profile build `c997a829…`, capture scenes `@30000`, `ldstart host0:` beside the ms0 pack): 38 scenes, every report written, exception list empty in all.
   - Covered: opening loop, VS mode / fighter / stage select, VS on gkind 0–8 with rotating fighters, teams, sudden death, results, Training select and heavy items, 1P stages 0–13 (Break the Targets, Board the Platforms, race), 1P intro, ending and staff roll, game clear, challenger, bonus pause, star KO.
   - Lowest `minfree`: fighter select 1,957,888; VS results 2,106,368; 1P stage 12 2,257,408; all others 3.1–6.9 MB. RE-475's PSP-1000 VS-results out-of-memory screen did not occur under PSPLink; the XMB budget on a PSP-1000 is not measured.
   - Media Engine audio: 487 of 487 reports `state=1` (up), 59–60 lists/s, `fallbacks=0`, `resets=0`, `under_total=0`, `err=0`. Heard by nobody.

4. Polygon Team cause (tape counters, 120 frames): 30 frozen models; 18 replay each frame, 12 record and fail (`armed.valid` false). The 176 KiB VRAM vertex region (`gu::ge_vertices`) holds about 18 models (about 9.7 KiB each); the rest spill to list memory, which each list rewrites, so a replay is impossible ([RE-576](RE-576.md) spoiler "VRAM spill"). The PSP-2000 profile log shows the same draw (24.8–27.3 ms), not PSP-1000-specific.
5. Hardware counters (`profile_hw`, per frame, Yoshi Team intro vs the frame before it): cycles 8.0 M vs 3.5 M, memory stalls 3.65 M vs 1.28 M, I-cache misses 33k vs 7.5k. A replayed model still costs about 0.8 ms (14.7 ms for 18): node walk, matrices, materials, commands.
6. Fix: `gu::vertex_overflow` — while a tape is armed (`DrawState::arm_tape`), blocks past the VRAM region go to main memory that persists from list to list.
   - Grown at each list start by the last list's spill + 16 KiB, at most 192 KiB (`TAPE_OVERFLOW_BYTES`); freed at the start of the first list after one that arms no tape.
   - Once a list takes the overflow, the VRAM region takes nothing more: one cursor names the position (`vertex_region`), so tape start/end stay exact.
   - Hot path unchanged: the past-VRAM branch is a `#[cold]` helper ([RE-576](RE-576.md) placement rule).
