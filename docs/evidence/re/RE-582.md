# RE-582 — Boot time breakdown, boot_log distortion, deferred audio and first save (batch 90)

Status: VERIFIED (PSP-2000 hardware, PPSSPP headless, host tests)
Topics: boot, boot_log, audio, save, pack
Relevant files: `psp-game/src/main.rs`, `psp-game/src/boot_log.rs`, `psp-game/src/save.rs`, `psp-runtime/src/memory.rs`, `crates/ssb-rom/src/pack.rs`, `tools/psp-link.py`

## Hardware

PSP-2000 Slim, 6.61 ARK, PSPLink v3.2.1, pack v137, PRX from `ms0:/ssb64hw/` with the pack beside it (a PRX started from host0 finds no pack beside it and falls back to the pack in `ms0:/PSP/GAME/ssb64/`). `boot_log` build, 3 runs each, interleaved.

## Findings

1. No boot regression on the PSP-2000: `psp_main` to frame 1 was 534 ms at HEAD 917505c9. Not reproduced: "very slow" boot from the XMB (needs a person; PSP-1000 unmeasured).
2. Breakdown (ms, `psp_main` to frame 1, before the change):

| Span | ms |
|---|---:|
| `Gpu::init` + pad | 31 |
| `assets::load_pack` (5,056,928 B resident, one `sceIoRead`, 15.5 MB/s) | 327 |
| `scene_files::boot` | 23 |
| `start_audio` (1,941,342 B prefix, streamer thread) | 107 |
| `save::boot` | 9 |
| `Pack::open` + indexes | 9 |
| `go_scene(Startup)` | 9 |
| `DrawAssets::resolve` | 19 |
| frame-1 `save::persist` (file exists) | 35 |

3. `boot_log` distortion: one open/append/close per line costs about 16 ms, and 0.34 s to create the file. The as-shipped log read 951-957 ms for the same boot; every boot.log taken before batch 90 is inflated by 0.4-0.5 s.
4. Change: `boot_log` holds lines in an 8 KiB buffer until frame 60, a fatal (`memory::on_fatal` hook) or a full buffer. Lines before frame 60 are lost on a hang or panic.
5. Change: boot audio start and `apply_options` move to the top of tick 2, and a save taken in tick 1 is written at tick 2 (same bytes). D-049: the N64 installs audio before `mnStartup`; tick 1 is the `mnStartup` tick and makes no sound call (host test `the_logo_makes_no_sound_before_its_skip`), `Startup::new` only stops BGM, the earliest scene change is tic 8. Captures keep the old order, goldens are unaffected.
6. Result, `psp_main` to frame 1: 533.3 / 534.3 / 534.1 before, 412.4 / 410.9 / 410.3 after (mean 533.9 to 411.2, -122.7 ms). `start_audio` 107.3 ms and the 34.7 ms save moved to tick 2 (stdout `audio: started` then `save: wrote`). The opening scene starts at `psp_main` + 1,459 ms before and 1,447 ms after: the first picture is 123 ms sooner, boot-to-opening unchanged; tick 2 stalls about 0.16 s inside the logo scene. `Gpu::init` + pad fell 31 to 19-21 ms with the same code (cause unmeasured). PPSSPP emulated clock: 331 to 288 ms.
7. A pack of another version loaded as `ssb64.pak` stopped at a coloured placeholder screen with no text. `Pack::open` now runs before `scene_files::boot`; `BadVersion` and a non-OOM `scene_files::boot` error go to the fatal screen ("it is pack version N; this EBOOT needs version M") and `boot.log`. `ms0:/PSP/GAME/ssb64/ssb64.pak` on the test PSP is a stale 64 MB pack (Oct 9).
8. Not changed: `load_pack` `NotFound`/`Empty`/`ShortRead`/`OutOfMemory` still show the placeholder screens.

9. Link order: a rename of an impl-order symbol (`Msp_` to `Msq_`) left `psp-link.py` lines unmatched, silently, and moved the layout. `tools/psp-link.py` now matches link-order lines without impl disambiguators (`s<base62>_`) and warns on unmatched lines in timed (`11frame_timer`) builds. Stack placement of the same batch: RE-583. Hardware: boot 533.9 to about 417 ms (final patch, 3 runs 417.7 / 412.5 / 423.0).

## PSP deviation

Boot audio installs at tick 2 instead of before the first scene; no sound call is lost.
