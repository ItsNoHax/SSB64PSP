# RE-326 — Material sampling: texture ownership, palettes and the UV affine

Status: COMPLETE (ROM texel and sampling checks exact; host tests; PPSSPP goldens; PSP hardware captures of three stages)
Topics: material, animation, texture, palette, uv, pack, visual-regression, hardware
Relevant files: `tools/romtool/src/matsample.rs`, `tools/romtool/src/matcolors.rs`, `crates/ssb-rom/src/mesh.rs`, `crates/ssb-rom/src/skeleton.rs`, `crates/ssb-rom/src/pack.rs`, `psp-runtime/src/meshdraw.rs`, `tools/romtool/src/main.rs`

**Question.** RE-325 left three things open:
- whether the GE scale and offset `UvAffine` installs land on the texels the
  RDP samples;
- whether the packed textures hold the right texels;
- whether file 114's packed palette already equals `palettes[0]`.

Nothing had been checked on hardware.

## Method

`romtool matcolors` gains three checks (`matsample.rs`):

1. **Texels.** Each packed texture an entry can bind is compared with the
   `MObjSub.sprites[k]` image it stands for:
   - `textures[k]`, `next_textures[k]`, and the static texture of every
     primitive whose `MObj` sets the image.

   Index textures compare indices; direct-colour ones compare RGBA at the
   packed format's precision. The render tile's format and the baked
   mirror/mask period are not in the pack. The check tries each candidate
   and reports the one with the fewest differences. Each static CLUT under
   `PALETTE` is compared with `palettes[0]`.
2. **Tile 0.** For every packed vertex of every primitive whose `MObj` owns
   tile 0 (authored UVs, and the generated range of texgen primitives), it
   compares two texels on every frame the window moves:
   - GE: `x * scale + dim * offset`, from the runtime's own `ge_affine`.
   - RDP: `gcDrawMObjForDObj`'s live window (`s32` `uls`/`ult` in a 12-bit
     field, `gSPTexture` as `u16`), applied to the vertex the packer
     loaded at rest.

   Repeating axes compare modulo the period; clamped ones after clamping.
   Tolerance is 1/64 texel.
3. **Tile 1.** The same for the two-tile blend's second pass, whose packed
   coordinates carry tile 0's baked origin.

## Findings

1. **Display lists that replace the `MObj`'s texture still took its
   tracks.** The mesh builder carries RDP state from one display list to
   the next, including `mat_anim`, so a later node with no `MObj` call
   still named the script. The runtime swapped its texture for the
   script's sprite, cycled its palette and moved its window. Examples:
   - Mushroom Kingdom (file 107) mesh `0x43A8` loads its own brick, plank,
     grass and tree images, TLUT and tile window, yet drew the 24x25
     animated sprite of `MObjSub 0x38E8`.
   - Over all entries whose track moves:

     | State | Primitives that own it | Primitives that replaced it |
     |---|---:|---|
     | Image | 30 | 33 |
     | TLUT | 34 | 38 |
     | Tile 0 | 24 | 1 |

     Replaced state occurs in files 105, 107, 114, 117 and 138.
2. **Palette cycling was keyed by texture.** `TextureDesc::mat_anim` holds
   one entry per texture, and the last writer won. Several `MObj`s with
   different scripts share one image: Final Destination's texture 591
   serves entries 64, 65 and 66. 21 primitives in Zebes, Final Destination
   and file 117 cycled another `MObj`'s palette. The bind cache compared
   the texture index only.
3. **The affine did not match the RDP.** With the RE-301 formula, 58,900 of
   114,966 moving tile-0 samples and 10,972 of 19,200 tile-1 samples were
   more than 1/64 texel off, by up to 3.12 texels. Causes:
   - the float origin, where the RDP truncates to a quarter texel;
   - normalising by the tile width, not the uploaded GE dimension (Meta
     Crystal's 159x79 tile is uploaded 256x128);
   - applying `ScaU`/`ScaV` where the `MObj` emits no `gSPTexture`.
4. **Texels are right.** With ownership, all 145 bound textures match their
   `sprites[]` image exactly: 115 at the stored size, the rest through a
   baked mirror or mask period (Dream Land's 32-row tiles repeat twice). All
   33 owned CLUTs equal `palettes[0]`, including file 114's texture 591 for
   entries 64 and 65. RE-325's linear `PaletteID` hold therefore draws the
   same colours as the packed palette for its first 90 frames: that fix
   has no visible effect.

## Change

- `mesh::AnimTexture` records which texture state the `MObj` still owns:
  image, TLUT, tile 0 and `G_TEXTURE` scale.
  - `apply_mobj` sets each bit it emits and clears the others.
  - A list's own `G_SETTIMG`, `G_LOADTLUT` from its own palette,
    `G_SETTILESIZE` on tile 0 or `G_TEXTURE` clears the matching bit.
- Pack v35: `IMAGE_ANIM`, `PALETTE_ANIM`, `TILE0_ANIM`, `SCALE_ANIM`, with
  `PrimDesc::image_anim`/`palette_anim`.
  - The packer builds a sprite table only from a primitive drawing the
    `MObj`'s image. No primitive reached a sprite-table script before its
    owner.
  - It attaches palette cycling only under `PALETTE_ANIM`.
  - Palette sizing and the reachable-palette replay accept every live kind
    and truncate. This does not change the pack.
- The runtime resolves texture, palette and window per primitive, only for
  the state its `MObj` owns. The bind cache keys on texture and palette
  entry.
- `UvAffine` moves to `ssb_rom::skeleton` as `MaterialUv::ge_affine(dims,
  clamp)`. Per axis, with `baked` the rest origin on a clamped axis and 0 on
  a repeating one:

  ```text
  scale  = k = base_sca / sca        (1 unless the MObj owns gSPTexture)
  offset = (baked * k - (uls & 0xFFF) / 4) / uploaded_dim
  ```

  The `u16` truncation of `gSPTexture`'s scale is not modelled, because
  `unk08` is not packed. `ScaU`/`ScaV` never change in the ROM (RE-324), so
  `k` is 1 on every checked frame.

## Limits

- The texel check chooses the render format and mirror/mask layout by
  best match. An exact match over every texel is strong evidence, but the
  layout itself is not read from the display list.
- `gSPTexture`'s `u16` truncation is not modelled. No ROM script changes
  `Sca*`, so it cannot matter today.
- A primitive owning only the scale over a list's own tile origin is not
  modelled. There are none.
- `MObjSub.unk10 == 1` halving is still not modelled (RE-325).
- Effect primitives read UV windows from the stage clock, not the effect
  player's.
- The hardware captures cover three stage scenes, not the golden matrix.
