# RE-504 — Gameplay `__sinf`/`__cosf` match the ROM bit for bit; double-single fast path on the PSP

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, PRX sha256 39f824fc…; PPSSPP; host)
Topics: hardware, determinism, performance
Relevant files: `crates/ssb-engine/src/math.rs`, `crates/ssb-engine/src/math/trig_golden.rs`, `crates/ssb-rom/src/particle.rs`, `psp-runtime/src/trig_selftest.rs`, `tools/r4300/trig_hashes.py`

## Question

Does the port's sine and cosine equal libultra's `__sinf`/`__cosf`, and can the PSP afford it?

## Findings

- Original: `__sinf`/`__cosf` (ROM 0x800303f0 / 0x80035cd0) are a
  double-precision Cody-Waite reduction plus a degree-9 polynomial, rounded to
  f32 once. They are not correctly rounded: about 5% of sweep inputs differ
  from a correctly rounded sine. Edge cases: |x| < 2^-12 returns x for sin;
  |x| >= 2^28 and infinities return +0; NaN returns 0x7f810000; cosf(+-0) = 1.
- Oracle: the ROM's machine code run under `tools/r4300` gives sinf
  0x0ae64c80ba5c8ee7, cosf 0x037f84ec89add89b, sinf_angle 0x126e1fdb4372c505,
  cosf_angle 0x4b4c37df1393b4c6, Tan_angle 0x17ddb219f595dccc. Host, PPSSPP and
  the PSP-2000 match all five (0 R4300 traps).
- Port: `sinf_f64`/`cosf_f64` are an operation-for-operation f64 port. The PSP
  has no f64 hardware: 8.1 / 9.9 us per sinf / cosf (old f32 Taylor shim 1.1 us).
- Tier 2: a double-single (f32 Dekker/Knuth) fast path for |x| < 65536 falls
  back to the f64 port near rounding boundaries (2^-40 relative; 2^-20 on the
  reduction quotient). 2.7 / 2.9 us (1.8 us for |x| < 1.5) on the PSP-2000.
  Exhaustive host test over all 2^32 inputs: 0 differ; still 0 at 2^-44.
  Fallback rate about 2e-5 (sin) and 3e-5 (cos).
- PSP identity rests on f32 add/sub/mul being IEEE round-to-nearest with no
  FMA (hardware hashes `HASHES_ARITH`) and no denormal intermediates (argued,
  not measured).
- Frame cost: golden routes average up to 45 calls per frame, peak 216.
  vs4@2800: avg 23, peak 116, about 0.04 ms avg and 0.20 ms peak over the old
  shim. Tier 1 would have cost about 0.93 ms at the vs4 peak. No FPS claim.
- FCR31 restore must be one `asm!` block: with two, LLVM moved the clearing
  `add.s` out from between the `ctc1` writes and PSPLink trapped at the second
  `ctc1` ("FPU Exception (IU)"). `sqrt_selftest.rs` has the same latent pattern.
- Goldens: 4 changed and were rebaselined (r2-dream-land-water 36 px,
  f1-vs-team 28, f1-vs-shield-damage 20, f1-vs-four-magnifier 1912; the last
  mostly billboard rotate in gu.rs). Not compared with an N64 capture.

## Limits

Every `math::sin_cos` caller now takes libultra's bits, including
`gSYSinTable`-family sites that should use the table (PLAN.md).
