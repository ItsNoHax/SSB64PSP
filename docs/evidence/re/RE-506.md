# RE-506 — GU fovy and display matrices use the original's fixed-point chains

Status: COMPLETE (host and PPSSPP; matrix bits checked against the ROM's own code in tools/r4300; not hardware proof for frame time)
Topics: determinism, rendering, reverse-engineering
Relevant files: `crates/ssb-engine/src/math.rs`, `crates/ssb-rom/src/scene.rs`, `crates/ssb-rom/src/skeleton.rs`, `crates/ssb-rom/src/sector.rs`, `crates/ssb-rom/src/ground_obj.rs`, `psp-runtime/src/gu.rs`, `psp-runtime/src/movie.rs`, `tools/r4300/matrix_hashes.py`

## Question

Do the port's projection and per-node model matrices equal the matrices the original builds?

## Findings

- Every GU projection except the opening cliff is `syMatrixPerspFastF`
  (table cotangent, RE-505): `Mat4::sy_persp_fast`, loaded through
  `gu::set_projection`. The cliff camera (`nGCMatrixKindPerspF`) is exact
  `syMatrixPerspF` with libultra `cosf`/`sinf` (`Mat4::sy_persp_f`,
  `gu::set_perspective_f`); `sceGumPerspective` was already bit-identical
  there. CPU particle projections use `sy_persp_fast` too. fovy 0 is
  guarded as in `sy_persp_cot`.
- Display matrices are `syMatrixTraRotRpyRSca` / `TraRotRpyR`: angle through
  the sine table (0.088 degree steps), scale truncated to 1/256, s15.16
  words. Fighter joints use TraRotRpyRSca when scale != 1, else TraRotRpyR
  (bit-identical to the Sca chain with word 256). Stage, item, effect and
  Arwing DObjs follow their transform kinds. Ported as
  `Mat4::from_trs_display` / `from_tr_display`; the scene-graph world bake,
  `Skeleton::compose`, `StageAnimator`, `Sector` and `GroundObject` use them.
- Oracle: the ROM's `syMatrixTraRotRpyRSca` (0x8001C588) and `TraRotRpyR`
  (0x8001C21C) run in tools/r4300 over 2665 inputs; FNV-1a of the 3x3 words
  is 0x7aa61fcfd076712c and 0x9e2bb5a58a59aa47; the Rust chains match both
  (pinned test). Breaking one shift fails it.
- Gameplay never reads these matrices: hit and hurt volumes use
  `compose_collision` (RE-468); every changed compose caller is a draw path.
- Cost on a PSP-2000 (PSPLink, 100000 calls): `from_trs` 2606 ns,
  `from_trs_display` 1465 ns, `from_tr_display` 1473 ns.
- Pixels: fovy alone changed 197 of 201 goldens (14.5 M px at 960x544, most
  under 8 levels: sub-pixel texture resampling); the display chains changed
  190 (median 10392 px a scene, largest 66236). Against N64 frames of the
  opening the display change is neutral to slightly toward the N64.
  The fovy change cannot be judged by an affine-registered comparison and
  rests on bit exactness.
- The stub sine table is zeros, so display matrices are zero under
  `SSB64_STUB_TABLES`; four structural tests that need real matrices are
  ignored there.

## Limits
