# RE-385 — The Training stage select

Status: IMPLEMENTED (decomp source, host tests, PPSSPPHeadless golden captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: menu, stage, gameplay, visual-regression, psp-platform
Relevant files: `crates/ssb-game/src/stage_select.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-training-stage-select.png`

## Question

How does the original pick the Training stage, and can Training run on
any VS stage?

## Source

- `mnMapsFuncRun` (`mn/mnmaps/mnmaps.c`) runs the stage select for both
  VS and Training. It reads no input for its first 10 ticks. It returns to
  the title after five idle minutes; any held button or a stick outside
  ±20 restarts that clock (`scSubsysControllerCheckNoInputAll`).
- A or START saves the scene data and loads Training (or the VS battle).
  B saves it and goes back to the character select.
- The cursor holds one of ten slots in two rows of five
  (`mnMapsGetGroundKind`): Peach's Castle, Kongo Jungle, Hyrule Castle,
  Planet Zebes, Mushroom Kingdom; Yoshi's Island, Dream Land, Sector Z,
  Saffron City, Random.
- Up and down move by five and refuse a locked target. Left and right
  step and wrap: left from slot 0 goes to 4 (3 when Mushroom Kingdom is
  locked), and left from 5 goes to 9. Right from 3 goes to 4 (or 0), from
  4 to 0, and from 9 to 5.
- A held button repeats every 12 ticks. The stick repeats after
  `(160 − |deflection|) / 7` ticks. A neutral stick with no direction held
  clears the wait.
- `mnMapsCheckLocked` locks only Mushroom Kingdom, until
  `LBBACKUP_UNLOCK_MASK_INISHIE` is set.
- `mnMapsSaveSceneData` stores the slot's kind as `maps_training_gkind`
  (the random slot keeps 0xDE), where the cursor starts next time. It
  stores the stage to load as `gSCManagerSceneData.gkind`. The random slot
  draws `syUtilsRandTimeUCharRange(9)` (the clock's low byte) until it
  lands on an unlocked kind that differs from the last stage loaded.
- Both kinds default to Peach's Castle (`dSCManagerDefaultSceneData`).
- `sc1PTrainingModeFuncStart` spawns each player at the map object whose
  kind is the player number (`mpCollisionGetPlayerMapObjPosition`). This
  is the host's `Pack::spawn` rule on every stage.

## Implementation

- `ssb_game::stage_select` ports the cursor, the scroll wait, the lock,
  the idle return and the save, with host tests for each rule.
- `psp_runtime::scene::vs_stage_index` finds the pack stage whose
  `GR*Map` file is a given `GRKind`.
- In `psp-game`, the Training menu entry opens the stage select on the
  remembered kind. Confirming builds the stage map, the ground objects and
  the stage controller, then spawns both fighters on the chosen stage
  (`enter_training`). The random pick reads the low byte of
  `sceKernelGetSystemTimeLow`.
- The select draws ten rectangles: the cursor's slot in the selected
  colour and the locked slot dimmed. It draws no names, emblems or
  previews.
- `enter_training` moved the Training setup out of `run`, which is now
  111 KB in the release build: back inside MIPS's ±128 KB branch range
  (RE-382).

## Deviations

- The host has no save data, so Mushroom Kingdom stays locked.
- The host's menu stands in for the character select, so B returns to it.
  Re-entering Training from the menu resumes the running session without
  the select, as before.
- Every capture scene except `stageselect` skips the select and loads
  Dream Land, so the existing Training goldens are unchanged.
- The stage wallpaper (`grWallpaperMakeDecideKind`) is not drawn on any
  stage; the flat Training background shows behind the geometry.

## Verification

The `stageselect` capture opens the select at tick 8, taps D-Right at
ticks 20 and 24 (Kongo Jungle, then Hyrule Castle) and confirms at tick 30.
At tick 70, `PPSSPPHeadless --log` reports the player in `Wait` and the
dummy in `Wait`. The `f1-training-stage-select` golden shows both on
Hyrule Castle's roof, and was identical in both captures. The first try
held the default route's left stick from tick 34 and walked Mario off the
roof. The host `romtool jumptest --stage 10 --stick-x 0` trace settles
spawn 0 at (−2400, 1022) in `Wait`, which confirmed the stick as the cause.
All 93 existing goldens matched twice. Workspace tests pass with an
absolute `SSB64_ROM` and one test thread.
