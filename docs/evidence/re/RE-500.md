# RE-500 — Release-code frame timer: vs4 is vsync-bound; link orders ranked by busy time on a PSP-2000

Status: COMPLETE (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `capture_scene_file,frame_timer` builds with audio on, pack v109 by symlink beside the host0 PRX, `tools/hw-link-order.sh`)
Topics: performance, hardware, cache, link-order, methodology
Relevant files: `psp-runtime/src/frame_timer.rs`, `psp-game/link-order.txt`, `tools/hw-link-order.sh`, `tools/icache/hwrank.py`, `tools/icache/cmpaddr.py`

## Question

What frame rate does release code reach on a PSP-2000, and which searched
link order is fastest on hardware (RE-499: the model does not rank them)?

## Findings

- Release code runs `vs4@2400` at 59.32 FPS, vsync-bound (three runs within
  0.003 FPS). Sector Z 59.84, Hyrule 59.78, Saffron 59.70. The 56.5 FPS of
  the `profile` builds (RE-498, RE-499) is the spans' overhead, about 3 FPS.
- FPS cannot rank orders on vsync-bound code, so ranking used BFPS, busy-time
  FPS = 1e6 / busy, where busy = frame minus the wait for the last frame to
  be on screen. Busy: Dream Land 14.0 ms, Sector Z 13.8, Saffron 13.6,
  Hyrule 13.0 (order s3). One binary repeats within 5 us (0.024 BFPS).
- Twelve equal-model orders spread 3.4 BFPS (about 700 us busy) on Dream Land.
  The model correlation is weak: Spearman 0.45 (n=12), Pearson -0.48; the
  model-best s3 came 8th. Orders searched on the previous code's trace were
  the two slowest.
- Chosen order s7 against incumbent s3, three interleaved runs each, spans
  at most 0.08 BFPS: Dream Land +1.06 BFPS (-205 us busy), Sector Z +0.90
  (-169 us), Hyrule +1.02 (-170 us). The top three orders were the same on
  all stages, so the ranking transfers.
- Method: measurement builds keep the 312 searched functions at release
  addresses, only relocated address halves differ (`cmpaddr.py --elf`). Their
  data layout differs from release (as every capture or profile build before),
  but identically across relinks, so rankings transfer and absolute times do
  not. `stage=` must follow the scene spec line.

## Deviation

In `frame_timer` builds the vblank wait is made from the main loop before
`draw_frame` instead of inside `Gpu::begin_frame`. The feature is off by
default; a default `cargo psp --release` contains no timer code.
