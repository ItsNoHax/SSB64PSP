# RE-573 — Memory Stick small-read latency on the PSP; audio sample streaming

Status: MEASURED (64 MB Slim/Brite PSP, 6.61 ARK, PSPLink v3.2.1, 333 MHz, 4 GB MS PRO Duo, pack v136 on ms0:, scratch probe, HEAD 9d7cbd35)
Topics: memory, audio, loader, psp-1000, performance
Relevant files: `crates/ssb-engine/src/audio/stream.rs`, `psp-runtime/src/sample_stream.rs`, `crates/ssb-rom/src/audio.rs`

- ≈ 1.6 ms + 0.073 ms/KiB; lseek 9 µs; async submit 19 µs, total = sync; no read cache (replay = cold).
- Driver serializes reads; a read burns ~0.65-1.4 ms CPU; a non-reading higher-priority thread is never delayed.
- Default async priority: an async read does not progress while the caller's priority level is busy; sceIoChangeAsyncPriority(fd, 0x1E) fixes it.
- Audio thread doing 1 KiB reads: 4/block = 6.8 ms med, 9.9 ms max of a 16 ms block; 8/block or 4/block beside a 16 KiB+ loader read underruns.
- N64 (D-034, two readings): samples via syAudioDma only (audio.c:441-484, from _decodeChunk n_env.c:744-745); 16 pvoices x 4 rotating 1 KiB buffers (audio.h:9-11); never waits (OS_MESG_NOBLOCK, audio.c:1082-1085); a late DMA decodes stale bytes.
- Built (pack v137): 16 KiB pages, 48-slot LRU (786,432 B), 2 KiB resident head per wave (439 waves, 865,950 B), 8 KiB lookahead + loop-start prefetch, streamer prio 0x1E with its own descriptor (opened on the main thread: a created thread has no cwd, NOCWD 0x8002032C under PPSSPP); miss → zeros (PSP deviation).
- Host model (golden script, 1 page/frame): head 0/512/1024/1536/2048 B → 1041/146/36/8/0 misses; slots 32/48/64 → 15/0/0; 1 page per 2 frames → 87.
- Resident audio 4,428,816 → 1,941,342 B; low_free +2.21-2.47 MB on all 188 f1 goldens; PPSSPP smoke 0 misses, 0 underruns.
- Loader: background and sync reads in ≤ 64 KiB chunks; async fd at prio 0x1E.
- C: per-fighter LRU ≥ 64 KiB + pinned common set; sync miss reads; 512-aligned figatrees.
