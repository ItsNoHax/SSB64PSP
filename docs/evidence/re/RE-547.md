# RE-547 — Small `d*` arrays from the ROM: 1-ULP fireball angles, the mdust spawn angles and a 5551 fill colour

Status: COMPLETE (decomp source and US ROM SHA-1 e2929e10 through `crates/ssb-tablegen`'s `d_arrays`; host tests; golden matrix; no N64 runtime capture of the staff roll; no hardware run)
Topics: tablegen, d048, weapon, effect, staffroll, colour
Relevant files: `crates/ssb-tablegen/src/d_arrays.rs`, `crates/ssb-tablegen/src/d_arrays/game_a.rs`, `crates/ssb-tablegen/src/d_arrays/game_b.rs`, `crates/ssb-tablegen/src/d_arrays/rom.rs`, `crates/ssb-tablegen/src/d_arrays/engine.rs`, `crates/ssb-game/src/weapon.rs`, `crates/ssb-game/src/effect.rs`, `crates/ssb-game/src/spgame/staffroll.rs`, `crates/ssb-engine/src/math.rs`, `tools/docs/rom_tables.py`

## Question

[RE-546](RE-546.md) generated the large overlay `d*` tables. More than a
hundred smaller `d*` arrays (under 24 values, or cited by a doc comment) were still
committed in `ssb-game`, `ssb-rom` and `ssb-engine`: HUD positions and
colours, camera and projection defaults, fighter, item, weapon, effect and
stage constants, the `ground_obj` animation tables and the 1024-word
`dLBCommonSinLookup`. Under [D-048](../../decisions/D-048.md) they must be
read from the ROM at build time. Before each committed copy was deleted it
had to be compared with the ROM.

## Evidence

- **Generator.** `ssb-tablegen`'s `d_arrays` reads each array at its
  symbol's overlay (`source.rs` now names every code overlay, `OVL0` to
  `OVL65`, `MAIN` and `SCMANAGER`) with one element type (`U8`, `U16`,
  `U32`, `I32`, `X32`, `F32`), a shape, and for one field of a record
  array a stride. A temporary test compared every generated array with the
  committed copy (f32 by bits) before the copy was deleted. All were equal
  except the three below.
- **Fireball angles, 1 ULP.** `dWPMarioFireballWeaponAttributes` writes
  its angles as `F_CLC_DTOR32(x)`, `(float)((x * PI32) / 180.0F)`
  (`include/macros.h:42`). The port had Rust literals taken from the
  decimal in the decomp's comments (Mario's ground angle, -5 degrees;
  Luigi's rotate speed, 25 degrees). The IDO-built words in the ROM differ
  from those literals by one unit in the last place. The ROM's words are
  now used; tests and the golden matrix are unchanged.
- **Hit-spawned mdust.** `efManagerDamageSpawnMDustProcUpdate`
  (`efmanager.c:3551`) reads `dEFManagerDamageSpawnMDustAngles`, and the
  sparks read `dEFManagerDamageSpawnSparksAngles` (:3470). The port read
  the sparks table for both. The two arrays hold the same three angles in
  the US ROM, so nothing visible changes. The mdust now reads its own
  table.
- **Staff-roll text box, green one lower.** `dSCStaffrollTextBoxDisplayList`
  fills with `GPACK_FILL16(GPACK_RGBA5551(r, g, b, 1))`, and the port had
  committed the macro's 8-bit arguments. The game's framebuffer is 16-bit
  (`gSYVideoColorDepth = G_IM_SIZ_16b`, `sys/video.c:90, 155`), and
  `GPACK_FILL16` packs the colour as RGBA5551 for exactly that framebuffer,
  so each channel the RDP writes keeps only its top 5 bits. The red and
  blue arguments read back unchanged; the green argument does not survive
  the packing: its 5-bit value reads back 2 lower with the bits shifted and
  1 lower with the high bits repeated. The port now decodes the ROM's fill
  word and widens each channel by repeating its high bits, as it widens
  RGBA5551 textures and as the PSP GE widens `Psm5551`, so the box's green
  is 1 lower than before. Whether the N64's video interface shows the
  shifted or the repeated value for a flat 16-bit region was not measured:
  there is no N64 capture of the staff roll. Either way the committed
  green was not a value the N64 can display.
- **Sine table.** `dLBCommonSinLookup` was built by the compiler from a
  formula plus 14 authored exceptions (RE-470). It is now generated, so
  the exceptions are no longer committed. `lbcommon_sine_table_matches_the_rom`
  still checks every word. The camera test that asserted three of the
  words now checks the table against the rounded sine instead.
- **Check 10.** `tools/docs/rom_tables.py` also flags a const or static of
  2 or more literals whose doc names a `d*` symbol, unless it reads
  `crate::d_arrays`. This found the projection defaults
  (`dGCPerspDefault`, `dGCCObjVecDefault`, `dGMCameraPerspDefault`) and the
  shield's seed colour (`dEFManagerShieldColors[0].env`), which were still
  committed. They are now generated and equal the committed values.

## Outcome

- `d_arrays` makes 187 generated constants (one per array, or per field
  of a record array); none of their values is committed. Tests that depend on them carry the stub-ignore attribute.
- The ROM's words replace the 1-ULP fireball literals and the staff-roll
  fill colour; the mdust reads its own angles.
- `tools/docs/rom_tables_baseline.tsv` lists 62 tables that remain:
  function-local arrays (open question in `PLAN.md`), `ll*` link-time
  labels and layout, function-body constants, generated copies whose
  literals are indices, and test fixtures.
- Not covered by check 10: values in `match` arms and function bodies,
  small tables whose doc names no `d*` symbol, and struct defaults compared
  with the ROM only by a test (`Backup::default`, against
  `dSCManagerDefaultBackupData`).
