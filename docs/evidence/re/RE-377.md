# RE-377 — Captain Falcon in Training: the Falcon Kick flame

Status: IMPLEMENTED (decomp source, host tests, PPSSPPHeadless golden captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: fighter, effect, visual-regression, rendering
Relevant files: `crates/ssb-game/src/captain.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-training-captain-kick.png`

## Question

When does the Falcon Kick flame exist, and under which transforms does
its tree draw?

## Source

- `dEFManagerCaptainFalconKickEffectDesc` has flags `0x4 |
  EFFECT_FLAG_USERDATA`. `efManagerMakeEffect` builds file 350's
  `DObjDesc` tree at 0xB08 with `gcSetupCustomDObjs`. It adds the MObjSub
  table at 0x960, the transform animation at 0xB90 and the material
  animation at 0xC00. The pack already converts the tree and both
  animations as manager effect slot 29.
- The root DObj takes transform set 1: kind 0x50 (80) and `RotRpyR`. The
  child takes set 2, `TraRotRpyRSca`. Kind 80 (`func_ovl0_800C99CC`) loads
  a pure translation to the `user_data` joint's world position, so the
  root's desc translate (0, -66, -324) never applies. The child's desc
  translate (0, 66, 324) still does.
- `efManagerCaptainFalconKickMakeEffect` sets `user_data` to
  `fp->joints[23]`, `rotate.y` to `lr * DTOR(90)` and, in `SpecialAirLw`
  only, `rotate.z` to `-lr * DTOR(60)`. `syMatrixRotRpyRF` applies x, then
  y, then z, which is `ssb_rom::scene::Mat4::from_trs`'s order.
- The child's script (0xB98) animates `RotX` and the Y/Z scale, then loops
  with `SetAnim`. The material script cycles the texture ID every 2 frames.
- `ftCaptainSpecialLwUpdateEffect` runs from `ftCaptainSpecialLwProcPhysics`
  (`SpecialLw`, `SpecialLwAir`, last) and `ftCaptainSpecialAirLwProcPhysics`
  (first). With no effect attached and flag 2 at 1, it makes the flame and
  clears flag 2. With an effect attached and flag 2 at 2, it stops the
  flame and clears flag 2. Both kicks run `dCaptainMainMotion_DownSpecial`
  (the aerial script is a `Goto`), which sets flag 2 to 1 at frame 12 and
  to 2 at frame 32.
- `ftCaptainSpecialLwProcStatus` clears flags 0–3. `SpecialLwAir` is set
  with `FTSTATUS_PRESERVE_EFFECT`; every other kick status change passes
  `FTSTATUS_PRESERVE_NONE`. The update is `efManagerNoEjectProcUpdate`.

## Implementation

- `CaptainState::kick_effect` counts the flame's played frames, from 1 on
  the frame it is made. `kick_effect_air` records a `SpecialAirLw` flame.
  `captain::kick_effect_ticks` returns the count only in `SpecialLw`,
  `SpecialLwAir` or `SpecialAirLw`. The kick setters now clear script
  flags 0–3.
- `psp-game`'s `EffectVisuals` plays the tree's transform and material
  animations up to the count. Each posed node is premultiplied by
  `R(kick_effect_rotate) · T(-root desc translate)`, then drawn under
  `T(joint 23 world) · MODEL_SCALE`.
- The capture scene `captainkick` presses Down+B at tick 20 and freezes
  at tick 44, some 12 flame frames into a ground kick.

## Deviations

- Joint 23's position is read at draw time, as for the Falcon Punch flame
  (RE-376).
- No golden covers the aerial kick's Z tilt. A host test covers the
  rotation it selects.

## Verification

Host tests check that both kicks make the flame on frame 12 with one
played tick and stop it on frame 32, and check the rotation for each.
`tools/golden.sh verify --twice` matched all 84 scenes, including the new
`f1-training-captain-kick`, which was identical in both captures. In it the
flame trails behind Falcon's extended foot, brightest at the foot.
Workspace tests pass with an absolute `SSB64_ROM` and one test thread.
