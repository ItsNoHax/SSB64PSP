# RE-350 — Combat audit 2: motion scripts, per-frame hit log, reaction chains

Status: IMPLEMENTED (decomp source, host tests; no ROM, PPSSPP or hardware run)
Topics: combat, gameplay, hit resolution, motion scripts, status machine, weapons
Relevant files: `tools/gen-motion-scripts.py`, `crates/ssb-game/src/motion/`, `crates/ssb-game/src/combat.rs`, `crates/ssb-game/src/reaction.rs`, `crates/ssb-game/src/rng.rs`, `crates/ssb-game/src/attack.rs`, `crates/ssb-game/src/hurtbox.rs`, `crates/ssb-game/src/fighter.rs`, `crates/ssb-game/src/status.rs`, `crates/ssb-game/src/grab.rs`, `crates/ssb-game/src/weapon.rs`, `crates/ssb-game/src/kirby.rs`, `crates/ssb-game/src/capture_kirby.rs`, `psp-game/src/main.rs`

**Question.** After RE-349, where does combat still differ from the source
for all twelve fighters, and which gaps block a faithful match?

**Root cause.** Each fighter's attacks were hand-written `MoveData` tables
(active windows, lengths, hitboxes), and each hit was resolved the moment it
was found. The source instead runs each status's `ftMotionCommand` bytecode,
gathers a frame's hits into a log and resolves them in `ftMainProcParams`.
The tables had drifted from the figatrees (Mario's up smash lasted 16 frames
against 60) and had no rebound, shield damage (`sd`), hit-status windows or
script flags. Per-fighter code then approximated those flags with frame
windows (aerial landing lag, jab chains, Rest and PK Thunder
intangibility).

**Changes.**

| Area | Before | Source | Now |
|---|---|---|---|
| Attack data | Hand `MoveData` tables per fighter | `relocData/*MainMotion.c` bytecode (`ftMotionCommand*`), with shared `FTCommonMoveset` subroutines (relocData 201) | `tools/gen-motion-scripts.py` transcribes the motion scripts, motion descs and combat attributes of all twelve fighters plus the common moveset into `motion/scripts.rs`, validated against every `_0xNNNN` offset and file size. `crate::motion` runs them: waits, loops, subroutines (into the common moveset), goto, parallel thread, pause/resume on a looping figatree, `frame_begin` fast-forward, flags, `MakeAttackColl[Scaled]`, `SetHitStatus*`, `SetDamageColl*`. The `*_attack.rs` tables are deleted |
| Lengths | Hand frame counts | `ftAnimEndSetWait` on the figatree length | `motion::anim_length`; looping figatrees wrap in place |
| Jab chain / rapid jab | Frame thresholds | Script flag 1, `is_goto_followup`, `attack1_followup_frames`, `attack1_status_id`; `ftCommonAttack100LoopProcUpdate` | Ported for every fighter, Pikachu's self-chain and Kirby's wrapping rapid loop included |
| Hit resolution | Immediate, one hit at a time | Search every pair (clank with the damage-10 rule, group records, swept `gmCollisionTestRectangle`/`Sphere`, shield sphere, `throw_gobj`), then `ftMainProcessHitCollisionStatsMain`, then `ftMainProcParams` | `crate::combat`: `search_all`, weapons, `finish_frame`. Invincible parts register; intangible ones do not. A spat-out star never hits its Kirby |
| Hurtboxes | Root sphere for the last four fighters | `damage_coll_descs` | Kirby, Pikachu, Jigglypuff and Ness tables and egg descs added; all twelve now use joint boxes |
| Shield | Damage only | `shield_damage_total` = damage + `sd`; regen below 55 every 10 frames; break sets 30; bubble scales with health | Ported, with the break, `FuraFura` and `FuraSleep` chains |
| Weapon attributes | Element normal, `sd` 0 for every weapon; Blaster radius 40 | `WPAttributes`/`ITAttributes`: Fireballs and PK Fire fire, Charge Shot/Thunder Jolt/PK Thunder electric, Final Cutter slash; `sd` 1, Egg 6, Yoshi Star −3; radius is `size / 2` | Every weapon hitbox checked against its attributes and corrected; the Blaster radius is 20 |
| Clank / rebound | None | `attack_rebound`, `ReboundWait`/`Rebound` (US `push * 1.62 + 4`) | Ported |
| Hitlag | `damage / 3 + 5` | Electric × 1.5, crouch × 2/3, buffered taps, knockback stacking; `proc_hit` only when `attack_damage != 0` | Ported; taps during hitlag carry to the lag-end frame |
| Elements | Sleep as a flag | Sleep leaves the current status for `FuraSleep`, electric detours through `DamageE1/E2` | Both in `ftCommonDamageGotoDamageStatus`'s branches |
| `damage_resist` | Kirby-only side check | `ftMainCheckGetUpdateDamage` soaks the hit and passes only the overflow to `damage_queue` | In the pipeline (Stone) |
| Knockdown / tech / roll | None | `DownBounce` → `DownWait` → stand/roll/attack; tech within 20 frames of Z; `EscapeF/B` from guard, dash and Samus's charge loop | `crate::reaction` |
| RNG | None | Shared LCG (`syUtilsRandFloat`, seed 1, `× 214013 + 2531011`) | `crate::rng`: `DamageFlyRoll` and Kirby's 1-in-12 copy loss on a tumble (`ftKirbySpecialNDamageCheckLoseCopy`, `is_allow_losecopy` per caller) |
| Smash DI | Frozen fighters skipped map processing | `ftCommonDamageCommonProcLagUpdate`: a fresh tilt ≥ 53 moves the fighter stick × 2.1 once, through map collision | Through the shared map solver during hitlag |
| Aerial landing | Per-fighter frame windows | Flag 1 is the landing-lag speed; Z within 10 frames smooth-lands; `vel_y > -20` skips landing; no `LandingAirX` → `LandingAirNull` | One script-driven path for all fighters; Mario's down air lands through `LandingAirNull` |
| Guard | Instant `GuardOn` | Clip lengths, `GuardSetOff` push, guard jump/pass/roll/grab out | Ported; the `GuardSetOff` push sign was inverted |
| Giant Punch | Charge applied at hit time | `ftDonkeySpecialNEndProcUpdate` (and Kirby's copy) add `charge * 2` to new collisions | Ported for both |
| Catch search | Invincibility only | `ftMainSearchFighterCatch` skips any non-normal body status and intangible/invincible parts | Ported |

**PSP frame order.** `psp-game` Training runs the source's process
priorities after both fighters tick: catch search, fighter hit search,
weapon hits, then `ProcParams` for both fighters.

**Provenance.** The bytecode, motion descs, hurtbox tables and attributes
are transcribed from the decomp's C source text, the material the removed
hand tables were transcribed from. No ROM bytes are read or committed.

**Not changed.**
- The pack has no clips for the reaction statuses (Escape, Down, Passive,
  ShieldBreak, FuraFura, Rebound); root motion for rolls and techs comes
  from those clips. Adding slots changes the pack layout.
- Damage map callbacks (`WallDamage`, `StopCeil`, `DownBounceD`) and
  `DamageFall` ledge catch.
- Weapon–attack clank, reflector and absorb collisions as attack
  collisions, items, and the one-frame invincibility after a knockback
  overrun.
- The catcher's branches that read the held partner's same-frame
  `damage_knockback`.
- Pikachu's Thunder head stays harmless, as RE-345 ported it.

**Verification.** 449 `ssb-game` host tests, 1,108 across the workspace:
jab chaining on flag 1, script hitboxes and intangibility, every script
runs to completion, the star's damage and thrower exclusion, clank and
rebound, shield regen and break chain, tech windows, tumble landings,
FlyRoll, copy loss, Stone's overflow, Sing's sleep, Smash DI, hitlag tap
buffering, aerial landing and Z-cancel for the new fighters, Giant Punch
charge damage. Clippy (`-D warnings`), rustfmt and the `no_std` build pass;
both PSP builds pass, `psp-game` also with `strict_render`. No PPSSPP smoke
test: the environment has no ROM, pack or PPSSPP.
