# RE-011 — Level of detail selection

Status: COMPLETE
Topics: camera, rendering

## Question

- `DObjDistDL` / `DObjDistDLLink` pick a display list by `sGCDetailLevel`. How is the tier chosen; should the PSP force one?

## Findings

1. `sGCDetailLevel` (`objdisplay.c:59`) is zero-initialised `.bss`.
2. Writers (distance-from-eye loops over `DObjDistDL` / `DObjDistDLLink` tables): `objdisplay.c:1823`, `:2002`, `:2306`, `:2466`, all inside `unref_80014A84`, `unref_80014FFC`, `unref_80015A58`, `unref_80015F6C`.
3. Readers: `dls[sGCDetailLevel]` / `multi_list[sGCDetailLevel]` at `objdisplay.c:1776`, `:1911`, `:2250`, `:2370`, also in `unref_*` display callbacks.
4. No caller: the six `unref_800147E0`…`unref_80015F6C` names and addresses appear only in `objdisplay.c/.h` and the symbol lists (`rg` over the decomp tree, two independent readings, D-034). No `dist_dl` / `dist_dl_link` is assigned outside `objdisplay.*`.
5. Shipped game: the level is always 0; the distance LOD path never runs. Not player count or options.

## Port

- No distance-LOD code; one display list per node = tier 0. Equal to the original.
- `ssb_rom::skeleton::resolve_lod_blend` and `meshdraw/batch/lod.rs` are the unrelated `G_TEXTURE` LOD blend.
- No tier for the PSP to force: not a performance lever.
