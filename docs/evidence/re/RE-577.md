# RE-577 — Link-order names independent of crate hashes; vs4 order re-searched; box guard test rejected

Status: MEASURED (64 MB Slim, 6.61 ARK, PSPLink v3.2.1, 333 MHz, pack v137 on ms0:)
Topics: performance, hardware, link-order, clipping
Relevant files: `tools/psp-link.py`, `tools/icache/cmpaddr.py`, `tools/icache/order.py`, `tools/icache/layout.c`, `psp-game/link-order.txt`

## Findings

1. v0 back-references (`B<base62>_`) are byte offsets into the mangled name. They move with the crate-hash lengths, which change with the feature set and the checkout path. `stable()` stripped the hashes but kept the offsets, so generic or nested names in `link-order.txt` matched only builds with the searched build's hash lengths.
   - 78 of 372 entries were unmatched in the release layout.
   - HEAD frame_timer build: missed `map::edge` and `project_floor_line`.
   - Another checkout path: missed 7 names (~16.7 KB).
   - `stable()` now re-encodes back-references into the hash-free name. All 1,954 v0 names demangle to the original minus hashes; 0 collisions; release layout unchanged.
2. Same code, matching fixed only: vs4 19.87 to 19.61 ms, 1P intro 24.95 to 22.96. Earlier frame_timer builds did not have the release layout.
3. Order re-searched (RE-494, 6 seeds x 90,000 iterations, vs4 traces at 20 s and 32 s; seed 5 shipped, 357 names): model misses 474,603 to 336,376 (-27%). 347 of 357 names at release addresses in the frame_timer build (HEAD order: 57 of 289).
4. Hardware, busy ms, HEAD to new, 2 runs each:

| Scene | HEAD | New |
|---|---:|---:|
| vs4@2400 | 19.87 | 18.20 |
| Zebes | 13.25 | 12.46 |
| 1P intro | 24.95 | 19.58 |
| 1P battle | 19.45 | 17.51 |
| Opening Room / Run / Yoster / Clash | 13.76 / 15.68 / 13.22 / 12.87 | 13.08 / 13.55 / 11.96 / 11.17 |
| Opening 1-39 | 10.20 | 9.48 |

   Seeds 2, 3, 6 within 0.12 ms of seed 5. FPS vs4 44.2 to 50.3.
5. Negative result: per-mesh bounding-box guard test (VFPU, cached bounds, per-vertex fallback, identical output): vs4 +0.43 to +0.84 ms, Zebes +0.30 to +0.63 ms. Box costs 0.24-0.37 ms; the per-vertex test it skips costs 0.21-0.41 ms (~7 vertices per mesh). Reverted.
6. Guard-band clip: vs4 test 0.63 ms + sub-triangle 0.31 ms; Zebes 0.59 + 0.78 ms.
7. Single-entry order edits move vs4 -0.34 to +0.60 ms depending on the rest: noise-level; only a full re-search is a lever.

- `cmpaddr.py --elf` release vs frame_timer relink: entries at different or missing addresses mean stale names; re-search after hot-code changes.

## Conclusion

Shipped: canonical link names and the new order. vs4 is 1.5 ms above 16.7. PPSSPP goldens unchanged (layout only).
