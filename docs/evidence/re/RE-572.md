## Question

Why does peak use (18.8-20.6 MB) exceed the ~18 MB free on a PSP-1000, and which N64 residency rules close the gap?

## Pack vs N64 bytes

- VS select + maps: texture storage 6.76 MB vs 3.77 MB ideal N64 level-0 (pow2 padding, 5551 wallpapers at 512x256, mip chains, costume duplicates); vertex 20 B vs 16 B (~0.22 MB).
- Animation scripts held for every action: 4.7 MB in Zako, 3.6 MB in clash.
- Resident region holds matanim files 1.24 MB and AnimJoint/AnimDesc tables 1.4 MB; the N64 keeps these inside per-scene files.

## Addendum: N64 Maps loading, step B

Two readings of `mnmaps.c` agree (D-034).

| Step | Code | Loads |
|---|---|---|
| Scene start | `mnMapsFuncStart` 1624-1660 | 5 listed files (`dMNMapsFileIDs`) |
| Model heaps | `mnMapsAllocModelHeaps` 148-165 | 2 heaps, each the largest map-file closure |
| First preview | `mnMapsMakePreview` 1660 | cursor stage's map file + externs |
| Cursor move | `mnMapsFuncRun`, `mnMapsLoadMapFile` 876 | one map file into the other heap (ping-pong), old preview destroyed |
| Random slot 0xDE | same | nothing |
| Training | `mnMapsMakePreviewWallpaper` | one wallpaper file per stage (`dMNMapsTrainingModeWallpaperIDs`) |
| Timing | `syDmaCopy` | synchronous blocking DMA in the update |

- Prefetch rule: prefetch what the next scene's FuncStart loads; never what it loads later on input.
- PSP: `scene_load::maps_preview` swaps via `enter_within`; old preview Leaving, freed at the safe point.
- PPSSPP preview load (emulated I/O): 237 KB 2.4 ms; 1.07 MB 11.8 ms. Hardware latency pending.


## Addendum: figatrees streamed per status, step C

Two readings agree (D-034): `ftMainSetStatus` ftmain.c:4613-4626 and `lbRelocGetForceExternHeapFile` lbreloc.c:363-369 reload the figatree on every status change into a heap of the kind's largest figatree (`ftmanager.c:364`).

| Part | Port |
|---|---|
| Pool | `crates/ssb-rom/src/stream_pool.rs`: fixed slab, first fit, 64 B entries, LRU by `Epoch`; never evicts an entry used this frame |
| Pinned set | 20 slots from `SLOT_DASH` (`PINNED_CLIP_SLOTS`), held per scene, never re-read |
| Slab | one 64 KiB slab per anim kind, lazy, shared by same-kind players |
| Read | synchronous, from the 512 B sector before the file (no pack change) |
| Scenes | `battle` and `opening` stream; presentation scenes (1P intro, challenger, clear, ending, results, continue) do not: a slab costs more than their clips |

Deviations: per-kind slab with LRU instead of per-fighter single heap; pinned set never re-read; sector-superset read; a miss may wait behind one 64 KiB background chunk; presentation scenes not streamed.

- Per kind: 282,736-468,880 B before; pinned 24,112-49,824 B plus a 64 KiB slab after.
- `low_free`: 183 of 197 rows higher, median +292,096 B, max +3,658,240 B. Lowest row 38,052,352 B (f1-vs-results-link).
- 14 non-streaming rows lower by 4,864 B = code size (equals the boot free drop); accepted.
- Misses (PPSSPP): max 4 a frame in battle (f1-cpufx), 8 on the opening's first frame; total up to 43 a run; evictions 0, failures 0; longest read 2,266 us; slab peak 512 KiB.
- Test `crates/ssb-rom/tests/figatree_stream.rs`: 1,773,732 poses bit-identical through 64 KiB slabs.
- Hardware pending: miss latency (RE-573 ~3 ms a miss; several a frame may drop a frame).

## Addendum: PSP-1000 budget and ballast check

| Term | Bytes |
|---|---:|
| User partition (32 MiB model) | 25,165,824 |
| usersystemlib + release image + 512 KiB stack | 5,912,832 |
| Firmware overhead (PSP-2000 6.61 ARK: RE-535 PSPLink vs PPSSPP model, 56 MiB partition) | 1,302,272 |

- PPSSPP model = partition - 16 KiB - image (256 B blocks) - stack; equals golden `boot_free` to the byte.
- `tools/golden.sh verify --ballast 18000000` and `17500000`: 266 of 266 match; lowest `low_free` 3,582,976 / 3,083,008 (f1-training-fighter-select); median 6,611,456 at 18 MB. Failures begin at 15.0-15.1 MB.

- Under the 6 MiB prefetch margin 15 rows load the next scene at entry (pixels identical).
