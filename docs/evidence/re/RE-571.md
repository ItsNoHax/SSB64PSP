# RE-571 — Runtime loader: pack needs no slot patching; per-run blocks beat one block per scene

Status: IMPLEMENTED (host audit and simulation; runtime not yet switched to `reloc_link`; physical PSP not needed)
Topics: memory, loader, pack, performance
Relevant files: `crates/ssb-rom/src/reloc_link.rs`, `crates/ssb-rom/src/reloc_link_pack_tests.rs`, `crates/ssb-rom/src/reloc_link_sim_tests.rs`

## Question

Does the pack need runtime patching of extern slots, and is one block per scene better than one block per read run?

## Slot audit (pack v136)

- `relayout` moves chunks unchanged, so a chunk holds no absolute address. Only animation-script chunks and mat-anim files carry raw `relocData` bytes.
- `pack_readers_never_reach_an_extern_slot` walks every consumer's roots (AnimJoint scripts, sector descriptors, pilot anims, laser/flare scripts, training layout, mat-anim scripts) over each `AObjEvent32` path, including Jump/SetAnim targets and `SYInterpDesc`.

| Item | Count |
|---|---:|
| Unique chunks | 1949 |
| Matched to their source file | 1917 |
| Converter-built chunks | 32 |
| Chunks with extern slots | 40 |
| Extern slots in them | 1008 |
| Slots any reader reaches | 0 |
| Walk errors | 0 |

- Limit: opcode semantics are those of the Rust interpreters (opcodes 0-15, 18-22).
- Result: no runtime patch slots; D-011 stands as placement only.

## Policy simulation

- Model: `scene_files` (keep transitions, prefetch, safe point, run grouping) over `scene_load.rs` root lists, 109 loads (startup, openings, title, VS, 1P, Training, bonus). Assumes background reads finish before the next event; kernel granularity ignored. Bytes are 64-padded block sizes.

| Policy | Peak scene-block bytes | Delta | Loads above today (of 109) | Copy bytes total / largest per load | Reads |
|---|---:|---:|---:|---:|---:|
| Today: per-run blocks | 11,669,440 | - | - | 0 | 861 |
| One block per load, pin | 18,404,608 | +6,735,168 (+58%) | 85 | 0 | 861 |
| Copy every kept file | 17,058,560 | +5,389,120 | 96 | 200,978,062 / 6,121,930 | 861 |
| Copy from part-dead blocks | 14,545,600 | +2,876,160 | 57 | 27,184,402 / 4,299,490 | 861 |

- Calibration: 11.67 MB plus the 5.5 MB resident region is about RE-475's VS results 17.0 MB.
- Decision: per-run blocks stay. Copy policies move 4.3-6.1 MB per load (43-61 ms at 100 MB/s).
- `PREFETCH_MARGIN` would not bind under either policy at the 47,891,712 B XMB budget.

## Loader API

- `reloc_link::{closure, place_into, Placement, Order, FileSource, link_into}`: `Order::Original` equals `layout`/`alloc_size` (RE-341); `Order::Ascending { max_run }` equals `load_missing`'s run grouping, 64-byte aligned.
- Pack-level tests prove closure, order and run equality for 63 root lists.

## L3 landed (batch 65)

- `scene_files` on `reloc_link::closure` + `place_runs` (Ascending, MAX_RUN 4 MiB, MAX_BACKGROUND_RUN 1 MiB, queued files held); blocks from `ssb_engine::memory::AssetArena`.
- Host equivalence vs the replaced loader over the real pack: 8 heap/IO configs x 352 steps, identical reports, reads, spans, block groups, heap bytes.
- PPSSPP: goldens match, `memory.tsv` held/blocks/demand/peak identical, `Report::micros` 336 = 336; peak 20,555,520 B (f1-vs-players) unchanged.
- Deviations: static image +2,304 B; one 256 KiB heap chunk timing shift in Room ticks 780-1590 (not an asset block).
- PPSSPP headless `cpu_us` is deterministic per binary but scheduling-dominated; cannot rank this change. Host bench: enter -3%, prefetch +1.4%.
