# RE-359 — Tile-relative mirror phase restores Mario and Luigi's buttons

Status: IMPLEMENTED (US ROM, RDP reference, host regression and PPSSPP software; no physical PSP)
Topics: texture, geometry, fighter, pack, rendering, visual-regression
Relevant files: `crates/ssb-rom/src/{mesh,psp_texture,skeleton,n64_addressing,pack}.rs`, `tools/romtool/src/{main,filter_coverage,matsample}.rs`

## Question and evidence

Mario and Luigi have plain overall bibs in the fighter goldens, while the
user's reference and the existing original-game emulator capture
`re276-mario-training-closeup.png` (removed; git history)
show Mario's yellow button. RE-283's old closure was incorrect: a tile
origin changes texture coordinates, not the source image's starting row.
Luigi was not independently investigated there.

The authoritative graph conversion resolves each torso's material and ROM
commands, including the segment-0x0E palette call:

| Fighter | Model file / graph | Torso node / list | Texture / palette | Scale S/T | Tile window S/T (quarter texels) |
|---|---|---|---|---|---|
| Mario | 296 / `0x2200` | 2 / `0x1668` | `0x65F0` / `0x65C8` | 65535 / 39960 | 128..380 / 32..124 |
| Luigi | 323 / `0x2410` | 2 / `0x1830` | `0x6D38` / `0x6D10` | 65535 / 54613 | 128..380 / 39..131 |

Both use CI4, a 32x24 image, 32-texel row pitch, a 32-texel S mask,
mirrored repeating S and clamped T. Both load the image with
`G_LOADBLOCK uls=ult=0`. The tile's S origin is one mirror period, 32
texels. Keeping absolute S flips which half of the mirror pair is sampled.

[`angrylion-rdp-plus`'s texture pipeline](https://github.com/ata4/angrylion-rdp-plus/blob/master/src/core/n64video/rdp/tex.c#L157-L176)
subtracts `TRELATIVE` on both axes before clamp and mask/mirror. The
existing `n64_addressing::address_axis` already models that unconditionally;
RE-152's mesh conversion had restricted it to clamped axes. The source
port references SSB's `gcDrawMObjForDObj` in
`refs/ssb-decomp-re/src/sys/objdisplay.c:1374–1419` for material window
and scale commands.

For Mario's front corner at `[-39,-1,71]`, load-scaled S=850 becomes
850-1024=-174 S10.5. Mask/mirror selects source column 5; T=156 selects row
4. The raw palette decodes that texel to `[247,222,0,255]`, the button.
The old S selects column 26 instead. Luigi's corresponding front corner
`[-24,58,61]` changes from S=894 to -130, with T=435.

## Implementation and pack attribution

Authored UV conversion subtracts the tile origin on both axes. Linear and
regular texgen, texgen filter coverage and the material animation affine
use the same basis. Live animation restores the rest origin before applying
the live scale and subtracting the live origin, regardless of wrap mode.
The independent material checker uses that packed coordinate basis too.
No fighter-specific rendering override or texture change is added.

The pack remains v43 and **25,288,432 bytes**; SHA-256:
`b83c6d37131e0e88de51a4c02d163c93c2db4bc93a1d4bc905b049e33e84098f`.

A byte comparison against the RE-358 pack attributes every changed byte to
UVs: 567 vertices in 30 meshes. Mesh descriptors, positions, normals,
colours, indices, bindings, all 1,881 texture descriptors, texels and
palettes are unchanged. Changed source lists, including costume variants:

|---|---|---:|

Generated packs and scratch diagnostic scripts are not committed.

## Verification and visual attribution

- The ROM regression pins both front-corner UVs, checks mirrored addressing
  against the RDP model and confirms Mario's raw yellow texel.
- Synthetic texgen cases cover a fractional repeating origin and a
  one-period mirrored origin; material animation checks both clamp and repeat.
- A control pack changes only S by -1024 in the old pack's two high-detail
  torso lists, including costume meshes. Its Mario and Luigi captures are
  byte-identical to the rebuilt pack's corresponding captures.
- The **old pack with the new runtime reproduces all 73 old goldens twice**.
  This isolates the visible changes to packed UVs, rather than runtime state.
- All 41 changed scenes are visually reviewed; every repeat differs by zero
  pixels. Mario/Luigi regain buttons and authored straps. DK's 476 changed
  pixels are confined to his head texture. The other changes are on Mario's
  torso in stage views and on the Mario models in Training.
- After rebaseline, **73/73 goldens match twice**. Training captures provide
  the integration smoke. Both PSP release builds pass and interactive
  outputs are restored. Existing viewer warnings remain.
- Strict pack check: zero unresolved. Material sampling: 114,966 moving,
  358 rest and 19,200 tile-1 axis samples, zero discrepancies above 1/64 texel.
  All 145 checked source texture variants and 33 static CLUTs match.
- Host workspace, formatting, Clippy and no_std results are recorded in
  [STATUS.md](../../../STATUS.md). No new physical-PSP or original-N64 run.

## Conclusion

The missing buttons were a porting bug in repeat-axis origin lowering.
RE-283's dismissal is superseded. Both fighters are fixed from their own
ROM data, without changing assets or guessing materials.
