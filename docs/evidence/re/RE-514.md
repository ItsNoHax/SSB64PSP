# RE-514 — Fighter vertex lighting from SSB's F3DEX2 microcode, and the fighter shadow regression

Status: COMPLETE, verified against an LLE RSP (cxd4) on 768 vertices
Topics: rendering, lighting, fighters, shadows, performance
Relevant files: `crates/ssb-engine/src/rsp_light.rs`, `psp-runtime/src/meshdraw.rs`, `crates/ssb-game/src/shadow.rs`

## Question

Why were PSP fighter highlights paler than the N64 (Kirby, RE-513), and why did the shadow under the feet differ?

## Findings

- Ground truth method: SSB's own microcode (F3DEX2 2.04H) was run on the cxd4 LLE RSP with crafted `G_MTX`, `gSPNumLights`, `gSPLight`, `G_MW_LIGHTCOL` and `G_VTX` lists. 24 matrices (identity, rotations at scale 0.5, 1, 1.37, 2) times 32 normals = 768 vertices. The Rust model matches 768/768 bytes (RGB and alpha).
- The light direction is normalised: `continue_light_dir_xfrm` transforms it by the 3x3 of the modelview (s15.16), normalises with the VRSQ table and stores s8. The hypothesis that lighting uses a 100/127 factor is rejected; a uniform matrix scale cancels.
- Vertex shade: `S = n.d` (s8 x s8); `dot16 = S <= 0 ? 0 : min(2S, 0x7FFF)`; `shade = min(0x7FFF, (amb*32767 + col*dot16 + 128) >> 8) >> 7` per channel. The channel saturates at 255 before the combiner, so PRIM x SHADE cannot exceed PRIM: highlights are flat PRIM. Combiner `(p*s + 0x80) >> 8` makes 255 x 255 = 254. The GE cannot clamp before the PRIM multiply, which caused the pale highlights.
- Skinned (borrowed) vertices are lit in their source joint's space, as the RSP does; the GE used the current joint's transform.
- Implementation: GE lighting is unused for packed meshes. `meshdraw` lights each vertex on the CPU through `rsp_light` (`lit_rgb`); skinned meshes store dot16 in the vertex tail padding.
- Shadow: not geometry. Since RE-487 the node path uploads model matrices with `sceGuSetMatrix` behind gum's back, so `draw_fighter_shadow` reused the last stage node's matrix and drew off screen. It now loads identity first. The source also has no depth test (`dFTShadowNoPrevLinkDL` clears `G_ZBUFFER`; `G_RM_AA_XLU_SURF` has no `Z_CMP`); RE-302's "depth test on" is corrected.
- Perf (PPSSPP, `vs4@2400`, `profile`): CPU 5200-5375 to 6820-7014 us per frame (+1.6 ms); `dfighters` 1385 to 2940 us. Cause: lit primitives now take `expand_corners`. Not measured on a physical PSP.

## Consequences

- Correction (RE-516): the 768/768 match held on the host only. On the PSP the node matrices carry MODEL_SCALE, so the light rows were saturated until RE-516's `light_rows` fix.

- Deviations: lit vertex alpha keeps the packed alpha (N64 255 becomes 254, at most 1 LSB); the float modelview is quantised to s15.16 before the direction transform (rare +-1 LSB in the s8 direction).
- Goldens rebaselined: every lit fighter row, skinned borrowed vertices, restored shadows, animated stage/item light primitives.
