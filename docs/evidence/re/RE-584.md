# RE-584 — Anim-less display effects rebuilt a 23 KB animator per frame; `.rodata` line pinned (batches 93, 94)

Status: MEASURED (PSP-2000 hardware, PPSSPP, host tests)
Topics: performance, effect, boss, d-cache, hardware
Relevant files: `crates/ssb-rom/src/skeleton.rs`, `psp-game/src/main.rs`, `psp-runtime/src/boss.rs`, `tools/psp-link.py`

## Findings

1. Every electric hit (fighter, weapon or item element Electric: `ftmain.c:2719/2774/2811`; colanim `ftcommondamage.c:369`) spawns ShockSmall displays: life 20 (`efManagerVelAddDestroyAnimEnd`; mat anim 0x1570 in file 0x54, ROM replay = 20), no AnimJoint. The Master Hand Fall wallpaper (ticks 1166-1466) runs anim-less display effects too.
2. Cause: `draw_one_display` assigned `StageAnimator::new()` (23 KB, `MAX_STAGE_JOINTS` 64) per anim-less display per frame (RE-469 pattern).
3. Fix: `StageAnimator::clear()` (count 0, `gobj_frame` 0); every reader stops at count; host test `stage_animator_clear_reads_as_new`. Boss effects read node parents once at the make (`Visual::parents`). Pixel-identical: goldens 268 of 268, twice.
4. PPSSPP: shocked frames -1.8 / -5.0 ms CPU; Fall window -16% game samples.

6. Left: 4xL9 Pikachu, no hit, 17.3-18.0 ms; shocked 19-20 ms; boss comets and Fall 17.3-19.9 ms (effect CPU skinning, material replay from frame 0: RE-415).
7. `.rodata` line offset: the `.bss` pad (RE-580) works in whole lines, so `.rodata` and `.data` sat at code size mod 64. The fix shrank code, moved them +16 B in their line: 1P intro +0.05-0.07 ms, battle +0.03 ms. Hot code was unchanged, stack unchanged.
8. Rule: `tools/psp-link.py` pins `.rodata` at line offset `RODATA_LINE` = 0x00 and `.bss` at `BSS_SET` 0x1d00 (up to 63 B more pad; no `low_free` change at 256 B granularity). Re-screen with `PSP_LINK_RODATA_LINE` and `relink.py` when the data layout changes a lot.
