# RE-403 — The fighters' entry effects

Status: IMPLEMENTED (decomp source, pack probe, host test, PPSSPPHeadless goldens captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: fighter, effect, animation, match, visual-regression
Relevant files: `crates/ssb-game/src/{appear,appear_tests,fighter}.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`

## Question

VS fighters enter through their Appear clips (RE-402), but the effects
`ftCommonAppearSetStatus` starts with each entry are missing. Which
effect belongs to which fighter, and how is each placed and ended?

## Source

- **The makers.** `ftCommonAppearSetStatus` calls one maker per fighter
  (`src/ef/efmanager.c`):
  - Mario and Luigi: `efManagerMarioEntryDokanMakeEffect`, which swaps
    `file_head` to `gFTDataLuigiSpecial2` for Luigi;
  - Fox: the Arwing; Donkey Kong: the barrel (`...DonkeyEntryTaru...`);
  - Samus: the capsule (`...SamusEntryPoint...`);
  - Link: the wave and the beam, two effects;
  - Yoshi: the egg; Kirby: the star, whose `AnimJoint` is the `R` or `L`
    table by `lr`;
  - Pikachu and Jigglypuff: the thrown Poké Ball; Captain Falcon: the car;
  - Ness makes none.
- **Placement.** Each maker sets the effect's first DObj translation to
  the entry position (`dobj->translate.vec.f = *pos`). With flag `0x4`
  and without `0x1`, `efManagerMakeEffect` builds the desc's own tree, so
  the first DObj is the desc's root.
- **Playback.** Every one of the listed effects plays its `AnimJoint` and
  `MatAnimJoint` with `gcPlayAnimAll`.
  - The pipe, barrel, capsule, egg and star use
    `efManagerHaveStructProcUpdate`, which ejects the effect once
    `anim_frame` drops to zero or below (the table's end).
  - Link's wave and beam run plain `gcPlayAnimAll`, and nothing ejects
    them. A later probe (RE-405) found that their tables do not reach an
    end within 5,000 ticks, so the port keeps drawing them as the source
    keeps running them. Their look after the entry was not checked.
- **The Arwing, the Poké Ball and the car** run their own updates (paths,
  a throw and a drive) and need their own port.

## Pack probe

A probe (removed afterwards) read each packed object and its effect
animation:

| Effect | Key | Nodes | Root rest translate | Animated nodes |
|---|---|---:|---|---|
| Pipe | (356, 0x608) | 3 | 0 | 1, 2 |
| Barrel | (355, 0x7C8) | 2 | 0 | 1 |
| Capsule | (349, 0xB90) | 3 | 0 | 1 |
| Wave | (353, 0x3F8) | 2 | 0 | 0 |
| Beam | (353, 0x7B8) | 2 | 0 | 0 |
| Egg | (354, 0x530) | 1 | 0 | 0 |
| Star (L) | (348, 0x1DA8) | 2 | 0 | 0, 1 |

Every root rests at the origin, so placing the root at the entry position
matches `translate = *pos`.

## Implementation

- **`ssb_game::appear`.**
  - `EntryEffect` and `entry_effect(kind)` map the fighters to the
    makers.
  - `Entry::effect_ticks` counts the frames since the entry started. It
    is set to 0 by `appear_set_status` and advanced by
    `tick_effect_clock` in the fighter's physics slot. The clock keeps
    running after the fighter stands, as the effect outlives the clip.
- **`psp-runtime`.** `ENTRY_EFFECT_KEYS`, `entry_effect_parts(fighter)`
  and `manager_effect(pack, key)` resolve each part's object and its
  animation from `MANAGER_EFFECT_KEYS`.
- **`psp-game`.**
  - `EffectVisuals::sync_entry` catches each fighter's parts up to
    `effect_ticks`, restarting on a new entry.
  - `draw_entry_effects` draws each part at the entry position until its
    animator ends. It draws for both the player and the dummy.

## Deviations

- **Not drawn.** Fox's Arwing, the Poké Ball and its rays, and Captain
  Falcon's car.
- **Luigi's pipe** comes from his own file, which is not packed, so
  Luigi draws none.
- **Kirby's rightward star** needs `llKirbySpecial2EntryStarRAnimJoint`,
  which is not packed. Only a leftward entry draws the star.
- **Root translation tracks.** If a root-animated effect (the wave, the
  beam, the egg or the star) also animates its root's translation, the
  original's next `gcPlayAnimAll` would overwrite the entry position; the
  port keeps the position. The tracks' kinds were not dumped.

## Verification

- **Test.** `the_entry_effect_clock_starts_with_the_entry`: the clock is
  `None` before the entry, 0 at it, and counts on.
- **Goldens.** `f1-vs-countdown` was rebaselined, captured twice. It shows
  Mario's pipe under the player on the ground and a second pipe on the
  left platform under the CPU, who has not risen yet. 106 of 106 goldens
  match.
- **Gates.** Workspace tests, Clippy and both PSP builds pass. The release
  `run` is 107,232 bytes.

## Conclusion

The pipe, barrel, capsule, wave, beam, egg and leftward star now play at
each fighter's entry. The Arwing, the car, the Poké Ball, Luigi's pipe and
Kirby's rightward star remain.
