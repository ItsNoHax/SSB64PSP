# RE-331 — Grab golden model below Dream Land platform

Status: COMPLETE (decomp motion descriptors, ROM figatree, 69 PPSSPP goldens twice)
Topics: fighter, animation, grab, rendering, asset-pipeline, visual-regression
Relevant files: `tools/gen-anim-table.py`, `tools/romtool/src/main.rs`, `psp-runtime/src/scene.rs`, `tests/golden/f1-training-grab.png`

**Symptom.** The first `f1-training-grab` golden in RE-330 showed Mario and
his held dummy below Dream Land's left platform. The scripted jump route was
correct: `romtool jumptest` kept Mario at x -1253.1, y 904 on that platform
through the catch. PPSSPP frames at ticks 107 and 114 stood on the platform;
the model sank during `CatchPull` at tick 116.

**Cause.** Mario's `CatchPull` file 562 has 25 figatree entries but only 24
enabled model parts. The packer assumed the spare entry was a *leading*
runtime joint and bound script 1 to the model root. `ftdata.c` gives this
motion flag `0x10000000`, with no TransN/XRotN/YRotN joint. The extra entry
is instead an unbound trailing model part. Script 1 sets root Y to 0 while
the model's rest root is Y 150; the mistaken binding moved the visible
fighter below his collision root. The held fighter had a second problem:
Mario's `CapturePulled` *does* have a leading runtime joint. Its script 0
translates Y 210 while model-root script 1 translates Y -60. The renderer
discarded script 0 and drew the held model 210 units too low. The
`joint_itemheavy_id` is an `FTStruct::joints` index; the four runtime joints
precede the packed DObjDesc nodes (`ftmanager.c`), so treating it as a
skeleton animation index also sampled the wrong attachment point.

**Correction.** The generated animation table records each motion's runtime
joint flag from `FTMotionDesc.anim_desc`, and the packer shifts script
bindings only when the flag and table length both require it. The PSP
bridge maps the heavy-item joint ID to its packed model part and composes
the held pose with its runtime-joint transform. This fixes the rendering
while leaving the portable gameplay position and floor collision intact.

**Verification.** `romtool anims --verify` agrees on all 414 finite lengths;
901 workspace tests and both PSP builds pass. The rebuilt v36 pack is
22,446,048 bytes, SHA-256
`b5c86c5efe53030626fac4629561140da0d8596f4c39542ec07173c4ae5e6686`.
The corrected grab image visibly has both fighters on the left platform.
Rebaselining changed 8,936 pixels and two captures were identical. All 69
PPSSPP software goldens then matched twice. PPSSPP remains separate from
physical-PSP validation.
