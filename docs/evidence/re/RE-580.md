# RE-580 — In-place battle locals; order traced on the timed build; pinned .bss cache placement

Status: MEASURED (64 MB Slim, 6.61 ARK, PSPLink v3.2.1, 333 MHz, ms0 pack)
Topics: performance, hardware, link-order, data-cache
Relevant files: `tools/psp-link.py`, `psp-game/link-order.txt`, `tools/icache/layout.c`, `crates/ssb-rom/src/skeleton.rs`, `crates/ssb-pose/src/joints.rs`, `psp-runtime/src/meshdraw.rs`

## Findings

1. Code cuts: `CollisionLocals`/`LayerPose` MaybeUninit arrays, part locals written in place, `CpuSight::observe_into`, `begin_clashes` in place, grab outbox and monster-shot queue only when non-empty. Trace words vs4 1,635,119 to 1,575,785 per frame (-3.6%); intro unchanged.
2. The capture build and the `frame_timer,capture_scene_file` build differ in 121 function sizes (52 in the hot order). An order traced on the capture build does not transfer: intro 21-22.5 ms. Trace the timed build.
3. Code alone with the HEAD order: vs4 17.84, intro 22.62: the order must be re-searched after hot-code changes.
4. Residual intro regression of re-searched orders was data placement, not I-cache: ~5 KB less code moved `.rodata/.data/.bss` by -0x1340. Hardware intro did not track model misses among searched orders.
5. Timer and release builds placed `.bss` differently (release offset 0x1b80, timer 0x07c0). `psp-link.py` now pins `.bss` at offset 0x1d00 of the 8 KiB data-cache way (zero-pad object, second `rust-lld` pass); identical in both builds.
6. `.bss` offset is a timing variable (d2 order, busy us):

   vs4 target 16.7 ms: 0.06 ms short.
8. `low_free` -1,280 B in all rows (image size: code -5 KB, pad in the capture build +6,144 B). Owner accepted.
9. Release ELF vs timed relink: 437 names same; 8 differ and 16 missing, all timer-only code.

## Method

- Trace the `frame_timer,capture_scene_file` build (a `frame_timer`-only build ignores `capture_scene.txt`).
- Replaying a trace with hot functions at real ELF addresses ranks relinks like hardware.
- Pin data placement before comparing orders; re-screen `BSS_SET` when the data layout changes much.
