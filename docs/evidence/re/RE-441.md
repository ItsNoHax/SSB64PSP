## Source and ROM findings

`it/itmain.c:itMainCheckSetColAnimID`/`itMainClearColAnim`,
`it/itvisuals.c:itVisualsUpdateColAnim`, `it/itprocess.c:itProcessProcItemMain`,
`it/itdisplay.c:itDisplayColAnim{OPA,XLU}{,ProcDisplay}` and
`if/ifcommon.c:ifCommonItemArrow*` are the source.

| Behaviour | Source rule |
|---|---|
| Update | `itVisualsUpdateColAnim` ends `itProcessProcItemMain` for held and loose items, after the map and attack updates; it runs `ftMainUpdateColAnim` (no sound, no effects) and clears the animation when its script ends or its length runs out. |
| Requests | Bob-omb `ExplodeWait` sets `ItemBombHeiCritical` for 90 frames. The Link Bomb's fuse sets `ItemLinkBombCritical` for 96 frames at `lifetime == 96`, in all three fuse paths (held, loose, dropped). The fighter's Hammer timer sets `ItemHammerEnd` (no length) at `ITHAMMER_WARN_BEGIN_FRAME`; `itHammerDroppedSetStatus` clears it. `itManagerMakeItem` clears it. |
| Display | `ITAttributes::is_display_colanim` (bit 29 of the flag word) selects the ColAnim renderer. ROM: set only on the Bob-omb (251 + 0x424), the Hammer (251 + 0x374) and the Link Bomb (225 + 0x40, also XLU). The renderer switches to two-cycle mode and sets ENV to `color1` when in use, else `(0, 0, 0, 0)`. |
| Combiners | Every primitive of the Hammer (86 + 0x25F0), the Bob-omb (86 + 0x3310 and both walk lists 0x34C0/…) and the Link Bomb body (353 + 0x16F8) has second cycle `(ENV - COMBINED) * ENV_ALPHA + COMBINED`, alpha `COMBINED`. The Link Bomb spark (353 + 0x17E8) is `(PRIM - ENV) * TEXEL0 + ENV` in both cycles, but its list sets its own ENV (`FE B8 00 FF`) before its triangles, so the animation's ENV never reaches it. |
| Arrow | Every common maker but the Star's calls `ifCommonItemArrowMakeInterface`; the interface GObj is ejected with the item. `arrow_timer` reloads to 45 when it reaches 0 and decrements each frame the item can be picked up. The arrow draws while `is_allow_pickup` and `arrow_timer >= 15` (30 of 45 frames), at the item position plus `map_coll.top + 100` in Y, if the projection is inside ±150/±110; position is the truncated centred-X, bottom-anchored sprite corner. |
| Arrow sprite | `llIFCommonItemArrowSprite`, file 87 (`IFCommonItem`) + 0x50: 9 × 7 I4, `SP_TEXSHUF | SP_TRANSPARENT`, primitive colour `0xFF0000`. |
| Item light | Items draw after the fighters in the same pass. `ftDisplayMainProcDisplay` ends every fighter with `ftDisplayLightsDrawReflect` at the stage's `gMPCollisionLightAngle{X,Y}`, and the pass's `FuncLights` set `G_LIGHTING`, so a lit item primitive takes the stage direction and the `G_MW_LIGHTCOL` values its own list writes. The Hammer's handle (86 + 0x25F0, second prim) writes `LIGHT_1 = LIGHT_2 = FE 80 00`. |
| Pause | The arrow is an Interface-link GObj: battle and Training pauses hide it with every other interface. One made while Training is paused starts hidden; resuming clears every interface flag. |

## Port

- `Item::colanim` is the shared `ColAnim` interpreter; `check_set_colanim`,
  `clear_colanim` and the end-of-process update follow the source.
  `ItemVars::hammer_warning` is replaced by the real request.
- `ItemAttributes::is_display_colanim` is set on the three ROM kinds and
  checked against file 251 in `containers.rs`.
- `ItemKind::has_arrow` and `Item::is_arrow_shown` hold the arrow gate;
  `player_interface::item_arrow_position` projects it.
- Pack v89 adds the arrow sprite and `flags::ENV_LERP` on primitives whose
  second cycle is the ENV lerp (`MeshMaterial::env_lerp`).
- `DrawState::configure_item_light` installs the stage light around the
  items' draw. Only primitives with both `LIGHT1_COLOR` and `LIGHT2_COLOR`
  packed take the runtime light; any other lit primitive would read light
  registers an earlier list left, which the pack does not know, so it keeps
  the baked fallback shade (the Heart's fill, for one, goes transparent
  under GE lighting). Before this, every lit item primitive drew the white
  baked fallback and lost its authored colours.

## PSP deviation

The GE has no second combiner cycle. A blend of the combined colour towards
a constant colour by a constant factor is exactly the GE's fog with a
constant fog factor, the technique the fighters' `G_RM_FOG_PRIM_A` colour
animation already uses (`Gpu::set_constant_fog`). For an item whose
attributes set `is_display_colanim` and whose `color1` is in use with
non-zero alpha, `psp-game` installs that fog and `DrawState::begin_env_lerp`
enables it only for `ENV_LERP` primitives. ENV `(0, 0, 0, 0)` is a no-op on
the N64, so no fog is installed without a colour.

The spark's own `G_SETENVCOLOR` overrides the wrapper's, on the N64 and in
the pack alike, so it needs no live ENV.

## N64 references

Mupen64Plus Training on Dream Land with two Marios, from temporary decomp
builds; each patch was reverted and the decomp rebuilt to SHA-1
`e2929e10…`. A screenshot advances one frame of its own, so
`--screenshot-every 1` samples every second tick and showed a constant
phase of any one-tick alternation; `--screenshot-every 2` samples every
third tick.

- Arrows: RE-434's six-throwable build, no input. Small red arrows over
  the resting Poké Ball, shells and Motion-Sensor Bomb, blinking per item,
  match `trainingthrowable@300` in size, colour and height within camera
  framing.
- Hammer: one Hammer at Mario + (0, 300), A at 330. The head and handle
  alternate olive yellow and dark red/orange-brown each tick at the end,
  as `traininghammer@700/701` do after the lighting change; untinted, the
  N64 handle is yellow, where the port's was grey before it.
- Equipment and containers: the six held utilities at the
  `trainingequipment` offsets; a Barrel at (500, 500) and a Capsule at
  (-500, 500). Against the N64: the Sword's hilt is dark red, the Fan white,
  the Ray Gun has its red stripe and the Capsule its red knob only with the
  item light; the Barrel brightens toward the N64's. Frames were compared by
  pose, not tick for tick.
