## Questions and source

RE-415/416/418 leave the roll egg, Egg Throw explosion and shield-release
shell burst undrawn. Is Yoshi's bank missing, and what drives the roll?

- `dFTYoshiData` names `particles_unk2`, already pack bank 3. All nine banks
  are packed; the match runtime previously loaded only common bank 0.
  Earlier records' “bank not packed” diagnosis was incorrect.
- `efmanager.c:1375`, `:5426`: the roll egg is a forced userdata effect on
  link 15. Its maker hides model parts only after successful allocation,
  attaches to fighter joint 5 and sets X/Y scale 1.5. It has no update or
  animation. `ftMainSetStatus` stops attachments unless PRESERVE_EFFECT.
- Matrices 0x50/0x4A/0x2E translate to the attached joint, copy signed
  local rotate.x into egg rotate.z, then build the spun billboard.
  `lbcommon.c:2011` chooses positive rotation when mtx_translate[0][2] > 0.
  `efManagerYoshiShieldProcDisplay` supplies the same health-dependent ENV
  subtraction as the shield (RE-418).
- `efmanager.c:5808`: explosion uses Yoshi script 3. `:6048`: shell breakup
  uses common script 0x54. Both create a ready transform, process the first
  particle update, then set translation; neither holds an EFStruct.
- `ftcommonguard1.c:72`: on release-lag expiry or shield depletion, restore
  Yoshi's parts/hurtboxes, make shells at YRotN if attached, then stop the
  attachment and lower the shield. This batch wires that shell maker into
  the existing raised-shield abstraction.

## Implementation and original-game evidence

now calls the explosion maker. Roll eggs reserve a forced effect struct,
retain it until stopped and draw through the existing egg mesh/material.
Generated PRESERVE_EFFECT rows govern status cleanup. Queued makers carry
an attachment epoch so a roll ending before flush cannot hide the new
status; maker/stop allocation order is retained.
