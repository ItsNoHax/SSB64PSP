# RE-301 — Stage material-track replay and pack identity correction

Status: COMPLETE
Topics: material, animation, texture, pack, stage, psp-ge
Relevant files: `crates/ssb-rom/src/{mobj,mesh,pack,skeleton}.rs`, `tools/romtool/src/main.rs`, `psp-runtime/src/meshdraw.rs`

**Question.** Could the material player drive every stage track with a GE equivalent without leaking one material's UV rest state into another?

**Source behaviour.** `gcPlayMObjMatAnim` writes `TextureIDCurrent`, `TraU`, `TraV`, `ScaU`, `ScaV`, `ScrU`, `ScrV`, `SetLFrac`, and `PaletteID` to a live `MObj`. `gcDrawMObjForDObj` consumes the first five in tile-0/gSPTexture equations; `ScrU`/`ScrV` address tile 1, and `SetLFrac` selects two adjacent images plus fractional RDP blending (`objanim.c:1304-1342`, `objdisplay.c:1160-1420`).

**Implementation.** The pack preserves each animated MObj's initial tracks and tile-window parameters. A `MatAnimDesc` is keyed by `(file, script, MObjSub)`, not script alone, because one stream may attach to materials with different rest UV state. `TextureIDCurrent` resolves a packed sprite-frame table using the source's truncating u16 conversion; the renderer applies the source tile-window scale/offset delta through the GE mapping and includes it in the mapping cache key. Palette selection is independent, so a frame can also carry a cycling CLUT. Pack version 30 rejects the old descriptor layout.

`ScrU`/`ScrV` are verified inert in the converted stage scope: they update tile 1, but no converted combiner samples `TEXEL1`. `SetLFrac` remains a documented PSP limitation: the RDP's two-tile fractional-image blend has no equivalent single-pass GE path. `TextureIDNext` is only the second source image for that path.

The census also finds two `PrimColor` and one each `Light1Color`/`Light2Color`
stage attachments. They are accounted as a separate documented renderer
limitation: the affected stage shade-scale values were baked into vertices at
pack time, while the stage draw path deliberately has no per-material GE
lighting context. Replaying those tracks would require a source-measured
dynamic vertex/combiner lowering; pretending that a static baked colour is
live would be less correct. This limitation does not affect fighter costume
colour/light selection, which uses its existing runtime path.

**Census correction.** `romtool stages` now replays every resolvable stage-layer material joint and reports **61** script attachments, not RE-086's historical 172: 14 `TextureIDCurrent`, 15 `TraU`, 13 `TraV`, 2 `ScaU`, 2 `ScaV`, 2 each `TextureIDNext`/`ScrU`/`ScrV`/`SetLFrac`, 33 `PaletteID`, and 2/1/1 primitive/light colour scripts. All 61 replay with zero failures; 33 palette tables resolve. The old temporary-walker count cannot be reproduced from the current ROM/archive loader and is not a valid acceptance number until recovered.
