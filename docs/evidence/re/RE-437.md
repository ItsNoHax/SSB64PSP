# RE-437 — CPU item objectives and the CPU's item/weapon/hazard view

Status: IMPLEMENTED (decomp source, host regressions, PPSSPPHeadless captures twice, both production PSP builds; no N64 runtime comparison or physical PSP)
Topics: cpu, items, weapons, stages, visual-regression
Relevant files: `crates/ssb-game/src/computer/{attack,attack_tests,behave,behave_tests,mod}.rs`, `crates/ssb-game/src/item/mod.rs`, `crates/ssb-game/src/weapon.rs`, `crates/ssb-capture/src/lib.rs`, `psp-game/src/{main,play}.rs`

## Source and scope

The source is `ft/ftcomputer.c`: `ftComputerProcDefault`'s item branch,
`ftComputerCheckFindItem`, `ftComputerCheckTargetItemInRange`,
`ftComputerFollowObjectiveTrackItem`, `ftComputerFollowObjectiveUseItem`,
the held-item terms of `ftComputerCheckDetectTarget`, the item walk of
`ftComputerCheckTargetItemOrTwister` and both walks of
`func_ovl3_80135B78`. `psp-game` now gives each CPU the items, weapons,
Twister, Zebes acid and its own PK Thunder trail, rebuilt before each
CPU's interrupt so it sees the items as earlier fighters left them.

## Behaviour

| Source | Port |
|---|---|
| `ftComputerProcDefault` | No opponent within 350: the nearest item counts `item_track_wait` while within `400 * (level + 3)`; TrackItem after `225 - 25 * level` ticks (`315 - 35 * level` in 1P). No item resets the count. A held Damage/Shoot/Throw item gives UseItem; any other held item gives Attack. |
| `ftComputerCheckFindItem` | Empty hand only. Skips the CPU's own items and, with team attack off, its team's; needs `is_allow_pickup`, a floor below and the item inside the line bounds and under the camera top. Clears `ftcom_flags_0x4A_b1`. |
| `ftComputerCheckTargetItemInRange` | The pickup box of `ftCommonGetFindItem` for the item's weight, without its same-floor test. |
| TrackItem | In reach while in Wait or Squat: script 40 (A press); else walk. |
| UseItem | A loaded Shoot item: level 5+ throws it at a Ness or Fox target; within 400 vertically it fires (script 41), except a Fire Flower outside 0–1,500 ahead walks. Empty Shoot items count `item_throw_wait`; Damage/Throw/empty Shoot throw at once (42), or after the wait (43) on the third try or for a Poké Ball. |
| `ftComputerCheckDetectTarget` | Grounded jab, forward tilt and forward smash boxes widen 1.3 with a Sword, Bat or Star Rod. A Swing item's forward smash sets `detect_range_base` to -0.8 for every later attack in the walk; a grounded Bat weighs it 4. Giant Donkey Kong's boxes scale 1.4. |
| `func_ovl3_80135B78` | Weapons, then items, past `New` with the fighter interact bit. Fox, Ness and their polygons set `is_opponent_ra` on a hit (`ftcom_flags_0x49_b2` is never set). |

## Port deviations

| Topic | Port |
|---|---|
| `target_user` | The source stores the item in the slot that names a fighter. The port keeps it in `Computer::target_item` and clears `target_user`. Reads of an item through `ftGetComTargetFighter` (none reached in VS) see no fighter. |
| `wp->lr` | The weapon pool now keeps each slot's make `lr`: the owner's facing, the parent's for a trail, +1 for the Arwing laser, the reflector's for the PK Thunder reflect head. Reflectors turn only the velocity (`wpMainReflectorSetLR`). The Charge Shot and PK Fire read the velocity's sign (`wpMainVelSetLR` on make, hop and reflect); the Jolt reads its 2/3 wall values. |
| Threat size | `attack_coll.size` is a radius in both pools; the CPU halves it again as the source does. The old `WeaponThreat` doc called it a diameter. |
| 1P | `is_1p_game` is false: the 1P game is not ported. |
