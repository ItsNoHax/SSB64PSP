## Question

Which battle-camera behaviours were still unmatched, and what does the N64 do?

## Evidence

- **Inishie** (`gmCameraUpdateInishieFocus`): eye direction is `adjust_at_angle(0, 0, ..)`, no `at` tilt. N64 eye.x residual 0.0002 vs 92.17 with the default camera over 749 ticks.
- **Zebes** (`gmCameraUpdateAcidZoom`): ideal eye y floored at `acid curr + (step + 3000)`; step applies only while the acid status is Rise (3). 897 floor-active ticks: eye.y residual 0.0053 vs 203.7 without.
- **Boss intro order**: `BossCameraAnim` runs as a priority-5 wait thread before the camera step, so it is a pre-step. After the move PSP clock k equals N64 row 360+k for k 1..642 (eye, at, fovy within 0.01), including the anim end and hand-off to the default camera at k 600.
- **Boss spawn floor**: `ftManagerMakeFighter` runs `mpCollisionCheckProjectFloor` from the spawn. `boss::init` does the same, so Master Hand stays over the spawn x (900) after Appear; before, it lerped to 0.
- **cpufx entry focus**: all seven cpufx reference ROMs draw entry focus id 2 (PlayerZoom from frame 121 for 240 frames). The draw is still consumed. With id 2 pinned, cpufx-u camera vs N64 mean 0.015, max 0.032 over el 20-100.
- **cpufx tick map**: clean trace state rows map to PSP tick 398 + el (u, d); screenshot el (post-update image) maps to 399 + el. Screenshot calls drift the trace by one frame (Captain `SpecialLwAir` el 61 drift, 62 clean).
- **Captain's car**: N64 frame f equals PSP tick f+7 within 0.001 for f 100-422 (default, out-of-bounds fallback, zoom on Captain, return). Diverges from f 423 (CPU AI).
- **Same-frame makes**: owned makes on one frame are distinct ports in port order, as `effect_order`.
- **Stage-clear zoom**: `set_camera_zoom` (PlayerZoom, pan 0.06, FOV 28, detail High) runs on ProcSet plus 45 Set ticks (46 total in PPSSPP); RNG draws X index (6) then Y (4), from the `sc1pgame.o` disassembly.
