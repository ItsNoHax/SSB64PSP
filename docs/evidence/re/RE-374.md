# RE-374 — Link in Training: Boomerang tree, spin animation and Spin Attack swirl transforms

Status: IMPLEMENTED (decomp source, pack readback, PPSSPPHeadless goldens captured twice, workspace tests, both PSP builds; no physical PSP)
Topics: fighter, weapon, effect, animation, asset-pipeline, visual-regression, rendering
Relevant files: `tools/romtool/src/main.rs`, `crates/ssb-rom/src/pack.rs`, `crates/ssb-game/src/weapon.rs`, `crates/ssb-game/src/link.rs`, `psp-runtime/src/meshdraw.rs`, `psp-runtime/src/scene.rs`, `psp-game/src/main.rs`, `crates/ssb-capture/src/lib.rs`, `tests/golden/f1-training-link*.png`

## Question

What do Link's Boomerang and Spin Attack draw, with which transforms and
animations, and when does the Spin Attack effect end?

## Source

- `dWPLinkBoomerangWeaponDesc` has flags 0x01 (`WEAPON_FLAG_DOBJDESC`) and
  transform kind `TraRotRpyRSca`. `wpManagerMakeWeapon` builds the
  `DObjDesc` tree with `gcSetupCustomDObjs`, then sets the root's
  `translate` to the spawn position. It adds the `anim_joints` stream with
  `gcAddAnimAll`. Display is `lbCommonDObjScaleXProcDisplay`, a plain tree
  draw.
- `226_LinkSpecial1.c`: the Boomerang's `data` is file 325 + 0x610 and its
  `anim_joints` is 325 + 0x6C0, with `p_mobjsubs = NULL` (RE-058).
- `325_LinkSpecial3.c`: the tree has three nodes. The root has no display
  list and a desc translate of (0, 37.5, -15), which the spawn position
  replaces. Node 1 draws the list at 0x458 and node 2 the list at 0x580.
  Only node 1 has a script. It runs `SetValBlock(ROTX, 0) = 0`,
  `SetValBlock(ROTX, 6) = 2π`, then `SetAnim` back to its start: a spin
  about X every 6 frames.
- `wpLinkBoomerangMakeWeapon` calls `wpMainVelSetModelPitch` once. It sets
  the root's `rotate.y` to +90° when `vel_air.x >= 0`, and to -90°
  otherwise. The launch `vel_air.x` is `cos(angle) * vel * lr` with the angle
  within ±30°, so its sign is `lr`. Nothing changes `rotate.y` later.
- `wpLinkBoomerangSetReturnVars` sets `DOBJ_FLAG_NOTEXTURE` on
  `DObjGetStruct(weapon_gobj)->child->child` (node 2). `lbCommonDrawDObjScaleX`
  then skips that node's display list. The flag is never cleared, so a
  reflection after a return keeps node 2 hidden.
- `wpProcessProcWeaponMain` calls `gcPlayAnimAll` before `proc_update`,
  unless `is_hitlag_weapon`.
- `ftLinkSpecialHiMakeWeapon`, on flag 0 of the ground and aerial Spin
  Attack, calls `efManagerLinkSpinAttackMakeEffect` for both. It makes the
  weapon only on the ground.
- `dEFManagerLinkSpinAttackEffectDesc` is slot 38 of the manager-effect
  inventory: file 353's graph at 0x11C0, with its `MObjSub`, `AnimJoint` and
  `MatAnimJoint`. Transform set 1 is main kind 0x50 (80) with secondary
  `RotRpyR`. Set 2 is `TraRotRpyRSca`. The effect's `user_data` is the
  fighter's TopN joint. `rotate.y` is 30° for `lr == +1`, else 210°.
- Kind 80 is `dLBCommonFuncMatrixList` pair 80 - 66 = 14,
  `func_ovl0_800C99CC`. It loads a pure translation to
  `gmCollisionGetFighterPartsWorldPosition(TopN)`.
- The root has no script. Node 1's script holds `TraY` at 300 and animates
  `RotY`. The material script ramps primitive alpha from 0 to 204 on
  frame 13 and back to 0 by frame 65 (RE-324).
- `efManagerHaveStructProcUpdate` plays the animations, unless
  `is_pause_effect` is set. It ejects the effect when the animation ends.
  `fp->proc_lagstart = ftParamProcPauseEffect` pauses it during Link's
  hitlag. `ftMainSetStatus` stops the effect unless the new status passes
  `FTSTATUS_PRESERVE_EFFECT`. Only the ground-to-air switch into
  `SpecialAirHi` passes it (`ftlinkspecialhi.c:275`); `SpecialHiEnd` does
  not.

## Implementation

- Pack v53 adds `AnimDesc::WEAPON` (`u32::MAX - 7`). Slot
  `WEAPON_ANIM_LINK_BOOMERANG` holds file 325's 0x6C0 table against the
  packed 325 + 0x610 object. `Pack::weapon_anim` reads it. Pack v53 is
  27,089,392 bytes.
- `LinkBoomerang` gains three fields for presentation only:
  `model_rotate_y` (±90°, from `lr` at launch), `grandchild_hidden` (set by
  `set_return`) and `anim_ticks` (one per update).
- `LinkState::spin_effect` counts the swirl's played frames. It starts at 1
  on the flag-0 frame, because the effect's own update plays once on the
  frame it is made. It advances in `link::update` outside hitlag.
  `link::spin_effect_ticks` returns it only in `SpecialHi` or
  `SpecialAirHi`. The ground Spin Attack lasts 60 frames and the aerial one
  100, so the status ends before the animation does.
- `psp-game`'s `LinkVisuals` plays a `StageAnimator` up to each count, plus
  an `EffectMaterialAnimator` for the swirl. It restarts a player when its
  count goes back.
- The Boomerang draws under `T(position) · Ry(model_rotate_y) · MODEL_SCALE`.
  Every posed node is premultiplied by the inverse of the root's desc
  translate, because the source replaces that translate.
  `meshdraw::draw_object_posed_hiding` skips node 2 after a return.
- The swirl draws under `T(fighter.pos) · Ry(30° or 210°) · MODEL_SCALE`
  with its posed nodes and live material colours.
- The capture scenes `link` (the Boomerang in flight) and `linkspin`
  (13 frames into a ground Spin Attack) spawn Link.

## Findings

- The swirl's quad lies in the XZ plane at node 1's height. The Training
  camera is almost level, so the `linkspin` golden shows the swirl as a
  thin yellow arc at sword height. A capture with the swirl draw disabled
  differed from the golden in 376 pixels, so the golden covers the draw.
