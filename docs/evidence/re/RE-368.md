# RE-368 — Luigi translation scales in clips and shield pose

Status: IMPLEMENTED (decomp, US ROM pack readback, host tests, both PSP builds, PPSSPPHeadless Luigi golden and game smoke; no physical PSP)
Topics: animation, fighter, shield, asset-pipeline, visual-regression
Relevant files: `crates/ssb-rom/src/{figatree,objanim,pack,skeleton}.rs`, `tools/romtool/src/main.rs`, `psp-runtime/src/scene.rs`, `psp-asset-viewer/src/main.rs`, `crates/ssb-rom/tests/shield_pose.rs`

## Question and sources

RE-367 left Luigi's `FTAttributes.translate_scales` unapplied. The decomp's
`ftParamUpdateAnimKeys` plays each joint through
`lbCommonPlayTranslateScaledDObjAnim` when the fighter has scale vectors and
the motion does not set `FTANIM_FLAG_TRANSLATE_SCALES`. The function multiplies
only translation tracks as it writes them; rotations, scales and silent
translation axes stay as they were. Luigi's main and submotion descriptor
tables do not set that flag. `ftCommonGuardGetJointTransformScale` also
multiplies each neutral `dobj_lookup` translation before the stick-range
blend. `ftCommonGuardUpdateJoints` and `ftCommonGuardInitJoints` play the
shield scripts with the same per-joint vectors.

The US ROM's Luigi `*Main` file has an internal relocation at
`FTAttributes + 0x324` to 29 `Vec3f` vectors, one per `FTPartsJoint` (TopN,
TransN, XRotN, YRotN, then 25 model joints). Only the Y components of joints
3, 7, 11, 12 and 13 differ from one. The pack builder reads these bytes from
the ROM; the decomp values serve only as test checks.

## Implementation

- Pack v50 adds one `AnimDesc::TRANSLATE_SCALES` row keyed by Luigi's kind.
  It holds the 348 source bytes, with no Nintendo asset committed.
- The figatree and 32-bit joint players multiply only live translation
  tracks. `Skeleton` resolves each packed model node to `FTPartsJoint` index
  `4 + node - first_node`; a hidden runtime joint has an identity vector.
- The shield pose resolves model entries from joint 4 and its separate
  `YRotN` from joint 3, scaling both the script and the neutral lookup
  translation. The game and asset viewer use the same pack vectors.

## Verification

- Pack v50: 27,085,696 bytes (+384), SHA-256
  `d8394ea153d52bd24df32415ff6a2ec92fe8dcdc672a80d392627643e7b45902`.
  Luigi has 29 vectors; Mario has no row. Host tests compare clip poses with
  and without scaling and both shield blend endpoints against the ROM row.
- Workspace tests pass with the US ROM; pinned Clippy with warnings denied,
  rustfmt, and all three `thumbv7em-none-eabi` no_std builds pass.
- Both PSP release builds pass. The viewer retains its existing warnings.
- PPSSPPHeadless: `r2-luigi-fighter` changed by 57,056 pixels at 2× and is
  byte-identical across two captures. Its new pose has the expected taller
  joint placement. Mario's control golden is unchanged; both pass twice
  after rebaseline. `psp-game` reaches scripted Training with pack v50.

The new vectors do not make Luigi selectable in `psp-game`. A live shield
scene and physical-PSP validation remain separate work.
