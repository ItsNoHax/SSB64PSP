# RE-495 — A flags-derived render-state table costs more to build than the redundant GE writes it removes

Status: COMPLETE, negative (PSP-2000, 6.61 ARK, PSPLink v3.2.1, `profile,capture_scene_file,no_audio` builds of `vs4@2400` with pack v109 on `ms0:`, reports 1–18, two interleaved rounds per pair; I-cache figures from the RE-494 PPSSPP model)
Topics: performance, hardware, icache, psp-ge
Relevant files: `psp-runtime/src/meshdraw.rs`, `tools/icache/layout.c`, `tools/icache/relink.py`, `psp-game/link-order.txt`

## Question

`apply_flags_state` (`psp-runtime/src/meshdraw.rs`, inlined through
`apply_material` into `draw_mesh_vertices`) runs whenever a primitive's
pack flags differ from the last ones. Each run rewrites the whole
flags-derived GE state: cull, shade model, lighting, depth test, depth
mask, alpha test and function, blend enable and function. Would a
precomputed or shadowed render-state word that emits only the registers
that actually change make the four-player draw faster?

## Findings

### How much the block costs

Counters in a `profile` build in PPSSPP, `vs4@2400`:

| Per frame | Count |
|---|---|
| Primitives drawn | ~128 |
| `apply_flags_state` runs | ~60 (58–64) |
| GE register words written by it | ~520 |
| Words whose value changes (upper bound) | ~90 |

In the I-cache model, on HEAD's inlined block (195 static instructions,
located through DWARF inline chains and `psp-addr2line -i`), the block
executes ~6,970 instruction words a frame (115 per run) and causes
228–236 model misses a frame. That comes to about 21 µs of instructions
plus 88 µs of misses, ~110 µs a frame, which is above the 50 µs bar the
experiment was set to need.

### Three shadowed encodings, none cheaper

All three kept the emitted GE state byte-identical, and the VS goldens
matched 24 of 24.

| Variant | Static instr. | Words/frame | Model misses/frame |
|---|---|---|---|
| HEAD (unconditional writes) | 195 | ~6,970 | 228–236 |
| v1: 12-word shadow array, diff per register | 306 | ~9,220 | ~306 |
| v2: packed bit word, if-chain per bit | 275 | ~8,380 | 239–251 |
| v3: branchless packed word, `trailing_zeros` over a command table | 167 | ~8,820 (147/run) | ~208 (3.47/run against 3.78) |

The redundant writes are cheap: `send_command_i` is ~6 instructions a
word. Packing the wanted state into a key and diffing it costs as many
instructions as the ~430 skipped writes save. The smaller static
footprint of v3 saves only ~0.3 misses a run.

### Hardware A/B (v3 against HEAD)

An order fits only its build (RE-494), so each build was also relinked
with its own searched order (anneal seeds 1 and 2):

| Pair | HEAD FPS | v3 FPS | HEAD frame µs | v3 frame µs | Material span µs (HEAD / v3) |
|---|---|---|---|---|---|
| As linked | 52.72 | 53.53 | 19,040 | 18,768 | 1,420 / 1,472 |
| Seed-1 order | 55.46 | 55.48 | 18,125 | 18,115 | 1,364 / 1,450 |
| Seed-2 order | 56.08 | 55.60 | 17,925 | 18,078 | 1,362 / 1,409 |

- The as-linked v3 lead is layout luck: the model gives HEAD 416K
  misses and v3 401K at those orders.
- With each build at its best searched order (seed 2), v3 is ~150 µs a
  frame slower (−0.47 FPS).
- The material span is 47–95 µs slower for v3 in every pairing.
- The model ranks every pair the same way the hardware does.
- Round-to-round noise was ≤0.03 FPS, except one seed-1 pair at 0.26 FPS.

### The anneal seed matters

On the same HEAD `profile` build, the seed-2 search modelled 3% fewer
misses than seed 1 (344,697 against 355,658; held-out trace 346,606).
It also ran 0.6 FPS faster (56.08 against 55.46). One annealing run
does not find the best order.

## Consequences

- No code shipped. `apply_flags_state` keeps writing the whole
  flags-derived state on each flags change; the v3 patch is not kept.
- A render-state cache on this path pays off only if the key comes
  for free, for example a state word precomputed into the pack per
  primitive. Even then, the ~430 redundant writes it removes are
  ~2,600 instructions, under 10 µs a frame.
- When searching a link order (RE-494), run several seeds, or more
  iterations, and keep the best held-out result. The shipped audio
  build's order came from a single seed and may have ~0.5 FPS left in it.
