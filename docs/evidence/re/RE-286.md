**Question.** RE-285 added the 4th of 41 stage entries as a dedicated
deterministic golden and named the rest "37 remain" as deliberately deferred,
one-at-a-time work. The user explicitly asked to add all remaining stage
goldens in one session, overriding that pacing. Before starting, this task
re-derived the exact remaining set from `AGENTS.md`'s own ground-truth
priority (decomp over inference): `STATUS.md`'s own text ("5 more real
battle stages... plus the Metal Mario stage, the tutorial map, and 26 bonus
maps") undercounts by 4 — cross-referencing `romtool stages`' 41-entry
file-255..295 block against `refs/ssb-decomp-re/src/mp/mpcollision.c`'s
`dMPCollisionGroundFileInfos` table (the decomp's own authoritative,
commented stage list) shows the true remaining set is **37**, not 33:
`STATUS.md` never named Mushroom Kingdom (file 260, `GRInishieMap` —
RE-285's own text had also miscategorized this as a "test map variant";
the decomp table comments it plainly as `// Mushroom Kingdom`, a real
selectable stage), Beta Dream Land (256), the Test Stage (258), Duel Zone
(268), and Small Yoshi's Island/1P (270). The corrected 37: 5 more real
VS-mode battle stages (Zebes, Mushroom Kingdom, Kongo Jungle, Yoshi's
Island, Hyrule Castle), Final Destination, the tutorial map (How to Play),
the Metal Mario stage (Meta Crystal), 3 small/test variants (Beta Dream
Land, Test Stage, Small Yoshi's Island), Duel Zone, and 25 bonus maps
(12 Break the Targets + 12 Board the Platforms + Race to the Finish).

**Scale decision.** The user was asked, and chose, to defer physical-PSP
hardware confirmation to a later batched pass rather than 37 sequential
PSPLink load/capture cycles in this session — every prior stage/fighter
golden in this project's history paired its PPSSPP software golden with an
immediate physical-hardware confirmation, so this is an explicit, recorded
deviation from that pattern, not a silent gap.

**Implementation.** Adding 37 near-identical named Cargo features
(`regression_capture_scene11`..`_scene47`, following RE-207-etc.'s existing
one-feature-per-scene convention) would have meant 37 nearly identical
`psp/Cargo.toml` entries and 37 nearly identical `stage_index = N` blocks in
`psp/src/main.rs` — the point at which repetition stops being "three similar
lines" and becomes a genuine scaling problem. Instead, added one
parametrized feature, `regression_capture_stage_index` (`psp/Cargo.toml`),
which reads the target stage index from the `SSB64_STAGE_INDEX` build-time
environment variable via `option_env!` (a compile-time read already used
elsewhere in this codebase's HLE-adjacent tooling, here applied inside the
`no_std` PSP binary itself since `option_env!` needs no runtime environment,
unlike `std::env::var`). Wired into the same `deterministic_capture_frozen`
tick-240 freeze and default whole-stage `stage_view` scenes 5/10 already use
— no new capture mechanism, no new freeze semantics, same rigor bar. Each of
the 37 stages is still captured, diffed for determinism, and committed as
its own permanently-named golden PNG; only the Cargo-feature layer is
shared, not the evidence.

**Verification.** For each of the 37 remaining stage indices (1, 2, 3, 5, 6,
8, 10-40), built once with `SSB64_STAGE_INDEX=<n> cargo psp --release
--features regression_capture_stage_index,headless_capture`, then ran
PPSSPPHeadless twice against the same EBOOT at different `--seconds` (8 and
20) and compared the two captures with `cmp`. All 37 were byte-identical
across both timings — deterministic, matching every other golden this
project has added. Each stage's first capture is committed at
`tests/golden/r2-stage-<slug>.png` (37 files; SHA-256 values recorded in
this session's manifest, spot-checked visually: Final Destination shows the
correct single floating-platform silhouette, Meta Crystal shows the
rock-formation geometry with a real spawn marker, Mushroom Kingdom shows
SMB1-styled block/pipe geometry, the Break-the-Targets maps show their
target markers — none blank, none showing a locked/black PPSSPP window).
