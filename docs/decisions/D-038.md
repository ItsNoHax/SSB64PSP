# D-038: Generated Texture Coordinates Use the GE Texture Matrix, Not Environment Mapping

Category: Rendering Fidelity

## Decision
- Reproduce `G_TEXTURE_GEN` with GE texture-matrix generator
  - `sceGuTexMapMode(TextureMatrix, ...)` + `sceGuTexProjMapMode(Normal)`
- Never `TextureMapMode::EnvironmentMap`
- Matrix holds: node world transform, `gSPTexture` scale, render tile origin
- Coordinate-mapping state separate from binding state
  - `bind_texture` must not install a coordinate scale

## Why
- Environment-map generator ignores `sceGuTexScale`/`sceGuTexOffset`; sweeps full uploaded texture only
  - 64x-larger scale gave byte-identical capture (RE-214)
- Real content needs the scale:
  - one `StageMetalFile2` tile sweeps 16 of 32 uploaded texels
  - 48x42 tile padded to 64x64 sweeps 47x41
  - 57 texgen triangles bind a tile with nonzero origin
- Matrix generator carries all of it
- Avoids environment path coupling S axis to named GE light slot (light 0 is the fighter light)

## Amendment (RE-226)
- Projection mode: raw `Normal`, not `NormalizedNormal`
  - RSP never normalizes quantized vertex normal (scales by `/127`)
  - `NormalizedNormal` discards magnitude: `[64,0,0]` and `[127,0,0]` gave identical output
- Dot-product term scaled by `128.0/127.0`
  - why: GE internal `/128` divisor (measured against PPSSPP source and real `sceGu` draws)

## Implemented
- `psp-runtime/src/meshdraw.rs`: `apply_texture_mapping`, `TextureMapping`, `DrawState::texgen_object_basis`
- `crates/ssb-rom/src/psp_texture.rs`: `env_map_tex_scale`, `authored_uv_tex_scale`
