# D-040: Exact Linear Texgen Is CPU-Generated into the Authored-UV Pipeline, Not a Second GE Mode or a Lookup Table

Category: Rendering Fidelity

## Decision
- Generate `G_TEXTURE_GEN_LINEAR` curve `acos(-dot)/(2*pi)` per vertex on CPU
- Dot product as RSP computes it: `normal / 127`, not true renormalisation
- Output in pack's raw S10.5 authored-UV unit; primitive draws via ordinary authored-UV `TextureMapMode`
- No second GE coordinate mode, no duplicated texture, no lookup table

## Why
- No GE generator reproduces the curve: texture-matrix and environment-map generators are affine in dot product; `acos` is not
- Same raw S10.5 unit and clamped-axis origin-shift rule (`* 8`) as `mesh::Builder::push_vertex` (RE-152)
  - texture dimension cancels
- LUT exact only over finite input domain
  - look-at basis it is dotted against varies per camera
  - LUT keyed on normal alone still interpolates: no gain over direct polynomial `acos`
  - adds build-time table and runtime gather
- Population small: 257 triangles, 12 packed primitives

## Amendment (RE-227)
- Look-at basis quantized to signed byte (`FTOFRAC8`) once per camera, before per-vertex work
  - `DrawState::texgen_object_basis` reproduces it
- LUT rejection stands: basis still varies per frame

## Implemented
- `crates/ssb-rom/src/psp_texture.rs`: `linear_texgen_curve`, `texgen_dot`, `linear_texgen_uv`, `acos`
- `psp-runtime/src/meshdraw.rs`: `draw_mesh` dynamic-vertex branch, `apply_texture_mapping`'s `environment` flag
