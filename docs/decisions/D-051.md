# D-051: PPSSPP Golden Hashes May Move for a Renderer-Path Change Only Under Hardware Proof

Category: Testing & Validation

## Decision
- PPSSPP golden hash may change for a renderer-path change only when all three hold.
  - Scope: list chunking, stall batching, draw-word writing.
1. Hardware framebuffer comparison proves PSP output identical over affected scenes.
   - Method: `frame_hash`, FNV-1a of each 480x272 frame, PSP before and after.
2. New hashes stable: at least 3 captures, one at `-j 1`.
3. Changed rows listed in commit message with native pixel count per row.
   - RE record only when the change carries a durable finding.
- Gameplay or asset changes: bit-identical goldens or reviewed rebaseline.

## Why
- PPSSPP software renderer bins work by range; flush chunking moves bin boundaries (RE-534).
- Word-for-word identical PSP display lists can move PPSSPP pixels.
  - Edge pixels, single sprite-edge rows, either direction.
- Hardware comparison shows nothing was lost.

## Applied
- Stall batching moved 44 rows (RE-537).

## Amendment trigger
- PPSSPP change making bin boundaries independent of list layout.
- Hardware difference in a scene whose golden moved.
