# D-039: Texgen State Is Primitive-Level Because the Archive Says So

Category: Rendering Fidelity

## Decision
- Store `G_TEXTURE_GEN` mode and `gSPTexture` scale on the primitive (`MeshMaterial`, `PrimDesc`)
  - not at vertex-cache/load granularity
- Keep raw `G_TEXTURE_GEN` / `G_TEXTURE_GEN_LINEAR` geometry-mode bits independent
  - not one mode enum

## Why
- F3DEX generates coordinates during `G_VTX`; primitive granularity needs an invariance
- `romtool texgen` measures it archive-wide: 3,012 texgen triangles
  - none load a vertex under a different effective mode or `G_TEXTURE` scale than the draw
  - includes 203 reusing a vertex across a node or display-list boundary
- Raw bits stay separate: `G_TEXTURE_GEN_LINEAR` is a modifier
  - list may clear `G_TEXTURE_GEN` while retaining it
  - re-setting must resume linear mode; three-state enum cannot express that
- Invariance violated by other content → move state to vertex-load level, never "last material wins"

## Implemented
- `crates/ssb-rom/src/mesh.rs`: `State::geometry_mode`, `TextureGen::from_geometry_mode`, `MeshMaterial::texgen_scale`
- `tools/romtool/src/main.rs`: `texgen`
