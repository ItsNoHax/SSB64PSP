# D-053: The First-Launch Pack Build Is a Separate Installer EBOOT, Started by LoadExec

Category: Platform & Toolchain

## Decision
- Two files in one `PSP/GAME/<folder>/`: `EBOOT.PBP` (`psp-game`) and `INSTALL.PBP` (`psp-installer`), plus the user's `rom.z64`/`.v64`/`.n64`.
- `psp-game` checks `assets::pack_status()` at start; not `Ok` → `launch::start_installer()`.
- Hand-off: `sctrlKernelLoadExecVSHMs2` (key `game`, argv = `INSTALL.PBP` path), fallback `sceKernelLoadExec`.
  - Both fail or file missing: a screen with the path and error code; exit on a button press.
- `psp-installer` links `ssb-pack` through `psp-runtime` feature `installer`; no renderer, tables, audio or game statics.
- The installer builds `ssb64.pak.tmp`, renames to `ssb64.pak`, shows done and exits to the XMB; the user launches again to play.
- `tools/psp-release.sh` builds both and collects them in `target/psp-release/ssb64/`.

## Why
- PSP-1000 has a 24 MiB user partition and ignores `MEMSIZE` ([RE-288](../evidence/re/RE-288.md)).
- The game's `.text` is pinned by link-gap padding; linking the pack build into it cost 2 MB of image and left 14.0 MB free at start.
- A separate EBOOT keeps the game image about the base (+16 KB) and gives the installer about 22.4 MB at start.
- Image-independent budget: free at start + image + main stack = 25.13 MB on a PSP-1000; installer ballast 22,367,488 B ([RE-588](../evidence/re/RE-588.md) item 15).

## Amendment trigger
- A PSP-1000 run needing more than the measured installer peak (12.36 MB use, lowest free 9.78 MB at the derived ballast).
- LoadExec hand-off failing on firmware used by owners.
