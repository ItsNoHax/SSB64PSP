# D-049: The N64 Audio System Is Ported Whole and Synthesized at Run Time on Its Own Thread

Category: Platform & Toolchain

## Decision
- Audio is the original's own, translated into `ssb_engine::audio` as one portable subsystem:
  - libultra `n_audio` synthesizer and compressed-sequence player.
  - FGM sound-effect engine in `n_env.c`.
  - `syAudio` layer of `src/sys/audio.c`.
- Nothing converted ahead of time except into the pack's layout.

### Data
- `romtool pack` copies ROM audio files into one section at the pack's end:
  - `S1_music.sbk`, `B1_sounds1`, `B1_sounds2`: `.ctl`/`.tbl`, VADPCM kept compressed.
  - `fgm.unk`, `fgm.tbl`, `fgm.ucd`.
  - Synthesizer constant tables: resampler filter, `n_eqpower`, custom reverb parameters and presets, `gSYSinTable`.
- Read once at boot into a never-freed buffer.
  - why: audio thread reads it at any time; outlives any scene.
- Repository holds only where these lie in the ROM ([D-048](D-048.md)).

### Synthesis
- VADPCM decoded at run time.
- RSP microcode commands implemented directly in integer fixed point, no command lists.
  - Commands: ADPCM, resample, envelope mixer, mixer, interleave, pole filter.
- Timing at N64 real output rate: 32006 Hz (`osAiSetFrequency(32000)` on NTSC).
- Frames of 552 or 368 samples, chosen by `syAudioThreadMain`'s rule; each cut into 184-sample sub-frames.

### Output
- Dedicated audio thread, higher priority than the game's.
- Renders frames, plays through the 32 kHz SRC channel in fixed 512-sample blocks.

### Calls
- Game code makes the decomp's calls where the decomp makes them.
  - `ssb_game::sound`: `syAudioPlayBGM`, `func_800269C0_275C0`, ...
- Reach the one `AudioSystem` synchronously under a lock the audio thread takes per frame (`SharedAudio`).
  - Matches the N64 calling the FGM engine under `osSetIntMask`.
- A play returns its handle at once.

### Speed
- DSP loops have Allegrex kernels (`dsp::allegrex`, MIPS only), same samples as portable code.
- Portable code stays the host reference (RE-479).
- Sample-exact rule (user decision, 2026-10-18): cut CPU cost only by exact means, never by approximating output.
  - Example: VFPU path whose products stay exact.

### Media Engine
- Allowed only for the same sample-exact DSP code.
- SC path is a mandatory fallback; no VME.
- Blockers:
  - Needs kernel-mode code rust-psp does not bind.
  - PPSSPP does not run it.
  - Its cache is not coherent with the Allegrex; no VFPU.
- Render path performs no system calls, allocation or trig, so it can move there.
- Status: `PLAN.md`.

## Deviations from the N64
| Deviation | Detail |
|---|---|
| Stream rate | PSP plays 32006 Hz stream at 32000 Hz: 0.02% slow, a third of a cent flat |
| Pacing | audio thread paced by PSP output, not video retrace; game call lands before next frame the audio thread renders |
| Boot | builds final configuration (custom reverb, 72-entry FGM oscillator pool) directly; no double audio-thread restart as `scManagerRunLoop` does |
| Spin waits | game does not spin on `syAudioGetSettingsUpdated`, `syAudioGetRestarting` |
| BGM stop | no spin on `syAudioCheckBGMPlaying` after `syAudioStopBGMAll`; BGM status machine handles stop and play in order |
| `__n_initFromBank` | writes one channel state past its 16-entry array; port adds a 17th entry nothing reads |
| Custom reverb low-pass | not applied; PCM recorded from original under Mupen64Plus matches only without it (RE-479) |
| Mono option | averages frame just rendered; N64 averages previous one in place before the AI |
| `sinf` (vibrato) | libultra's runs in `f32`, original uses double; no vibrato value differs |
| `func_80026738(NULL)` | N64 can stop parentless scripts (matches a node's NULL parent); port's absent handle stops nothing |
| Crowd reactions, single-fighter item-music changes | queued where decomp makes them, settled at end of same frame |

- Microcode is not decompiled.
  - Commands follow BattleShip's mixer (MIT).
  - Checked against PCM recorded from original under Mupen64Plus's HLE RSP.

## Why
- Sounds are programs, not samples.
  - FGM scripts spawn voices through articulation programs with own oscillators and random numbers.
  - Sequences change programs, tempo, loops as they play.
- Pre-rendering needs one recording per sound and interaction.
- Translating the engine keeps every sound, its timing, its game interaction.
- Size: compressed VADPCM 4.4 MB vs ~17 MB decoded.
  - Worst single sequence needs 74% of the music bank; per-sequence sample sets save little.
