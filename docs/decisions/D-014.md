# D-014: Fighter Vertex Cache — Shared Across Joints

Category: Asset Pipeline

## Decision
- Convert scene-graph lists in draw order, threading one 32-entry vertex cache
- Each cached vertex records its loading space
- Borrowed vertices keep original position and loading joint in pack
- Posed draws: reconstruct via `inv(world_here) * world_there` with animated matrices
- Static draws: baked rest-pose rebase

## Why
- `gcDrawDObjTree` emits one command stream; RSP cache survives across lists
- Joint drawing triangles with vertices loaded by previous joint = N64 skinning without per-vertex weights
- Conversion failures: 244 to 0

## Amendment (RE-358)
- Rest-only rebase tore fighter seams under animation
- Pack carries source-joint bindings; texture and triangle order unchanged
- PSP rebuilds borrowed positions and normals in transient GE memory
- Supersedes RE-026 rest-pose limitation
- PSP integer positions and signed-byte normals still round reconstructed values

## Implemented
- `crates/ssb-rom/src/mesh.rs`: draw-order traversal, cache threading
