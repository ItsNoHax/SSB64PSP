# D-014: Fighter Vertex Cache — Shared Across Joints

Category: Asset Pipeline

**Decision:** Convert scene graph lists in draw order, threading one 32-entry vertex cache. Each cached vertex records its loading space. Borrowed vertices retain their original position and loading joint in the pack; posed draws reconstruct them through `inv(world_here) * world_there` using animated matrices. Static draws use the baked rest-pose rebase.

**Reasoning:** `gcDrawDObjTree` walks tree emitting into one command stream — RSP cache survives across lists. Joint's list draws triangles with vertices loaded by previous joint = N64's skinning without per-vertex weights. Conversion failures 244 → 0.

**Implemented:** `crates/ssb-rom/src/mesh.rs` (draw-order traversal + cache threading)

**Reference:** RE-026

**Amendment (RE-358):** Animation exposed the rest-only rebase as torn
fighter seams, including Mario's knees. Pack v43 adds source-joint bindings
without changing textures or triangle order. The PSP rebuilds borrowed
positions and normals in transient GE memory. This supersedes RE-026's
rest-pose limitation; PSP integer positions and signed-byte normals still
round the reconstructed values.
