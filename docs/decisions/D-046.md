# D-046: Scenes Load Their Archive Files; Only the Pack's Index Stays Resident

Category: Platform & Toolchain

## Decision
- Pack groups its blob by ROM archive file (`ssb_rom::pack::FileDesc`):
  - Shared region first: particle banks, material-animation files every stage clock ticks, textures used by more than one file, special-role textures.
  - Then each archive file's own bytes, with its extern file IDs.
- Boot residency: header, tables, shared region (`ssb_psp_runtime::assets::load_pack`).
- Scene start reads the scene's files (`ssb_psp_runtime::scene_files::enter`), as `lbRelocLoadFilesListed` does.
- Scene roots: the N64 scene's own (`ssb_rom::scene_roots`).
  - `dXXFileIDs`, `dGMCommonFileIDs`.
  - Effect, item, fighter manager files.
  - Each fighter's main file; the stage's map file.
- Loader adds the extern closure from the pack's dependency lists, as `lbRelocLoadAndRelocFile` does.
- Files held by last scene but not this one: freed; files both hold: stay.
  - Block the GE may still read: freed after the frame's sync.
- `Pack::blob` resolves an offset past the pack buffer through `ssb_rom::residency`.
- Offset no loaded file holds: loads its file on demand.
  - Missing scene-list entry costs one read, never a wrong picture.
  - Capture logs count these (`demand=` in the `mem` line).
- Failed load or file allocation: text screen (`ssb_psp_runtime::memory::fatal`), not a hang.
  - Small Rust allocations still use `psp`'s allocator; its error handler spins.
  - Every scene leaves ~30 MB free.
- Asset viewer: same resident part; loads each file on first draw, keeps it.
  - why: draws any object at any time.
- Menus', title's, How to Play's, opening's sprites, plays, cameras, opening's models live in the pack under their archive files (no separate packs; `ssb64-menus.pak` RE-461 and opening models pack RE-467 retired).

## Deviations from the N64
| Deviation | Detail |
|---|---|
| Battle loads each fighter's whole figatree set at start | N64 reads one per `ftMainSetStatus`; a memory-stick read inside a frame would stall |
| Selects and results read clips on demand | next scene's files read ahead in background (RE-501) |
| Stage select holds all nine VS previews | N64 loads one per hover |
| Material-animation files stay resident | stage material clocks run for process life (`skeleton::MaterialAnimator`) |
| Files both scenes hold are not reloaded | N64 reloads everything per scene |
| Known next scene: files read in background (`scene_files::prefetch`, RE-476; leaves `PREFETCH_MARGIN` = 6 MiB free) | opening order, attract loop; both scenes' files held for a while |

- Scene start waits for a read still running: lengthens a frame, never changes a tick.
- Opening scene's files are entered when it begins, after the hold that still draws the last one.

## Why
- RE-475: from XMB, PSP-2000 with 6.61 ARK gives the game 47.9 MB (4.2 MB less than under PSPLink).
  - Whole 46.9 MB pack left 1.2 MB; first scene's allocations failed; `psp`'s handler spun on black screen.
- Per-scene loading holds only the scene's data: heaviest scene ~17 MB under PPSSPP vs 48-51 MB whole pack.

Status: Adopted (RE-475, RE-476).
