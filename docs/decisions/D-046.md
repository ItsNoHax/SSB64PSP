# D-046: Scenes Load Their Archive Files; Only the Pack's Index Stays Resident

Category: Platform & Toolchain

**Decision:** The asset pack groups its blob by the ROM's archive file
(`ssb_rom::pack::FileDesc`, pack v107): a shared region first (the
particle banks, the material-animation files every stage clock ticks,
textures more than one file uses, the special-role textures), then each
archive file's own bytes (meshes, indices, textures, sprites, figatrees,
baked plays) with its extern file IDs. The game holds only the header, the
tables and the shared region from boot
(`ssb_psp_runtime::assets::load_pack`, about 5.5 MB) and reads each scene's
files when the scene starts (`ssb_psp_runtime::scene_files::enter`), as
`lbRelocLoadFilesListed` reads them into the scene's heap:

- Each scene's roots are the N64 scene's own (`ssb_rom::scene_roots`:
  the `dXXFileIDs` arrays, `dGMCommonFileIDs`, the effect, item and fighter
  manager files, each fighter's main file, the stage's map file), and the
  loader adds their extern closure from the pack's dependency lists, as
  `lbRelocLoadAndRelocFile` does.
- Files the last scene held and this one does not are freed; files both
  hold stay. A block the GE may still read is freed after the frame's
  sync.
- `Pack::blob` resolves an offset past the pack buffer through
  `ssb_rom::residency`, so no consumer of `Pack` changed.
- An offset no loaded file holds loads its file on demand, so a scene list
  that misses a file costs one read, never a wrong picture; capture logs
  count these loads per scene (`demand=` in the `mem` line).
- A failed load or file allocation ends on a text screen
  (`ssb_psp_runtime::memory::fatal`) instead of a hang. Small Rust
  allocations still go through `psp`'s allocator, whose error handler
  spins; with every scene leaving some 30 MB free they are not expected
  to fail.
- The asset viewer holds the same resident part and loads each file the
  first time a draw reads it, keeping it: it draws any object at any time.
- The menus', title's, How to Play's and opening's own sprites, plays and
  cameras, and the opening's models, are in the pack under their archive
  files; `ssb64-menus.pak` (RE-461) and the opening models pack (RE-467)
  are gone.

**Deviations from the N64:**

- A battle loads each fighter's whole figatree set at its start. The N64
  reads one figatree per status change from the cartridge
  (`ftMainSetStatus`); a memory stick read inside a frame would stall it.
  Selects and results read their few clips on demand.
- Material-animation files stay resident: the port's stage material
  clocks run for the process's life (`skeleton::MaterialAnimator`).
- Files both scenes hold are not reloaded; the N64 reloads everything per
  scene.

**Reasoning:** RE-475: from the XMB, a PSP-2000 with 6.61 ARK gives the
game 47.9 MB, 4.2 MB less than under PSPLink, and the whole 46.9 MB pack
left 1.2 MB; the first scene's allocations failed and `psp`'s allocation
error handler spins, so the screen stayed black. Per-scene loading holds
the scene's data only: the heaviest scene measured holds about 17 MB in
all under PPSSPP, where the whole pack needed 48 to 51 MB.

**Status:** Adopted (RE-475).
