# D-048: Nothing Read From the ROM Is Committed — Tables Are Generated at Build Time, Goldens Are Pixel Hashes

Category: Engineering Process

Extends: [D-033](D-033.md) from the ROM and asset pack to everything else.

## Decision
- Repository holds no data taken from the ROM and no picture of the game.

### Tables
- Tables the original keeps in code, data segments or archive files: generated at build time from the user's ROM.
- Covered, by source:

| Source | Contents |
|---|---|
| Fighter code/data | motion scripts and tables, colour-animation scripts, CPU input scripts, attack tables, status flags, fighter animation table |
| Fighter archive ([RE-544](../evidence/re/RE-544.md)) | joint masks, hidden/texture parts, hurtbox descriptors, Falcon Dive capture offsets |
| Other relocData attribute structs ([RE-545](../evidence/re/RE-545.md)) | item and monster-weapon attributes, Smog scale animation, Mario physics, Kirby copy table |
| Decomp `d*` arrays, code and overlay segments ([RE-546](../evidence/re/RE-546.md)) | handicap, costume, item-throw, ground-hit, Zebes acid, Sector Z Arwing, Yoshi egg, charge-shot, shield-colour, boss tables |
| same | countdown, pause, announcer HUD data |
| same | title, Characters, 1P Game, stage-clear, staff-roll, congratulations, opening scene data |
| same | archive file ids, offsets, effect/transition descriptors `ssb-rom` reads from code |

- Generators for the `d*` rows (user decision, 2026-10-18): `ssb-tablegen` modules `battle_data`, `ifcommon`, `menu_data`, `sc1p_data`, `ending_data`, `opening_data`, `rom_layout`.
- Smaller `d*` arrays: one generic generator, `ssb-tablegen`'s `d_arrays` ([RE-547](../evidence/re/RE-547.md)).
  - Scope: HUD digit widths/colours, camera and projection defaults, fighter/item/weapon/effect/stage constants, `dLBCommonSinLookup`.
  - Per-crate lists: `d_arrays/{game_a,game_b,rom,engine}.rs`.
  - List entry: symbol, overlay, address, element type, shape; stride for one field of a record array.
  - Crates include result as private `crate::d_arrays` module.
  - Array name: symbol without the `d`, in `UPPER_SNAKE`.
  - Read at symbol's overlay, from overlay's ROM start, never from a VRAM alone.
- Function-local arrays (amendment 2026-10-19):
  - Scope: initialised locals the compiler placed in an overlay's `.data`; strings in `.rodata`.
  - Are ROM tables, generated through `d_arrays` (`DArray::local`, `CStr`).
  - Each read at its overlay and vram.
  - Enum-valued lists use checked const mappings ([RE-548](../evidence/re/RE-548.md)).
- Build scripts call `crates/ssb-tablegen`:
  - Finds ROM: `SSB64_ROM`, else the single `.z64` in `rom/`.
  - Verifies SHA-1; writes Rust into Cargo's `OUT_DIR`; crates `include!` it.
  - No ROM: build stops, says how to supply one.
- Commit only layout: ROM offsets, record sizes, counts, word counts, non-script regions, identifiers the port gives entries.

### Stub tables
- `SSB64_STUB_TABLES=1`: empty tables of same types; sets `cfg(ssb64_stub_tables)`.
  - For ROM-less CI: type-checks, lints, runs every test not needing ROM data.
  - Stub build cannot run the game.
- Tests needing ROM tables: `#[cfg_attr(ssb64_stub_tables, ignore = "needs the ROM-generated tables")]`.
- Tests and tools reading the ROM themselves:
  - `ssb_tablegen::test_rom(env!("CARGO_MANIFEST_DIR"))`; build scripts: `locate_rom`.
  - Skip when no ROM.

### Goldens
- Golden capture: SHA-256 of decoded pixels in `tests/golden/hashes.tsv`.
- PNG never committed.
- Local difference-mask PNGs: gitignored `tests/golden/local/` ([visual regression](../visual-regression/README.md)).

### Enforcement
- `tools/docs/validate_docs.py` (CI) fails on:
  - Any tracked ROM, pack, save or binary file.
  - Any image or media file outside original XMB artwork (`psp-game/xmb/`, `psp-asset-viewer/xmb/`).
  - Any known generated-table path.
  - Any tracked `.rs` file with a generated header.
- Check 10 (`tools/docs/rom_tables.py`): new hand-transcribed table in any crate (`ssb-tablegen` aside) fails.
  - Triggers:
    - Const/static array of 8+ numeric literals (24 in test code).
    - Struct literal or tuple static of 8+.
    - Const/static of 2+ whose doc comment names a data symbol and does not read generated `d_arrays`.
  - Data symbol: `d*` name with module or fighter prefix, `ll*` label, or `relocData/NNN_*.c` file.
  - Exemption: `tools/docs/rom_tables_baseline.tsv` row with a reason.
  - Baseline row whose table is gone fails too; list only shrinks.
  - Literals inside an index are positions, not counted.
- Local scan `tools/local_arrays.py`: places a function-local array in the overlay.
- Out of scope: scalar constants in function or `match` bodies.
  - Per-fighter ROM struct values (attributes, hitboxes, throw descriptors, item events) are generated.

### Layout versus data
- `SpriteFile` manifests, `*_OFFSETS` tables: layout (label offsets in a file); may stay.
- `Backup` default: generated from `dSCManagerDefaultBackupData`.
- `effect.rs` `QUAKE`, `THUNDER_SHOCK`: stay baselined until `ssb-tablegen` can play AnimJoint scripts (`PLAN.md`).

## Why
- Committed tables were transcribed from decomp C sources (which describe ROM bytes).
  - ~1.5 MB of game data in the tree.
  - Golden PNGs showed its characters and stages.
- Generating from the user's ROM makes README's legal statement true for the tree.
- Drops Python generators' dependency on a local decomp checkout.
- ROM generator reproduced old tables exactly, except sound ids:
  - Motion scripts' sound commands, and four Star Rod `SetFlag1` words carrying a sound id.
  - Now hold ROM's FGM and voice ids; Python generator wrote 0 for unresolved `nSYAudio*` enumerators.
- Port behaviour unchanged: motion interpreter skips sound commands; Star Rod clears flag 1 unread.

## Not covered
- Gameplay code: translation of decompiled code; keeps constants, enum values, small tables its functions use.
  - Examples: `colanim_preserve.rs`, `ftMainSetStatus` call sites whose flags preserve state.
  - These are facts about the original's code, not ROM data tables.
- Named `d*` array is data even when the code segment holds it.
- Remain, each listed in the baseline with its reason:
  - `ll*` link-time offsets passed as immediates.
  - `match`-arm values.
  - Test fixtures.
