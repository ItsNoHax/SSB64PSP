# D-043: Filtering and Tile Addressing Are Measured Against an N64 Reference Model

Category: Rendering Fidelity

**Decision:** Texture filtering and tile addressing are judged against
host-side N64 reference models (`ssb_rom::n64_filter`,
`ssb_rom::n64_addressing`), not by name equivalence. The measured results
stand:

- `G_TF_BILERP` (the RDP's 3-point reconstruction) is not PSP bilinear. It is
  an accepted PSP fixed-function deviation, reduced by build-time filter
  compensation ([`docs/rendering/textures.md`](../rendering/textures.md)).
- Mirror+clamp lowering bakes every mirrored period the drawn rect reaches,
  for authored UVs and texgen.
- PSP power-of-two padding repeats the logical edge, so N64 clamp addressing
  is unaffected.
- `G_SETTILE`'s CI4 palette bank is honoured.
- `mask == 0` axes are always clamped on the N64; the archive has none, and
  `romtool` fails if one appears.

**Reasoning:** RE-124 measured only that SSB64 selects `G_TF_BILERP`, not that
the RDP's 3-point reconstruction matches the PSP's four-tap bilinear filter.
RE-066, RE-067 and RE-102 fixed the cases they investigated but were not
checked against a full tile-addressing model. RE-218 reopened all four
claims; RE-219–RE-224 measured and closed them.

**Reference:** RE-218–RE-224. Supersedes the unqualified equivalence
conclusions drawn from RE-066, RE-102 and RE-124 for these claims only; those
records' own measurements remain valid for what they tested.
